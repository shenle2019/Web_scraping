## 0. 一句话认识本案例

极验（Geetest）滑动验证整条流程里有 **3 个需要逆向的 `w` 参数**，本课只解**第一个**（`get.php` 初始化数据的那个）：

**w = i + r**，其中——

- **r**：用固定 RSA 公钥加密一个随机 16 位 `aeskey`（node-jsencrypt 的 RSAKey 黑箱调用）；
- **o**：用这个 `aeskey` 对配置 JSON 做 **AES-CBC** 加密（crypto-js）得到字节数组；
- **i**：把 o 的字节数组做**自定义 Base64** 编码（字符表 `+/` 被换成 `()`，补位符 `=` 换成 `.`）。

逆向路线的看点不在算法本身，而在 **fullpage.js 的混淆代码怎么读**：`\u0077` 定位、字符串数组解密函数、`concat+shift` 制造的变量别名、逗号运算符与短路赋值。

## 3. 定位技巧：为什么搜 `\u0077` 而不是搜 `w`

fullpage.js 里的变量名/键名大量以 **Unicode 转义** 形式书写（`"\u0077"` 就是 `"w"`），直接全局搜 `w` 命中太多（全是干扰），正确姿势：

```js
// 想搜哪个字母就把它转成 \u00XX 形式
'\\u00' + "w".charCodeAt(0).toString(16)   // -> "\u0077"
```

- 在 fullpage.js 里搜 `\u0077`，命中约 **3 处**；
- 逐个打点后锁定目标结构：`"\u0077": i + r` —— 说明 **w 由两个变量 i 和 r 拼接**；
- 后续 s 对象（返回体）的键全是 `\u0074\u0074...` 这种，一眼可知都是转义，逐键翻译即可（gt / challenge / lang / pt / client_type / w）。

> 速查：`\u0074`=t、`\u0067`=g、`\u0063`=c、`\u0068`=h、`\u0061`=a、`\u006c`=l、`\u0065`=e、`\u006e`=n、`\u0070`=p、`\u005f`=_。

## 4. 第一个 w 的公式拆解

反混淆后 `get_first_w` 函数的核心（去掉了无关赋值）：

```js
var r = t['$_CCGH']()                                             // RSA：加密 aeskey
  , o = $_BFD()['encrypt1'](JSON['stringify'](t['$_EJY']), t['$_CCHI']())  // AES-CBC：加密配置JSON
  , i = p['$_HEv'](o)                                             // 自定义Base64：编码 o
  , s = { "gt":..., "challenge":..., "lang":'zh-cn', "pt":0, "client_type":'web',
          "\u0077": i + r };                                      // w = i + r
```

| 输出变量 | 生成函数 | 算法 | 输入 |
| --- | --- | --- | --- |
| **r** | `$_CCGH()` | RSA（node-jsencrypt） | aeskey（16 位随机 hex 串） |
| **o**（中间值） | `encrypt1()` | AES-CBC（crypto-js） | `JSON.stringify(配置对象)` |
| **i** | `_HEv(o)` | 自定义 Base64 | o（AES 密文的字节数组） |

关键认识：**r 和 o 用的其实是同一个秘密值 `aeskey`** —— r 是「把钥匙本身用 RSA 寄出去」，o 是「用这把钥匙加密数据」，服务端用私钥解开 r 拿到 aeskey，再解密 o。

## 5. 逐块分析

### 5.1 r：RSA 加密 aeskey

反混淆后的 `$_CCGH`：

```js
function $_CCGH(e) {          // 调用时不给参数，e 为空
    var t = new X()['encrypt'](this['$_CCHI'](e));       // ① 取出 aeskey，用 X 加密
    while (!t || 256 !== t['length'])                    // ② 长度必须为 256，否则重试
        t = new X()['encrypt'](this['$_CCHI'](!0));      //    （传 !0 强制重新生成 aeskey）
    return t;
}
```

**X 是什么**：进入 `X()` 内部看到成员 `n/e/d/p/q/dmp1/dmq1/coeff` + 构造函数里直接 `setPublic(公钥, '10001')` —— 这是典型的 **RSAKey 结构**。与 `node-jsencrypt` 源码里的 `function RSAKey()` 几乎一致，差别仅在于课件版 `X()` 在构造里多写了一行 `setPublic`：

- 公钥：`00C1E3934D1614...ABAB81`（固定不变，hex 长 258 字符，含前导 00，即 **1024 位**）
- 指数：`10001`（十六进制，即 65537）
- 加密输出：hex 字符串，长度恰好 **256**（= 128 字节密文），与 while 判断吻合

**处理套路**：不再往里抠 RSA 实现，直接用 `node-jsencrypt` 的 `RSAKey` 黑箱替代 `X()`：`new RSAKey()` 后手动补上 `setPublic(同一公钥, '10001')`。

### 5.2 aeskey 的生成与缓存（e / te / `_CCHI`）

**缓存函数 `_CCHI(e)`** —— 真正的 aeskey 出口：

```js
function _CCHI(e) {
    // 短路写法：aeskey 已存在且 e 为空 → 直接返回缓存；否则生成新值
    return this['$_EIi']['aeskey'] && !e || (this['$_EIi']['aeskey'] = te()),
    this['$_EIi']['aeskey'];   // 逗号表达式：返回最后一个值
}
```

- 第一次调用（e 为空）且无缓存 → 执行 `aeskey = te()`；
- while 重试时传 `!0`（true）→ 强制走 `(aeskey = te())` 重新生成；
- **r 和 o 里的 `t['$_CCHI']()` 调的是同一个缓存值** —— 保证 AES 的 key 和 RSA 寄出的 key 是同一份。

**生成函数 te / e**：

```js
function e() {   // 4 位十六进制随机串：65536*(1+random) ∈ [65536, 131071]
    return (65536 * (1 + Math['random']()) | 0)['toString'](16)['substring'](1);
}                // toString(16) 得 5 位 hex（如 "1a2b3"），substring(1) 去掉首位 -> 4 位

function te() {
    return e() + e() + e() + e();   // 拼 4 次 = 16 位 hex，也就是 aeskey
}
```

### 5.3 o：AES-CBC 加密配置 JSON

**混淆原貌**（`encrypt1` 内部，三个参数全被混淆）：

```js
t = u['parse'](t);
n && n['iv'] || ((n = n || {})['iv'] = u['parse']('0000000000000000'));
var r = m['encrypt'](c, e, t, n);   // ← 加密核心，看起来和标准写法完全不同
```

**破解方式**：在函数首行打断点，在 console 逐个确认三个要素：

| 混淆变量 | 实际含义 | 取值 |
| --- | --- | --- |
| `e`（参数1） | 被加密数据 data | `JSON.stringify(t['$_EJY'])` |
| `t`（参数2） | key | **aeskey**（同一个 `_CCHI()` 缓存值） |
| `n.iv` | iv | 字符串 **`0000000000000000`**（16 个 0） |
| `m['encrypt']` | 加密函数 | crypto-js 的 AES（数据格式与 CryptoJS 完全兼容） |

用熟悉的写法对照改写（笔记参考，非运行脚本）：

```js
key = CryptoJS.enc.Utf8.parse(key);
iv  = CryptoJS.enc.Utf8.parse('0000000000000000');   // iv 就是 16 个 '0' 字符串，不是 hex
r = CryptoJS.AES.encrypt(data, key, { iv: iv, mode: CryptoJS.mode.CBC });
```

**输出转换**：不直接返回密文对象，而是把 `ciphertext`（WordArray）压成**字节数组** ——

```js
var o = r['ciphertext']['words'];    // 32位整数数组
var i = r['ciphertext']['sigBytes']; // 有效字节数
for (var a = 0; a < i; a++) {
    var _ = o[a >>> 2] >>> 24 - a % 4 * 8 & 255;   // 大端逐字节展开
    s['push'](_);
}
return s;   // s 就是纯字节数组，如 [16, 174, 12, ...]
```

### 5.4 i：自定义 Base64 编码（_HEv / _HCR）

```js
function _HEv(e) {
    var t = $_HCR(e);          // 自定义Base64核心
    return t['res'] + t['end']; // 主体 + 补位符
}
```

`$_HCR` 核心结构（反混淆后）：3 字节一组拼 24 位，再分 4 次「按掩码取 6 位」：

```js
// 取位小工具
function $_HBX(e, t) { return e >> t & 1; }

// 字符表（与标准 Base64 的差别：+/ -> ()）
var t = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789()';

// 6位提取：掩码 t 的位模式决定从 24 位里抽哪 6 位
for (var n = 0, r = 24 - 1; 0 <= r; r -= 1)
    1 === $_HBX(t, r) && (n = (n << 1) + $_HBX(e, r));

// 主循环（每 3 字节出 4 个字符）
_ = (e[a] << 16) + (e[a+1] << 8) + e[a+2];
n += $_GJr(t(_, 7274496)) + $_GJr(t(_, 9483264)) + $_GJr(t(_, 19220)) + $_GJr(t(_, 235));
```

**四个掩码常量**：`7274496` / `9483264` / `19220` / `235`（即 `0x6F0000` / `0x90B400` / `0x4B14` / `0xEB`），每个都恰好有 **6 个二进制 1** —— 就是把 24 位切成 4 个 6 位块（标准 Base64 分组原理，只是用掩码方式实现）。

**尾部处理**：

| 剩余字节 | 输出 | `end` 补位 |
| --- | --- | --- |
| 余 2 字节（16 位 → 3 个 6 位块） | 3 个字符 | `.`（1 个） |
| 余 1 字节（8 位 → 2 个 6 位块） | 2 个字符 | `.` `.`（2 个） |

- 越界索引 `$_GJr` 返回 `.`，返回值结构 `{res: 主体, end: 补位}`，拼接后即完整编码串；
- 即：**`()` 替换了 `+/`，`.` 替换了 `=`** —— 整体只换了字符表，其余与标准 Base64 一一对应。

## 6. 混淆代码还原手法小结（本课方法论重点）

### 6.1 变量别名混淆（`concat + shift` 造「同一个函数三个名字」）

```js
var $_CEEIK = __GCt.$_CI                        // 真身
  , $_CEEHQ = ['$_CEFBN'].concat($_CEEIK)       // ['$_CEFBN', 真身]
  , $_CEEJl = $_CEEHQ[1];                       // 下标1 = 真身
$_CEEHQ.shift();                                // 去掉头元素 -> [真身]
var $_CEFAm = $_CEEHQ[0];                       // 下标0 = 真身
```

识别要点：**`$_CEEJl == $_CEEIK == $_CEFAm == __GCt.$_CI`**，三者是同一函数。同一文件里还有一组同款（`$_HCJM` / `$HDAO` / `$_HCIK`）。混看会以为在调不同函数，识破后全部统一替换成 `__GCt.$_CI`。

### 6.2 字符串数组解密函数 `__GCt.$_CI(n)`

代码里满屏 `t[$_CEEJl(384)]`、`$_CEEIK(1077)` 这类「数字参数」，实际是用数字索引去取字符串。还原方式：**在 console 里逐个运行 `$_CI(n)` 拿真实字符串，替换回代码**。课件实测对照：

| 调用 | 真实字符串 | 调用 | 真实字符串 |
| --- | --- | --- | --- |
| `$_CI(384)` | `$_EIi` | `$_CI(368)` | `$_EJY` |
| `$_CI(359)` | `gt` | `$_CI(1119)` | `encrypt1` |
| `$_CI(322)` | `challenge` | `$_CI(488)` | `stringify` |
| `$_CI(231)` | `lang` | `$_CI(1125)` | `$_CCHI` |
| `$_CI(1081)` | `pt` | `$_CI(1133)` | `$_CCGH` |
| `$_CI(1049)` | `client_type` | `$_CI(1190)` | `$_HEv` |

### 6.3 逗号运算符 + 短路表达式

- `return a && !b || (a = te()), a;` —— 逗号表达式返回最后一个值，实际就是「必要时生成、最终返回 a」；
- `n && n['iv'] || ((n = n || {})['iv'] = ...)` —— 无 iv 才补默认 iv；
- `o || (o = i)` —— 参数缺省时回退到 this。
- 阅读技巧：还原时不必改语义，把短路逻辑展开成 if 反而更贴近本意。

### 6.4 其他小套路

- **键名全 `\u` 转义**：`"\u0077": i + r`（§3）；
- **加密函数「改名换姓」**：`m['encrypt'](c, e, t, n)` 让人看不出是 CryptoJS，靠断点对参数语义逐一对号；
- **无意义的固定字符串赋值**：`t['$_CCFN'] = e`（`-1!!` 重复 73 次 + 末尾 `-1` 的固定串），只是「占位数据」，直接写死。

## 7. 补环境与改写要点（为理解机制，非复刻）

### 7.1 this 上下文丢失 → 自定义宿主对象

混淆代码里 `this` 指页面里的全局对象，单独跑 js 文件时 `this` 是空对象，`_CCHI` 里取 `this['$_EIi']['aeskey']` 会报 `Cannot read properties of undefined`。做法：**自造一个最小宿主对象**：

```js
var my_this = { $_EIi: { 'aeskey': undefined } };   // aeskey 初始为空即可，首次调用会生成
// 并把 _CCHI 内部 this 全部换成 my_this
```

### 7.2 `t['$_EJY']` 配置对象 → 全局固定 + gt/challenge 动态传参

`JSON.stringify(t['$_EJY'])` 是被加密的数据本体。断点取值后发现：**除 gt、challenge 外全是固定字段**（offline/new_captcha/product/https/static_servers/aspect_radio/各种 js 路径…）。做法：

- 定义全局 `quanju = { $_EJY: {...全部固定字段...} }`（去掉 gt/challenge）；
- `get_first_w(gt, challenge)` 入口里把这两个参数塞进去，其余照抄；
- 运行时补三条：`cc = 16`、`ww = true`、`i = 固定串 e`。

### 7.3 其余零碎值的处理

| 原代码 | 处理 |
| --- | --- |
| `n['lang']` → `'zh-cn'`、`t['$_BJGj']` → `0`、`t['$_BJHj']` → `'web'` | console 取值后直接写死 |
| `n['cc']`、`n['supportWorker']` 读不到报错 | console 运行取值后替换（16 / true） |
| `var e = t['$_BJCx']['$_BIBF']()` | 返回固定串 `-1!!`（×73 + `-1`），直接写成字面量 |

### 7.4 node-jsencrypt 源码改造（关键一步）

`node-jsencrypt/index.js` 结尾**只导出了 `JSEncrypt`，没导出 `RSAKey`**，而我们要用的恰恰是 RSAKey。改造：

```js
// 原版
exports.JSEncrypt = JSEncrypt;
module.exports = JSEncryptExports.JSEncrypt;

// 改为
exports.JSEncrypt = JSEncrypt;
exports.RSAKey = RSAKey;                 // ← 补导出
module.exports = { 'JSEncrypt': ..., 'RSAKey': ... };
```

之后即可：`var {RSAKey} = require('node-jsencrypt')`，用它替代混淆里的 `X()`（记得手动 `setPublic(公钥, '10001')`）。

> 顺带认识两个库的分工：`jsencrypt` 是浏览器端（前端加密→后端解密），`node-jsencrypt` 是 Node 端（后端加密→前端解密），公私钥格式互通。

## 8. Python 端联调（execjs）

课件 `first_w.py` 的调用骨架：

```python
import subprocess
from functools import partial
subprocess.Popen = partial(subprocess.Popen, encoding='utf-8')   # ① 防 Windows 下 execjs 乱码

import execjs
first_js = execjs.compile(open('first_w.js', encoding='utf-8').read())

# ② 请求 register-slide-official 拿 gt/challenge，走 gettype.php
# ③ 用 JS 生成 w 所需参数，再请求 get.php

get_ret = session.get(get_url, headers=headers, params=ret).text   # status: success
```

要点：

- **入口函数保留 `(gt, challenge)` 两个参数**，JS 里再写入固定模板 —— 动态值只有这两个；

- `callback` 参数记得带上 `geetest_%d % 时间戳`。

## 9. 关键信息点速查 / 易错点

**速查卡**

- 定位：搜 `\u0077`（= `'\\u00' + 'w'.charCodeAt(0).toString(16)`），锁定 `"\u0077": i + r`
- 公式：**w = i + r** = 自定义Base64(AES密文) + RSA(aeskey)
- AES：key = aeskey（16 位 hex 串）、iv = `'0000000000000000'`（16 个字符 `0`）、CBC、输出转字节数组
- RSA：node-jsencrypt 的 RSAKey、固定公钥（1024 位）+ 指数 `10001`、输出 hex 定长 256
- aeskey：`te()` 生成 = 4 × `e()`，`e()` = 4 位随机 hex；首次生成后**缓存共享**，重试传 `!0` 强制刷新
- 自定义 Base64：字符表尾部 `()` 替换 `+/`，补位 `.` 替换 `=`；4 个掩码常量各含 6 个置位
- 配置 JSON 固定字段全写死，只有 gt / challenge 动态

**易错点**

1. iv 是**字符串** `'0000000000000000'`（16 个字符 0），不是 16 个 0x00 的 hex 展开——保持原代码 `Utf8.parse` 语义写就没错；
2. iv 与密文都基于**同一份缓存的 aeskey**，重试循环里换了新 aeskey 的话 AES 密文也要用新的（共享缓存函数保证这一点，不要拆开）；
3. `r` 长度判断是 `256 !== t['length']`——是**字符串长度 256**（hex 形态），不是字节数 256；
4. 改造 node-jsencrypt 后，`new RSAKey()` 要**手动补 `setPublic`**（原版 RSAKey 构造函数不带公钥）；
5. `_CCHI` 里 `this` 已被换成自定义宿主对象后，`t['$_CCHI']()` 这种「通过对象调用」的写法也要一并手动替换成直接调用 `_CCHI()`；
6. 混淆三连识别：别名组（concat+shift 出来的）→ 统一替换；数字取串（`$_CI(n)`）→ console 逐个取值替换；`\u` 键名 → 对照翻译。三步做完，代码可读性恢复。
