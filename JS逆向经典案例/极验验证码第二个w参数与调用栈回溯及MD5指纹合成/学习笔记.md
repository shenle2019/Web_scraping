## 0. 一句话认识本案例

第二个 w 出现在**点击「点击按钮进行验证」后**产生的第一个 `ajax.php` 数据包中。整体公式与第一个 w 同骨架：

**w = 自定义Base64( AES-CBC( 数据体 r , aeskey ) )**，且 **aeskey 与第一个 w 共享**。

真正的难点有两个：

1. **定位难**：常规「搜 `\u0077` 打断点」对第二个 w **完全失效**（点按钮不断停），必须改用 **Initiator + 函数调用栈逐层回溯** 找到 w 的生成源头；
2. **数据差异大**：数据体 `r` 里不再是一份配置 JSON，而是「**captcha_token（djb2 哈希）+ 轨迹编码 + 浏览器指纹串 + MD5 系列字段 + 环境对象**」拼出来的一大串——本课一半的篇幅都在还原这些数据是怎么凑出来的。

## 2. 定位：从「搜 \u0077 失效」到「调用栈回溯 + 数字搜索」

### 2.1 常规方式为什么失效

- 全局搜 `\u0077` 依旧能定位到 fullpage.js 里 3 处；
- 但这 3 处**依次打点后点击「点击按钮进行验证」一个都不停留** —— 说明第二个 w 不走这几处代码，常规搜索定位法失效。

### 2.2 非常规方式：Initiator（发起者）切入

- 在抓包工具里找到点击后出现的 `ajax.php` 数据包，看 **Initiator（发起者）** 页签：它按调用先后顺序列出参与发起该请求的 js 文件；
- 最后执行的一环是 fullpage.js 中的一段代码，点进去看到（反混淆后）：

```js
// 源代码：return e[$_BGHEg(468)][$_BGHDd(626)](this[$_BGHEg(468)])
return head['appendChild'](<script src="ajax.php?gt=xx&w=xxx">)
```

- 结论：这段代码只是**把带 w 的 ajax.php 地址塞进 script 标签**发起请求——**w 在此刻早已生成完毕**，需要继续**往回追**。

### 2.3 函数调用栈逐层回溯（本课核心操作）

在断点处的右侧「函数调用栈」里，从当前函数**逐层往上（向调用者方向）**点，边点边观察每一层有没有 w 的踪迹：

```text
appendChild(script)
  └─ anonymous（调用 n 的成员函数，参数是 new le）
       └─ 发现 n.$_FIQ 里就装着 w → 定位 n.$_FIQ 的赋值处（r 变量处）
            └─ 继续回溯 …  function S()（第一个参数 s 就是 w 串）
                 └─ 谁调用 S()？→ 停在 S 定义处刷新，栈上一格即调用点
                      └─ 携带 n 的调用点 → 定位核心变量 i
                           └─ i 来自 L() 的第 6 个参数
                                └─ L() 又被 function() 调用 → 再追 n 的来源
                                     └─ ★ 终于找到 w 生成的源头：
                                        w 来自 this[$_CFJr(1139)] 的生成
```

### 2.4 数字搜索法（关键技巧）

找到源头后发现 w 是 `this[$_CFJr(1139)]` 属性——去分析 `this` 里所有属性太痛苦（内容太多、关联复杂）。**另辟蹊径**：

- 混淆函数名 `$_CFJr(1139)` 的核心是**数字 1139**（数字不同反混淆结果不同）；
- 在 fullpage.js 源文件里**直接搜 `1139`** → 定位到给 `this` 添加该属性的赋值操作（`this[xxx(1139)] = ...`）→ 这就是 w 的生成函数本体；
- 把该函数改写：前 5 行别名混淆删掉、末尾把 `return this[xxx(1139)]` 结果直接返回 → 得到 `get_second_w(e)` 的雏形。

> 经验总结：**「谁给 this/对象挂上了这个数字属性」比「this 里有什么」好找得多**——用数字做特征搜索，是混淆 JS 里定位「动态挂载函数」的通用打法。

## 3. get_second_w 的结构总览

反混淆 + 去控制流后的主干（三层结构）：

```js
function get_second_w(aseKey, gt, challenge) {
    var r = '';
    var o_string_code = "function o(e,t){...原始混淆源码...}";  // ① 从浏览器 console 拷的函数源码定值
    var n_string_code = 'function n(e){...原始混淆源码...}';   // ② 同上
    var e_string_code = 'bbOy';                                // ③ 同上
    !function o(e, t) {                                        // ④ 自运行函数：拼数据体 r
        function n(e) { /* djb2 哈希 */ }
        100 < new Date()['getTime']() - t['getTime']() && (e = 'qwe'),
        r = '{' + get_i_CECe(gt, challenge)
            + '"captcha_token":"' + n(o_string_code + n(n_string_code) + n(e_string_code))
            + '","sugd":"lyaxkuq4"}';
    }('bbOy', new Date());
    return $_HED(encrypt1(r, aseKey));                         // ⑤ AES-CBC → 自定义Base64
}
```

分工：

| 层 | 内容 | 说明 |
| --- | --- | --- |
| ① 数据体 r | `{<get_i_CECe 内容>,"captcha_token":"<djb2串>","<小字段>":"<小值>"}` | 真身的 13+ 个键值全在 get_i_CECe 里 |
| ② captcha_token | djb2( o函数源码 + djb2(n函数源码) + djb2('bbOy') ) | 依赖**函数源码字符串**，必须定值 |
| ③ 外层加密 | `$_HED(encrypt1(r, aseKey))` | 与第一个 w 完全相同的加密骨架，aeskey 传入 |

坑点备注：自运行函数调用时 `t['shift']()` 从 `['bbOy', <push进来的空串>]` 里取出 `'bbOy'` 传给形参 e；时间差超过 100ms 时 e 会被替换为 `'qwe'`（该字符串本身也是混淆取表得到的）。

## 4. 逐块分析

### 4.1 captcha_token：djb2 哈希 + 函数源码 toString

内置函数 `n`（反混淆+去控制流后）：

```js
function n(e) {
    var t = 5381, n = e['length'], r = 0;
    while (n--)
        t = (t << 5) + t + e['charCodeAt'](r++);   // hash*33 + char（经典 djb2）
    return t &= ~(1 << 31);                        // 清符号位，取正整数（& 0x7FFFFFFF）
}
```

- 被哈希的串 = **`o函数源码 + n(n函数源码) + n('bbOy')`**（外层包一层 `n(...)`）；
- **关键坑：依赖 `Function.toString()` 原文** —— 反混淆/改写后的代码 `toString()` 结果已和浏览器不同，所以必须用浏览器 console 里原样拿到三个字符串（o/n 函数源码、e 的值），在脚本里作为**定值**写死（课件名 `o_string_code` / `n_string_code` / `e_string_code`）；
- 新版快照里函数源码字符串中的混淆全局对象别名会变（如 `hZohI.$_CQ`、`hZohI.$_Dd()`），**拷贝定值时以当时浏览器里的一份为准**。

### 4.2 数据体主体：get_i_CECe(gt, challenge)

结构：`i['$_CECe'] = ''` 起步，遍历数组 `a`，每项拼 `"键":JSON.stringify(值),`：

```js
for (var a = [
        ['lang', o['lang'] || 'zh-cn'],
        ['type', 'fullpage'],
        ['tt',  自定义字符插入(e, o['c'], o['s']) || -1],
        ['light', r || -1],
        ['s',  H(get_p_value(t))],
        ['h',  H(get_p_value(n))],
        ['hh', H(n)],
        ['hi', H($_CCFB)],
        ['vip_order', vip_order || -1],
        ['ct', ct || -1],
        ['ep', $_CEDX || -1],
        ['passtime', s || -1],
        ['rp', H(o['gt'] + o['challenge'] + s)],
    ], _ = 0; _ < a['length']; _++)
    i['$_CECe'] += '"' + a[_][0] + '":' + JSON.stringify(a[_][1]) + ',';
```

**13 个键逐个说**：

| 键 | 来源 | 处理方式 |
| --- | --- | --- |
| `lang` / `type` | 固定 `'zh-cn'` / `'fullpage'` | 直接写死 |
| `tt` | 字符插入算法（§4.4） | 输入 = 轨迹串 e + 参数 `o['c']`/`o['s']` |
| `light` | `get_r_value()` = **`'SPAN_0'`**（固定） | 写死 |
| `s` / `h` | `H(get_p_value(t))` / `H(get_p_value(n))` | 先自定义Base64 再 MD5 |
| `hh` | `H(n)`（n = 指纹串，§4.3） | MD5 |
| `hi` | `H($_CCFB)`（`-1!!` 固定串） | MD5 |
| `vip_order` / `ct` | 均 `undefined` → `-1` | 写死 -1 |
| `ep` | `$_CEDX` 环境对象（§4.6） | 拷贝 + 时间戳动态化 |
| `passtime` | `s = 当前时间戳 - rt`（两行为间的时间差） | **可固定/随机**（2894）；一般不卡这个值 |
| `rp` | `H(gt + challenge + passtime)` | MD5 |

### 4.3 数据源四件套（get_xxx_value）

**① get_e_value()：鼠标轨迹**

- 断点看到原始 `e` 是一个大数组：`[["up",223,714,1717077570056,"pointerup"], ["focus",1717077570763], ...]`（事件名、坐标、时间戳、原生事件名）；
- 经 `this['$_BHIG'](e)` 预处理成 **`[事件名, [x,y]?, 时间差]`** 形式（3 元素带坐标、2 元素无坐标），课件直接复制这份预处理结果；
- 再经 `$_HDZ(...)` 编码为字符串（§4.5）；
- 课件结论：轨迹值**测试不被检测**，可直接固定——但要满足「连续、符合人工滑动」的形态。

**② get_t_value()：`return $_HDZ([])`** —— 空数组的编码结果（定值）。

**③ get_n_value()：浏览器指纹串**

- 内置一个 **70+ 项浏览器属性名数组**：`textLength, HTMLLength, documentMode, A/ARTICLE/ASIDE/AUDIO/...（各类标签名）, screenLeft/Top, innerWidth/Height, outerWidth/Height, browserLanguage(s), devicePixelRatio, colorDepth, userAgent, cookieEnabled, screenWidth/Height, localStorageEnabled, CPUClass, platform, doNotTrack, timezone, canvas2DFP/3DFP, plugins, maxTouchPoints, hardwareConcurrency, jsFonts, timestamp, performanceTiming, internalip, mediaDevices, DIV/P/UL/LI/SCRIPT, touchEvent...`；
- 对每项取 `r[e]`（r 是**空对象** `{}`）→ 取不到 → `void 0 === t ? -1 : t` → **全部填 `-1`**；
- 最后 `join('magic data')` —— 得到一条用 `-1` 与属性名隔开的固定指纹串。
- 配套造了 `$_DJS` 数组包装类 + `$_EBs` map 方法（仿 underscore 的小轮子），逆向时补个简化版即可：
  - `n['$_BIHJ'](t)` 的真身就是 `void 0 === e`（isUndefined），直接内联成 `t === undefined ? -1 : t`。

**④ get_r_value()：`'SPAN_0'`**

- 原函数有一堆 `this['$_BGC'] = []`、`e.join('|')` 等操作，断点验证后等价于直接 `return 'SPAN_0'`（固定值）。

### 4.4 tt：字符插入算法（o['c'] 系数 + o['s'] 种子）

```js
function (e, t, n) {          // e=轨迹串（会被插入字符），t=o['c']系数数组，n=o['s']种子hex串
    if (!t || !n) return e;
    var r, o = 0, i = e, s = t[0], a = t[2], _ = t[4];   // 只取系数数组的第 0/2/4 个
    while (r = n['substr'](o, 2)) {                       // 种子串每 2 个 hex 字符取一字节
        o += 2;
        var c = parseInt(r, 16)
          , l = String['fromCharCode'](c)                 // 转成字符
          , u = (s * c * c + a * c + _) % e['length'];    // 二次函数取模 → 插入位置
        i = i['substr'](0, u) + l + i['substr'](u);       // 插到位置 u
    }
    return i;
}(e, o['c'], o['s']) || -1
```

- 参数在数据对象 `o` 里现成：`o['c'] = [12,58,98,36,43,95,62,15,12]`（9 个系数，实际只用第 0/2/4 个）、`o['s'] = "4555386c"`（hex 种子）；
- 效果：按种子字节算出的位置往轨迹串里插字符——**混淆字符串特征**的手法；
- 还原时只需把 `o['c']`、`o['s']` 两个字段随配置对象一起定值即可。

### 4.5 $_HDZ：轨迹/数字序列编码器（本课最长算法）

输入 `e` = `[[事件, [x,y], 时间差], ...]`，输出一段编码字符串。流水线：

```text
e → 拆成四条序列：事件名 t[] / 时间差 n[] / x 序列 r[] / y 序列 o[]
  → f(t)         事件序列编码：事件名→数字(0~7) + 「重复次数压缩」（8|数字、i-1 两个码字）
  → d(n, false)  数字序列编码（不带符号位）
  → d(r, true) + d(o, true)   坐标序列编码（带符号位）
  → 拼接后长度不足 6 的倍数 → 补 '0'
  → 每 6 位二进制查 64 字符表
```

细节要点：

- **事件名映射表**（反混淆后就是对象字面量）：`move:0, down:1, up:2, scroll:3, focus:4, blur:5, unload:6, unknown:7`；
- **数字编码 d**：先做「重复值压缩」（同值连续 i 个 → `(正?32768:49152) | i<<7 | 值`），再对每个数取「位长前缀 + 值」：位长 = `ceil(log16(|x|+1))`（即 16 进制位数），用 `h(位长-1, 2)` 打 2 位二进制前缀，`h(|x|, 4*位长)` 写值；最后带符号序列再拼一串符号位（0 正 1 负）；
- **h(x, 长度)**：把数字转 2 进制字符串，**前面补 0 到指定长度**（小工具函数）；
- **最终查表**（64 个字符，6 位一分组）：

```js
'()*,-./0123456789:?@ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz~'['charAt'](parseInt(e.slice(6*r, 6*(r+1)), 2))
```

- 注意注释里的坑：这段在浏览器里带 `window.` 前缀调用 `parseInt`，**Node 里没有 window**，把 `window.` 去掉直接 `parseInt` 即可。

### 4.6 ep：环境对象 $_CEDX（可拷贝 + 时间戳动态化）

断点取值可见是一坨「设备/环境信息」，关键字段：

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `v` / `te` | 版本 `"9.1.9-glhvqm"`、布尔位 | 固定 |
| `ven` / `ren` | 显卡厂商 / **渲染器指纹**（`ANGLE (NVIDIA, NVIDIA GeForce RTX 4060 ... D3D11)`） | 与第一节 w 的 `$_HBX` 系列一样属指纹范畴，拷贝 |
| `fp` / `lp` | 鼠标按下/抬起的位置与时间（移动开始点、最后停止点） | 时间可换成 `now` / `now+间隔` |
| `em` | 一段小状态对象（ph/cp/ek/wd/nt/si/sc） | 拷贝 |
| `tm` | 一组时间戳（a~u） | 课件建议**动态获取**（脚本内取当前时间为基准造一串） |
| `dnf` / `by` | 杂项 | 拷贝 |

### 4.7 H：MD5

- 断点方式确认：拿 `get_p_value(t)` 的结果 `'tEQOYESJYERVYEQ.'` 做输入，H 返回 32 位 hex 串（`'c7c3e2...7cb'`）；
- 直接用 node `crypto` 的 md5 替代：

```js
crypto.createHash('md5').update(e).digest('hex')
```

### 4.8 复用链：第一个 w 的加密骨架原样搬过来

- `i['$_CCHE']()`（本课里的 `i['$_CCHE']`）= 第一个 w 的 `_CCHI()` —— **同一个 aeskey 缓存**；
- 因此：**改造 get_first_w，把 aeskey 顺带返回**：

```js
// first_w.js（改造点）
return { 's': s, 'aesKey': _CCHI() };
```

- second_w.js 里给入口加形参 `aseKey`，最终加密改为：

```js
return $_HED(encrypt1(r, aseKey));   // encrypt1 = 第一个w里的 AES-CBC（iv/0000000000000000/CBC）
```

- 复用清单：`encrypt1`（AES-CBC）、`$_HED`/`$_HCN`/`$_GJr`/`$_HBX`（自定义 Base64）、`$_CCFB` 固定串、`H`→MD5（新）。

## 5. Python 端串联（main.py）

```python
# ① JSONP 解析（ajax.php 返回 geetest_xxx({...}) 格式）
def jsonp_op(s):
    jsonp_re = re.compile(r"\((?P<code>.*)\)", re.S)
    return json.loads(jsonp_re.search(s, re.S).group('code'))

# ② 第一个 w：拿 w 和共享 aesKey
first_js = execjs.compile(open('first_w.js', encoding='utf-8').read())
ret_dic = first_js.call('get_first_w', gt, challenge)
aesKey = ret_dic['aesKey'];  w = ret_dic['s']['w']
# → 请求 get.php

# ③ 第二个 w：把 aesKey/gt/challenge 都传进去
second_js = execjs.compile(open('second_w.js', encoding='utf-8').read())
second_w = second_js.call('get_second_w', aesKey, gt, challenge)
# → 请求 api.geevisit.com/ajax.php（响应经 jsonp_op 解析）
```

关键衔接：**一次会话里只有一份 aeskey**，第一个 w 用 RSA 把它寄出去，第二个 w 继续拿它加密——Python 侧负责在两个 JS 文件之间接力传递。

## 6. 混淆手法新增点：控制流平坦化（switch-case 状态机）

第二个 w 涉及的函数几乎全被套了同一模板：

```js
function n(e) {
    var $_DDHGQ = __GCt.$_DH()[8][12];                       // 初始状态（数组取值）
    for (; $_DDHGQ !== __GCt.$_DH()[10][10]; ) {             // 循环直到「结束态」
        switch ($_DDHGQ) {
        case __GCt.$_DH()[10][12]:  ...; $_DDHGQ = ...; break;   // 顺序落到下一态
        case __GCt.$_DH()[8][11]:   ...; return ...; break;
        }
    }
}
```

还原套路（课件验证后直接删壳）：

1. console 里验证：**循环条件恒真、各 case 按顺序依次执行**（状态值用 `__GCt.$_DH()[i][j]` 数组取值表达，翻译成字面量后可看出就是 A→B→C 的直筒顺序）；
2. 于是把 `for` / `switch` / `case` / 状态赋值全部删掉，**只保留各 case 里的语句原文、按顺序排好**——逻辑瞬间变成线性代码。

与 Day29 的对比：Day29 已有零散 switch 控制流（e/te 函数），Day30 是**成规模系统性使用**（djb2、$_HDZ 内部的 h/f/c/d 全部套壳），必须熟练这一步才能读下去。

## 7. 关键信息点速查 / 易错点

**速查卡**

- 定位：`\u0077` 失效 → **Initiator 看调用链** → 断点 **函数调用栈逐层回溯** → 源头属性 `this[xxx(1139)]` → **直接搜数字 1139** 找到赋值处
- 公式：**w2 = 自定义Base64( AES-CBC(r, aeskey) )**，aeskey **与 w1 同一个**
- 数据体 r：`{<13 键>,"captcha_token":"<djb2>","<小字段>":"<小值>"}`
- captcha_token = `djb2(o源码 + djb2(n源码) + djb2('bbOy'))`，**三个源码/值串必须用浏览器 console 原文定值**（Function.toString 敏感）
- djb2 实现：`t=5381; t=(t<<5)+t+charCodeAt(i++); t &= ~(1<<31)`
- MD5 出现的 5 处：`s/h/hh/hi/rp` 键与 captcha_token 链（H 即 md5）
- 指纹串 = 70+ 属性名 × `-1`，用 `'magic data'` 连接；`r` 空对象所以全 undefined→-1
- 轨迹编码：`$_BHIG` 预处理（[事件,[x,y],时间差]）→ `$_HDZ` 编码（事件映射 0-7 + 重复压缩 + 位长前缀 + 64 字符表）
- 共享 aeskey 改造：`get_first_w` 返回 `{s, aesKey}`；`get_second_w(aseKey, gt, challenge)`

**易错点**

1. **别在改写的代码上直接 `toString()`** 去算 captcha_token——改写后源码已变，必须把浏览器里的原始函数源码作定值；
2. `$_HDZ` 里 `window.parseInt` 在 Node 不存在，去前缀即可；
3. `$_DJS`/`$_EBs` 是仿 underscore 的包装类，只需补 `map` 行为，不用整个还原框架；
4. `passtime`（时间差）与 `ep.tm` 时间戳可动态化（取当前时间）也可固定，但不是重点校验位；`fp/lp` 时间记得配套改 `now`/`now+间隔`；
5. djb2 的 `~(1 << 31)` 是把结果**清符号位**（等价 `& 0x7FFFFFFF`），别当成取反；
6. `get_i_CECe` 拼出的每项末尾自带逗号，外层 `'{' + ... + '"captcha_token":...'` 直接拼接即合法 JSON——改代码时别重复加逗号/大括号。

## 8. 与第一个 w 的对照总结（系列复盘）

| 维度 | 第一个 w（Day29） | 第二个 w（Day30） |
| --- | --- | --- |
