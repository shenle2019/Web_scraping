## 一、逆向爬虫的关键和技巧（关键字搜索）

逆向的第一步永远是**定位前端加密/解密的 JS 代码**。在浏览器开发者工具 Sources 面板中对 JS 文件搜索以下五类关键字：

| # | 关键字类型 | 具体内容 | 作用 |
| :-: | :--- | :--- | :--- |
| 1 | **key 关键字** | `key`、`iv` | 对称加密（AES/DES）的密钥、初始向量常以此命名 |
| 2 | **路径关键字** | 接口 URL 的路径片段（如 `build.json`、`recommendInfo`） | 反查调用该接口的 JS 代码位置 |
| 3 | **特殊方法关键字** | `encrypt`、`decrypt`、`JSON.stringify`、`JSON.parse` | 加密/解密/序列化方法的通用命名 |
| 4 | **拦截器** | axios interceptors 等 | 请求/响应被统一封装处理时的突破口 |
| 5 | **headers 关键字** | 请求头中的自定义字段名 | 定位签名/令牌（token、sign）的生成位置 |

> 补充技巧：可在 Network 面板对目标请求使用 **XHR/fetch 断点**（Breakpoints），请求发出时自动断下，通过 Call Stack 回溯加密函数。

## 二、前端加密交互流程（课堂原理图）

课堂手绘图描述的核心数据流：

```
客户端（浏览器 JS）                         服务器
┌──────────────────────┐                  ┌──────────────────┐
│ ① 明文参数            │                  │                  │
│ ② 加密 encrypt        │ ─── 密文请求 ──▶ │ ③ 解密            │
│  (AES / base64 ...)  │                  │ ④ 业务处理         │
│ ⑤ 解密 decrypt        │ ◀── 密文响应 ── │ ⑤ 加密响应数据     │
│ ⑥ 本地得到明文数据     │                  │                  │
└──────────────────────┘                  └──────────────────┘
```

**结论（爬虫复刻思路）**：爬虫端必须做好两件事——
1. **请求加密**：按前端相同算法把请求参数加密后再发送；
2. **响应解密**：拿到响应密文后，按相同算法解密还原为明文数据。

两侧的算法、key、iv、模式、填充方式必须完全一致，缺一不可。

## 三、核心案例：mmz 案例（请求体加密 + 响应解密）

**案例文件**：`01 mmz案例.py`　**目标网站**：https://www.maomaozu.com/#/build
**目标接口**：`POST https://www.maomaozu.com/index/build.json`

### 3.1 加密方案总览

| 环节 | 算法 | 密钥（key = iv） | 额外处理 |
| :--- | :--- | :--- | :--- |
| 请求体加密 | AES-128-CBC + PKCS7 填充 | `55b3b62613aef1a0`（16字节） | 加密后再 base64 编码 |
| 响应解密 | AES-128-CBC + 去填充 | `0a1fea31626b3b55`（16字节） | 先 base64 解码再解密 |

> 注意：**请求与响应使用两把不同的密钥**，这是本案例的关键细节。

### 3.2 请求体加密四步（Python 复刻）

```python
import json, time, base64, requests
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

timeStamp = int(time.time() * 1000)          # 毫秒时间戳 → 放进 expire 字段防重放

data = {"Type": 0, "page": page, "expire": timeStamp}
data = json.dumps(data).encode()             # ① 明文转 JSON → bytes

key = '55b3b62613aef1a0'.encode()            # ② key 与 iv 相同，均为 16 字节（AES-128）
iv  = '55b3b62613aef1a0'.encode()
aes = AES.new(key, AES.MODE_CBC, iv)

data = pad(data, 16)                         # ③ PKCS7 填充到 16 的整数倍
data = aes.encrypt(data)                     #    AES-CBC 加密
data = base64.b64encode(data).decode()       # ④ base64 编码成字符串

response = requests.post(url, cookies=cookies, headers=headers, data=data)
```

要点：
- 发送时是 **`data=data`（字符串）**，不是 `json=data`；请求头 `Content-Type: application/json; charset=UTF-8`；
- `pad(data, 16)` 使用 Crypto 库自带 PKCS7 填充，长度参数为块大小 16。

### 3.3 响应解密三步

```python
from Crypto.Util.Padding import unpad

encrypt_data = base64.b64decode(response.text)      # ① base64 解码（响应本身就是 base64 字符串）

key = '0a1fea31626b3b55'.encode()                   # ② 另一把 key（仍是 16 字节）
iv  = '0a1fea31626b3b55'.encode()
aes = AES.new(key, AES.MODE_CBC, iv)
data = aes.decrypt(encrypt_data)

data = unpad(data, 16).decode()                      # ③ 去填充 → 解码 UTF-8 → 得到 JSON 明文
```

### 3.4 其他实现细节（抗封锁）

- **分页循环**：`for page in range(1, 11)`，页码参与请求体加密；
- **请求间隔**：`time.sleep(1)` 控制频率；
- **Cookie 登录态**：携带 `PHPSESSID`、`SECKEY_ABVK`、`BMAP_SECKEY`、`Hm_lvt_*`（百度统计）等；
- **请求头**：带 `Origin` / `Referer`（同源校验）、macOS + Chrome 122 的 UA。

## 六、关键记录点速查

- **AES 三要素**：key、iv、加密模式（本课为 CBC），key/iv 长度 16（128位）/ 24（192位）/ 32（256位）字节；
- **Crypto 加密链**：`明文 → pad(16) → encrypt → base64` ；**解密链**：`base64 解码 → decrypt → unpad → decode`；
- **两把钥匙**：请求加密与响应解密可能使用不同密钥，别只找一把；
- **时间戳参与加密**：`expire` 毫秒时间戳放入请求体（防重放/参数时效校验）；
- **内容类型是烟雾弹**：请求头写 `application/json`，实际 body 是 base64 密文字符串；
- **定位手段优先级**：控制台网络抓包 → 关键字搜索（key / 路径 / encrypt / decrypt）→ 拦截器 / 断点回溯调用栈；
- **base64 ≠ 加密**：它只是编码，既能用于传输环节，也常被用来隐藏练习目标网址（先解码再说）。
