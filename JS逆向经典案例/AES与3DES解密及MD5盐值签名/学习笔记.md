## 一、案例1 czw：招标网接口 AES-CBC 响应解密

**案例文件**：`01 czw.py`（Python 版）+ `02 czw.js`（CryptoJS 版）

### 1.1 目标与请求

- 接口：`POST https://interface.bidcenter.com.cn/search/GetSearchProHandler.ashx`
- 表单参数：`from` / `guid` / `location` / `token` / `next_token` / `keywords` / `mod` / `page`（page 控制翻页，翻页无签名负担）
- 响应特征：**整个响应体是一整段 base64 字符串**（不是 JSON），需解密后才见明文

### 1.2 解密三件套（硬编码于前端）

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| key | `3zKzyf6eEfuDjAG3` | 16 字节 → AES-128 |
| iv | `fyUANZ0qSNZhhNCV` | 16 字节 |
| 算法 | AES / CBC / **ZeroPadding** | 注意不是 PKCS7，尾部填充是 `\x00` |

### 1.3 Python 路线（PyCryptodome）

```python
base64_encrypt_data = response.text                 # ① 拿到整段 base64 密文
encrypt_data = base64.b64decode(base64_encrypt_data)

key = '3zKzyf6eEfuDjAG3'.encode()
iv  = 'fyUANZ0qSNZhhNCV'.encode()
aes = AES.new(key, AES.MODE_CBC, iv)                # ② CBC 解密
data = aes.decrypt(encrypt_data)

data = data.decode().rstrip("\x00")                 # ③ 手动去 ZeroPadding（关键）
print(json.loads(data))                             # ④ 得到明文 JSON
```

**要点**：PyCryptodome 的 `decrypt()` 不做任何填充处理，解密后必须自己 `rstrip("\x00")` 去零填充，否则 `json.loads` 报错。

### 1.4 JS 路线（CryptoJS）与 words 形式密钥

```javascript
var nContent = CryptoJS.AES.decrypt(str, key, {
    iv: iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.ZeroPadding        // 与 Python 端一致
})
var constr = CryptoJS.enc.Utf8.stringify(nContent)   // WordArray → UTF-8 字符串
var data = JSON.parse(constr)
```

课件中 key / iv 以 **WordArray 形态**出现（打包产物里密钥常被序列化成这样）：

```javascript
let key = { "words": [863652730, 2036741733, 1164342596, 1782662963], "sigBytes": 16 }
```

- `words` 是 4 个 32 位**大端**整数，按字节展开即原 ASCII 密钥串：
  - `863652730 = 0x337A4B7A` → 字节 `33 7A 4B 7A` → `"3zKz"`
  - 同理 iv `1719227713 = 0x66795541` → `"fyUA"` 起
- 遇到这种形式不用慌：`bytes.fromhex(hex(w)[2:])` 拼起来就是 key/iv；CryptoJS 侧也可直接传字符串。
- 密文直接以 base64 字符串传给 `CryptoJS.AES.decrypt`（它默认按 base64 解）。

### 1.5 实测验证（离线复算）

- 取课件 `02 czw.js` 中的密文样本（22944 字节），Python 复刻流程解密 → 成功解出 JSON：
  `{"ret":true, "msg":"", ..., "other2":{ "listData":[40条], "realInfoCount":3833831, "pageSearchJson":"..." }}`
- Node 实跑课件 `AESDecrypt()` 同一密文 → 结果与 Python 完全一致。

### 1.6 复刻要点

- **ZeroPadding 双端一致**：Python 端 `rstrip("\x00")`，CryptoJS 端 `pad.ZeroPadding`；
- 明文里若含尾部 `\x00` 是填充残留，先去填充再 `json.loads`；
- 响应整体加密的站点：直接对 `response.text` 走"b64decode → 解密 → 去填充 → JSON"流水线即可。

## 二、案例2 qmp：企名片接口 3DES-ECB 响应解密

**案例文件**：`03 qmp.py`（execjs 调用方）+ `04 qmp.js`（完整加解密内核）

### 2.1 目标与请求

- 接口：`POST https://vipapi.qimingpian.cn/Activity/channelInformationByChannelName`
- 表单参数：`channel_name` / `page` / `num` / `unionid`
- 响应特征：**JSON 外壳 + 单字段加密**，密文在 `encrypt_data` 字段里（其余字段明文）

```python
encrypt_data = response.json().get("encrypt_data")
ret = execjs.compile(open("04 qmp.js").read()).call("s", encrypt_data)
```

### 2.2 解密入口 s() 与 DES/3DES 内核

```javascript
function s(e) {
    return JSON.parse(o("5e5062e82f15fe4ca9d24bc5", decode(e), 0, 0, "012345677890123", 1))
}
```

- `decode(t)`：**自定义 base64 解码**——先清空白字符、去尾部 `=`，用字符表 `indexOf` 逐位还原成"每字符一字节"的二进制字符串；
- `o(...)`：约 100 行的**完整 DES/3DES 实现**（大堆魔数表 + 位运算，是经典 DES 库抠出来的内核），不值得逐行硬啃；
- `s(e)`：把 base64 密文解码后交给内核解密，`JSON.parse` 成对象。

### 2.3 参数位解读（从调用与内部逻辑反推）

| 位置 | 实参 | 含义 |
| :--- | :--- | :--- |
| 第1位 key | `"5e5062e82f15fe4ca9d24bc5"` | 密钥；**长度 24 > 8 → 自动走 3DES**（源码 `e.length > 8 ? 3 : 1`） |
| 第2位 data | `decode(e)` | 待解密的二进制字符串 |
| 第3位 方向 | `0` | 解密分支（反向轮序 `[30,-2,-2]`；为真时正向 `[0,32,2]` 且会做 PKCS7 填充） |
| 第4位 模式 | `0` | **ECB**（为 1 才启用 iv 链式异或，即 CBC） |
| 第5位 iv | `"012345677890123"` | ECB 下不生效（代码里仍传了） |
| 第6位 填充 | `1` | PKCS7（解密后按其去填充） |

**解密尾部处理链**（源码顺序）：去尾部 `\0`（`replace(/\0*$/g,"")`）→ 去 PKCS7（末字节值 j≤8 则截掉 j 字节）→ `decodeURIComponent(escape(B))` 做 UTF-8 解码。

### 2.4 实测验证 + Python 等价复刻

- 取课件注释中的密文样本（1656 字节），**纯 Python 复刻成功**，解出：
  `{"list":[{"name":"元宇宙","channel_id":"093f65e0..."},{"name":"碳中和",...},...]}`
- 解密尾部字节实测为 `\x06\x06\x06\x06\x06\x06`（PKCS7 填充 6 字节），坐实 3DES-ECB + PKCS7；
- Node 实跑课件 `s()` 同一密文 → 与 Python 结果一致。

**Python 等价复刻（脱依赖运行，实测通过）**：

```python
from Crypto.Cipher import DES3
import base64, json

cipher = DES3.new(b"5e5062e82f15fe4ca9d24bc5", DES3.MODE_ECB)   # 24 字节 key → 3-key 3DES
plain = cipher.decrypt(base64.b64decode(encrypt_data))

plain = plain.rstrip(b"\x00")        # 对应 JS: replace(/\0*$/g, "")
j = plain[-1]
if j <= 8:
    plain = plain[:-j]               # 对应 JS: 去 PKCS7
data = json.loads(plain.decode("utf-8"))
```

### 2.5 复刻要点

- **大算法策略**：这类"整段库内核"不要硬啃位运算，execjs 直接调用即可；能读懂**参数位**（key/方向/模式/填充）就已具备纯 Python 复刻能力；
- **3DES 判断口诀**：key 长度 16 或 24 → 3DES；本次 key 24 字节 → 3-key 3DES；
- ECB 模式的坑：第 5 位 iv 传了也不生效，别被误导去分析 iv；
- 填充处理三部曲：去 `\0` → 去 PKCS7 → UTF-8 解码，顺序与 JS 源码一致才万无一失。

## 三、案例3 xdf：新东方搜课 MD5 盐值签名

**案例文件**：`05 xdf.py`（execjs 调用方）+ `06 xdf.js`（签名函数）

### 3.1 目标与请求

- 接口：`GET https://dsapi.xdf.cn/product/v2/class/search?{params}`
- 请求头必带 **`sign`**；URL query 必须带上签名同款的一整串参数。

### 3.2 签名函数 ve()（06 xdf.js 全文不到 20 行）

```javascript
function ve(e) {
    var t = "appId=".concat(5053, "&cityCode=").concat(110100, "&t=").concat((new Date).getTime());
    for (var r in e)
        String(e[r]) && void 0 != e[r] && null != e[r] && "undefined" != e[r] && "null" != e[r]
            && (t = "".concat(t, "&").concat(r, "=").concat(e[r]));
    return {
        params: t,                                                        // 拼串直接当 query
        sign: CryptoJS.MD5("".concat(t).concat("750F82C2-D8F6-49F6-878C-1E7EBEBC8DA2")).toString()
    }
}
```

拆解为三步：

1. **固定前缀**：`appId=5053&cityCode=110100&t=<毫秒时间戳>`（时间戳由前端现场生成）；
2. **追加业务参数**：遍历入参，排除 `undefined/null/"undefined"/"null"/空串` 后按 `&k=v` 追加（顺序 = for-in 顺序）；
3. **签名**：`sign = MD5(整串 + "750F82C2-D8F6-49F6-878C-1E7EBEBC8DA2")`——固定盐值硬编码在前端。

### 3.3 Python 调用方式（05 xdf.py）

```python
ret = execjs.compile(open("06 xdf.js").read()).call("ve", data)
sign, params = ret["sign"], ret["params"]

response = requests.get('https://dsapi.xdf.cn/product/v2/class/search?' + params,
                        headers={..., 'sign': sign})
```

- 一次 `ve()` 调用同时产出 `params` 和 `sign`——**必须同源**：sign 覆盖的就是 params 整串（含时间戳 t），分开生成会因时间戳不同而对不上。

### 3.4 实测验证

- Node 实跑 `ve({pageIndex:1, pageSize:12, keyword:"%E8%8B%B1%E8%AF%AD", order:"0"})`：
  - `params = appId=5053&cityCode=110100&t=1791618299945&pageIndex=1&pageSize=12&keyword=%E8%8B%B1%E8%AF%AD&order=0`
  - `sign = b0f91b98d0f6fdfdb1e260b3e583d005`
- 用 `hashlib.md5((params + 盐值).encode()).hexdigest()` 复算 → 与 JS 输出**完全一致**。

**纯 Python 复刻要点**：

```python
import hashlib, time
t = "appId=5053&cityCode=110100&t=%d" % int(time.time() * 1000)
for k, v in data.items():          # dict 保序，与 JS for-in 顺序一致
    if v not in ("", None, "undefined", "null"):
        t += "&%s=%s" % (k, v)
sign = hashlib.md5((t + "750F82C2-D8F6-49F6-878C-1E7EBEBC8DA2").encode()).hexdigest()
```

### 3.5 复刻要点

- 相比 Day21 建设库"三层 MD5 套娃"，本案例是**单层 MD5 + 固定盐**的最简形态：`sign = MD5(参数串 + salt)`；
- 拼串串内已经包含时间戳参数 `t`，服务端拿请求里的 `t` 复算即可校验——**params 和 sign 必须来自同一次调用**；
- 业务参数的值保持原样拼入（如 `keyword` 是 URL 编码后的 `%E8%8B%B1%E8%AF%AD`，Python 传入什么就拼什么，别再二次编码）；
- 空值过滤条件照抄 JS（`""/undefined/null/"undefined"/"null"` 五种），否则服务端复算不一致。

## 四、加密位置三分法与路线选择（总结）

| 加密位置 | 本课案例 | 定位手段 | 复刻目标 |
| :--- | :--- | :--- | :--- |
| 请求参数签名 | xdf | 搜请求头自定义字段名（`sign`）→ 追生成处 | 还原拼串规则 + 盐/密钥 |
| 响应整体加密 | czw | 响应是 base64"乱码"→ 搜 `decrypt`/`AES` | 还原 key/iv/模式/填充 |
| 响应字段加密 | qmp | 响应 JSON 里有 `encrypt_data` 字段 → 搜字段名 | 还原解密函数（可 execjs 直调） |

**Python 与 JS 双路线选择**：

| 维度 | PyCryptodome 等纯 Python | execjs 调 JS |
| :--- | :--- | :--- |
| 适用 | 标准算法且参数清晰（AES/3DES/MD5） | 大算法内核、逻辑复杂难还原 |
| 本课案例 | czw（AES）、qmp（3DES 复刻）、xdf（MD5 复刻） | qmp、xdf（先跑通再考虑复刻） |
| 优势 | 脱 Node 依赖、部署稳定、限频控制方便 | 原汁原味、保真度高、实现成本低 |

> 经验：**execjs 快速打通 → 确认算法族与参数 → 有能力再转纯 Python**。本课三个案例全部完成了双路线对照验证。

## 七、关键记录点速查

- **AES-CBC + ZeroPadding 流水线**：`b64decode → AES.new(key, CBC, iv).decrypt → rstrip("\x00") → json.loads`；
- **CryptoJS 密钥 words 形态**：`{words:[4个32位大端整数], sigBytes:16}`，按大端展开字节即原密钥串（`0x337A4B7A` → `3zKz`）；
- **3DES 识别**：key 长度 16/24；本次 qmp key 24 字节 → 3-key 3DES-ECB + PKCS7；
- **qmp 解密链**：自定义 base64 → 3DES-ECB 解密 → 去尾 `\0` → 去 PKCS7 → UTF-8 → `JSON.parse`；
- **大算法内核策略**：不硬啃位运算，execjs 直调；读懂参数位（key/方向/模式/iv/填充）即可转纯 Python；
- **MD5 盐值签名公式**：`sign = MD5(固定参数+时间戳+业务参数拼串 + 硬编码盐)`；**params 与 sign 同源生成**；
- **空值过滤**：拼串前排除 `""/undefined/null/"undefined"/"null"`，照着 JS 抄，防止服务端复算不一致；
- **加密位置三分法**：请求签名（看 headers）／响应整体加密（看整段乱码）／响应字段加密（看 encrypt_data 类字段）；
- **课时联系**：czw 与作业中的招标网案例同站点（响应解密视角互补）；qmp 与作业中的企名片案例同站点（三条目 3DES 与接口直连呼应）；xdf 是从"三层 MD5 套娃"（Day21 建设库）退化到"单层 MD5 + 盐"的最简签名形态。
