## 二、签名算法拆解（get_sign / get_header 核心逻辑）

五个输入参数：

```javascript
K = {
  "nonce":      "...",   // 32 位 hex 随机串（get_nonce 生成）
  "timestamp":  "...",   // 毫秒时间戳字符串
  "deviceId":   "...",   // 设备 ID（7-4-4-4-9 位 hex 格式）
  "secret":     "...",   // 硬编码密钥（secretType=2 对应生产密钥）
  "secretType": 2
}
```

四段哈希（**混用了三种算法**是本案例的标志性设计）：

```javascript
L = MD5(nonce)                                // 32 hex
B = SHA1(timestamp)                           // 40 hex
N = MD5(nonce + deviceId)                     // 32 hex
C = SHA1(secret + timestamp)                  // 40 hex
C = C.substring(C.length - 16, C.length - 1)  // 取后 15 个 hex 字符（substring 左闭右开！）
D = window.v(C, true, 16).toUnsigned().toString(10)   // 15 位 hex -> 十进制大数
```

拼接与终值：

```javascript
F = [L, B, N, D].reduce((t, e) => t + "!" + e)   // "!" 分隔四段
sign = SHA384(F)                                  // 96 hex
```

两个易错点：

- `substring(len-16, len-1)` 左闭右开，实际取**后 15 位**（不是 16 位）；
- `D` 是十进制字符串，可能到 16~18 位，**超过 JS `Number.MAX_SAFE_INTEGER`（2^53-1 ≈ 9.0e15）后必须走大整数库**（见第三节），否则精度丢失直接导致签名错误。

## 三、long.js 大整数与内嵌 WebAssembly

### 3.1 为什么需要 long.js

15 位 hex 最大值 0xFFFFFFFFFFFFFF（60 bit）≈ 1.15e18，远超 JS 安全整数范围。
直接 `parseInt(C, 16)` 会丢精度，误差传导到整个 sign，服务端校验必失败。
（本项目验证样本中 D = 17979043229821670，已经大于 2^53-1，正是必须用大数库的典型值。）

### 3.2 long.js 的表示与转换

- 用 `low` / `high` 两个 32 位整数拼出一个 64 位整数（`new r(t, e, n)`，n 为 unsigned 标志）；
- `fromString`（课件挂载为 `window.v`）：十六进制串按 8 字符一组循环
  `o = o.mul(16^8).add(parseInt(chunk, 16))` 累乘累加；
- `toString(10)`：大数除法逐位取余转十进制。
- 调用链：`window.v(C, true, 16)`（unsigned/16 进制）→ `.toUnsigned()` → `.toString(10)`。

### 3.3 内嵌 WebAssembly 的点睛之笔

课件中 long.js 顶部有一段极小的二进制模块：

```javascript
try {
  n = new WebAssembly.Instance(
        new WebAssembly.Module(new Uint8Array([0,97,115,109, /* … */])), {}).exports
} catch (t) {}
```

这是 long.js 自带的内嵌 WASM，导出 `mul` / `div_s` / `div_u` / `rem_s` / `rem_u` / `get_high` 六个函数，用于 64 位乘除法原生加速；`multiply` / `divide` / `modulo` 内优先调用 `n.mul`、`n.div_s` 等。

- Node 环境同样支持 WebAssembly → 加速路径生效；
- 若不支持，try/catch 静默失败并自动退回纯 JS 的 16 位分片乘法（结果一致，仅性能差异）；
- **逆向提示**：看到 `WebAssembly.Module(new Uint8Array([0,97,115,109,...]))` 不必恐慌——起头字节 `0x00 0x61 0x73 0x6d`（即 `\0asm`）是标准 wasm 魔数，很多是公开库（如 long.js）的内置加速模块，不承载核心算法。

### 3.4 Python 等价实现

```python
D = str(int(C15, 16))   # Python 原生大整数，一行等价于 long.js fromString + toString
```

➜ 反向经验：JS 端出现 long.js / BigInt / 大数库，Python 侧优先尝试原生 `int` 直替。

## 四、动态参数生成器（huiNong2.js）

### 4.1 `get_nonce(timestamp)` —— 类 UUID 随机串（32 位 hex）

```javascript
function get_nonce(timestamp) {
  l = function (t) {
    var e = timestamp;
    return (t ? "xxxxxxxxxxxxxyxxxxyxxxxxxxxxxxxx"
              : "xxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx")
      .replace(/[xy]/g, function (t) {
        var n = (e + 16 * Math.random()) % 16 | 0;
        return e = Math.floor(e / 16),
          ("x" == t ? n : 3 & n | 8).toString(16)
      })
  }
  return l(!0)
}
```

- 时间戳作"种子"逐位除以 16 被消耗，每位再混入 `Math.random()`；
- `x` 位取值 0-f；`y` 位固定取 `(3&n)|8`（范围 8-b）——经典 UUID v4 变体手法，但模板非标准：
  实测保留位在 **index 13、18**（标准 uuid4 去连字符模板则是版本位 12='4'、变体位 16='y'）；
- 该参数仅要求 32 位 hex 格式，"随机值只需格式合规"是常见设计。

### 4.2 `get_traceid(timestamp)` —— 36 进制链路追踪 ID（16 位）

```javascript
o(timestamp, 9)                    // 时间戳转 36 进制（字符集 0-9A-Z），左补 0 至 9 位
+ o(randomInt(0, 78364164095), 7)  // 78364164095 = 36^7 - 1，随机段补至 7 位
```

- `X-B3-TRACEID = get_traceid(time)`；`X-CLIENT-SID = "S_" + get_traceid(time - 1000)`；
- 前 9 位可逆解析回时间戳（验证抓包样本是否"看对字段"的实用技巧），后 7 位为随机段。

### 4.3 `get_header()` —— 组装 9 个请求头

| 请求头 | 值 |
|--------|-----|
| `X-CLIENT-APPID` | `"5"` |
| `X-CLIENT-PAGE` | `"/hangqing/"` |
| `X-HN-JOB` | 站方"招聘信"彩蛋文案（实战中必需，见第七节） |
| `X-CLIENT-ID` | deviceId（7-4-4-4-9 位 hex） |
| `X-CLIENT-SID` | `"S_" + traceid(time - 1000)` |
| `X-B3-TRACEID` | `traceid(time)` |
| `X-CLIENT-TIME` | 毫秒时间戳 |
| `X-CLIENT-NONCE` | `get_nonce(time)` |
| `X-Client-Sign` | 签名（算法见第二节） |

## 五、Python 桥接与复刻

### 5.1 execjs 桥接调用（课件 huiNong.py 方式）

```python
import execjs
header = execjs.compile(open("huiNong2.js").read()).call("get_header")
headers.update(header)   # 合并进 requests 的 headers
```

优点：跑通快；缺点：依赖 Node 与 crypto-js 环境。

### 5.2 纯 Python 复刻（推荐，无环境依赖）

```python
import hashlib

L = hashlib.md5(nonce.encode()).hexdigest()
B = hashlib.sha1(timestamp.encode()).hexdigest()
N = hashlib.md5((nonce + device_id).encode()).hexdigest()
C15 = hashlib.sha1((secret + timestamp).encode()).hexdigest()[-16:-1]
D = str(int(C15, 16))
F = "!".join([L, B, N, D])
sign = hashlib.sha384(F.encode()).hexdigest()
```

## 七、实战备注（关联本项目经验）

1. **签名匹配 ≠ 请求通过（500301 排障经验）**：服务端除校验 `X-Client-Sign` 外，还实际校验两处非签名因素——
   ① `X-HN-JOB` 头必需（缺省即返回 code=500301，其内容为站方"招聘信"彩蛋文案）；
   ② deviceId 必须符合 **7-4-4-4-9 位 hex 格式**（标准 uuid4 的 8-4-4-4-12 会被拒）。
   排查方法：Python 与浏览器请求头逐项对照实验，勿迷信抓包样本中的随机值（deviceId 只需格式合规，可随机生成）。
2. **同款算法两端同构**：本课件（APP 端 `appapi.cnhnb.com`）与本项目 Day22 实战的 H5 端
   （`m.cnhnb.com` vendors.app.js 模块 311）签名逻辑完全同构（MD5/SHA1/SHA384 组合 + secretType=2 密钥），
   纯 Python 复刻版已在本项目 `newcases\惠农网H5请求签名逆向\` 交付。
3. **定位要点**：搜 `X-Client-Sign` 或 `cryptoSha384` / `cryptoMd5` 关键字即可命中；
   整个签名函数只依赖 crypto-js + long.js 两个公开库，剥离成本低。
