## 一、请求堆栈调试法（定位加密函数的通用方法论）

**课件文件**：`03 请求堆栈.html`

### 1.1 课件演示代码（模拟真实爬虫场景）

```javascript
function encrypt(data) { return "asdfghjkl" }        // 假加密函数

function a() { b() }                                 // 入口

function b() {
    let data = "hello yuan"
    let encrypt_data = encrypt(data)                 // ② 加密发生在这里
    c(encrypt_data)
}

function c(encrypt_data) {
    params = { "a": "apple", "b": "banana", "encrypt_data": encrypt_data }
    d(params)
}

function d(params) { e(params) }

function e(params) {
    console.log("发射的机密数据：", params)            // ③ "发射"（相当于 ajax 请求发出）
}
a()                                                  // ① 调用链起点
```

调用链：`a → b（加密）→ c → d → e（发射）`

### 1.2 核心思想：从"发射点"回溯到"加密点"

真实网站中，我们**只能先看到"发射"出去的请求**（Network 面板里的密文参数），不知道密文在哪里生成。破解思路：

1. **在发射处打断点**：对目标请求使用 XHR/fetch Breakpoints（或直接在发包函数处断点），请求发出时自动断下；
2. **看 Call Stack（调用堆栈）**：断下后堆栈显示 `e ← d ← c ← b ← a`，即数据一路被谁传递过来；
3. **逐层向上回溯检查**：点击堆栈里的上层函数逐层排查，找到哪一层对数据做了加密/签名（本演示中进入 `b` 就能看到 `encrypt(data)` 的调用）；
4. **进加密函数**：在 `encrypt` 内部断点，观察入参、key/iv、返回密文，完成算法还原。

### 1.3 为什么这招有效

- 代码打包混淆**只能改函数名，改不掉调用链**——堆栈是一层套一层"谁调用了我"的真实记录；
- 配合 Day20 的"关键字搜索五法"（搜 `encrypt`/`key`/`iv`/接口路径），一个负责"广撒网找位置"，一个负责"顺着调用链精确定位"，是目前最通用的两种定位手段。

> 实战印证：本次作业招标网案例即是同款思路——抓 XHR 定位接口 → 下载 JS 搜索 → Call Stack 回溯到 `searchv17.js` 的 `AESDecrypt`。

## 二、sign 签名逆向案例：建设库（jianzhushe）

**案例文件**：`04 jianzhushe.py` + `05 jianzhushe.js`（JS 算法 + Python 调用双份）

### 2.1 案例信息与防爬机制

- 目标接口：`POST https://capi.jiansheku.com/nationzj/enterprice/page`（企业搜索分页）
- 防爬机制：请求头必须携带 **`sign` + `timestamp`** 双参数；服务端用相同算法重新计算 sign 比对，防止参数被篡改/重放
- 请求体 `json_data` 为复杂嵌套结构（achievementQueryDto / aptitudeQueryDto / page 等），**整个 body 参与签名**

### 2.2 签名算法 JS 源码逐层拆解（05 jianzhushe.js）

算法由 4 个辅助函数 + 1 个入口组成：

**① `Ou(e)` —— 取 key 并排序**

```javascript
Ou = function (e) {
    var t = new Array, n = 0;
    for (var i in e) t[n] = i, n++;     // 收集对象所有 key
    return t.sort()                     // 字典序排序
}
```

**② `ku(t)` —— 值的规范化序列化**

```javascript
ku = function e(t) {
    var n;
    if (Array.isArray(t)) {             // 数组：递归清理 null 字段
        for (var r in n = new Array, t) {
            var o = t[r];
            for (var i in o)
                null == o[i] ? delete t[r][i] : Array.isArray(t[r][i]) && e(t[r][i])
        }
        return n = t, JSON.stringify(n).replace(/^(\s|")+|(\s|")+$/g, "")  // 序列化后剥掉首尾引号/空白
    }
    return n = t && t.constructor === Object ? JSON.stringify(t) : t        // 普通对象→JSON串；字符串/数字原样
}
```

**③ `Cu(e)` —— 参数拼接（签名素材）**

```javascript
function Cu(e) {
    var t = Ou(e), n = "";
    for (var i in t) {
        var r = ku(e[t[i]]);
        null != r && "" != r.toString() && (n += t[i] + "=" + r + "&")      // 空值跳过，拼 "key=value&"
    }
    return n                                                               // 例：k1=v1&k2=v2&
}
```

**④ `Su(e,t,time)` —— 单层 MD5**

```javascript
Su = function (e, t, time) {
    var n = t + e + time;                  // 注意拼接顺序：data + key + time
    return n = CryptoJS.MD5(n).toString();
}
```

**⑤ `get_sign(param,time)` —— 三层 MD5 套娃（核心）**

```javascript
function get_sign(param, time) {
    t = Cu(param);                         // ① 参数拼成 k=v& 串
    return Su("ghaepVf6IhcHmgnk4NCTXLApxQkBcvh1",
           Su("mwMlWOdyM7OXbjzQPulT1ndRZIAjShDB",
           Su("ZuSj0gwgsKXP4fTEz55oAG2q2p1SVGKK", t, time), time), time);
}
```

即（K1/K2/K3 为硬编码密钥）：

```
m1   = MD5(拼参串 + K1 + time)
m2   = MD5(m1 + K2 + time)
sign = MD5(m2 + K3 + time)
```

### 2.3 Python 端调用方式（04 jianzhushe.py）

```python
import execjs, time
timer = int(time.time() * 1000)                          # 毫秒时间戳
sign = execjs.compile(open("05 jianzhushe.js").read()).call("get_sign", json_data, timer)

headers = {
    'content-type': 'application/json;charset=UTF-8',
    'devicetype': 'PC',
    'page': 'search-enterprise',                         # 业务标识头
    'origin': 'https://www.jiansheku.com',
    'referer': 'https://www.jiansheku.com/',
    'sign': sign,                                        # ① 签名
    'timestamp': str(timer),                             # ② 与签名配套的时间戳
}
response = requests.post('https://capi.jiansheku.com/nationzj/enterprice/page',
                         headers=headers, json=json_data)
```

### 2.4 复刻要点

- **同一个 `timer` 串起整条链**：JS 计算 sign 用的时间戳，必须与请求头 `timestamp` 完全一致（服务端复算时用请求头的时间戳）；
- 签名对象是**整个请求体**：改任何一个字段（如翻页 page）都必须重新计算 sign；
- 纯 Python 复刻等价实现：`Ou`→`sorted()`；`Cu`→ 排序后 `f"{k}={v}&"` 拼接；`Su`→ `hashlib.md5((data+key+ts).encode()).hexdigest()`（本次作业的 20 号建设库爬虫即纯 Python 版，不依赖 Node）。

## 三、execjs 调用 JS：mmz 案例的另一种实现

**课件文件**：`01 mmz案例之JS逆向.py` + `02 mmz.js`
（Day20 的 mmz 案例是纯 Python 复刻，这里换成 **execjs 直接执行前端 JS 文件**的方案）

### 3.1 JS 侧加解密函数（02 mmz.js 核心）

```javascript
const cryptoJs = require("crypto-js")

// 解密：d(key, 密文base64) —— key 同时充当 iv
function d(e, a) {
    e = cryptoJs.enc.Utf8.parse(e);
    var l = cryptoJs.AES.decrypt(a, e, {
        mode: cryptoJs.mode.CBC,
        padding: cryptoJs.pad.Pkcs7,
        iv: e                                  // iv 就是 key 本身
    });
    return cryptoJs.enc.Utf8.stringify(l).toString()
}

// 加密核心：e(key, 明文)
function e(e, a) {
    return e = cryptoJs.enc.Utf8.parse(e),
        a = cryptoJs.enc.Utf8.parse(a),
        cryptoJs.AES.encrypt(a, e, {
            mode: cryptoJs.mode.CBC,
            padding: cryptoJs.pad.Pkcs7,
            iv: e
        }).toString()                          // 输出 base64 字符串
}

// 加密入口：encrypt_data(key, 数据对象) —— 对象先 JSON 序列化再加密
function encrypt_data(k, data) {
    return e(k, JSON.stringify(data))
}
```

### 3.2 Python 侧调用（01 mmz案例之JS逆向.py）

```python
import execjs

JSCode = open("02 mmz.js").read()              # pip install PyExecJS（底层需 Node.js）
JSCompile = execjs.compile(JSCode)

k = '55b3b62613aef1a0'                         # 请求加密 key
data = {"Type": 0, "page": 1, "expire": ...}
data = JSCompile.call("encrypt_data", k, data) # 请求体加密（Python dict 自动转 JS 对象）
response = requests.post('https://www.maomaozu.com/index/build.json', ..., data=data)

e = "0a1fea31626b3b55"                         # 响应解密 key（另一把钥匙）
data = JSCompile.call("d", e, response.text)   # 响应解密 → 明文 JSON
```

### 3.3 execjs 方案 vs 纯 Python 复刻方案

| 维度 | execjs 调用 JS | 纯 Python 复刻 |
| :--- | :--- | :--- |
| 实现成本 | 低：拷 JS 直接跑，不用读懂算法 | 高：必须逐行读懂并还原 |
| 保真度 | 高：原汁原味执行前端逻辑 | 依赖人工理解，细节易错（填充/编码） |
| 环境依赖 | 需 Node.js + node_modules | 只需 pip 包，部署简单稳定 |
| 适用场景 | 算法复杂/含大依赖库（如 CryptoJS）时 | 算法清晰或需脱离 Node 环境时 |

> 选择建议：先用 execjs 快速打通验证思路，确认字段与链路后再决定是否转纯 Python。

## 四、工程化细节（package.json / node_modules / test）

### 4.1 依赖管理

- 根目录 `package.json`：`{"dependencies": {"crypto-js": "^4.2.0"}}` —— JS 里 `require('crypto-js')` 的来源；
- `node_modules/crypto-js/`：本地安装的加密库（含 aes / md5 / tripledes / pad-* / mode-* 等全部算法模块与文档）；
- **execjs 执行 JS 文件时，require 的包必须在其目录（或上层）的 node_modules 中存在**——这是 commonjs 的解析规则，`test/` 子目录因此单独装了一份。

### 4.2 test 目录（sign 双验证小实验）

| 文件 | 作用 | 说明 |
| :--- | :--- | :--- |
| `test.js` | 算法版：内置测试参数，运行即 `console.log(get_sign())` 输出签名 | 与 05 jianzhushe.js 同算法（去注释、page=4） |
| `test.py` | 请求版：**写死 sign + timestamp** 直接请求接口 | 验证"sign 与 timestamp 配套才有效"：二者必须来自同一次计算 |

> test.py 的意义：sign 是一次性配对的——服务端用请求头 timestamp 复算签名。写死的旧 sign 配旧 timestamp 在时间窗口内仍能通过，单改其一必失败。

## 六、关键记录点速查

- **三层 MD5 签名链**：`sign = MD5(MD5(MD5(拼参串+K1+ts)+K2+ts)+K3+ts)`，K1/K2/K3 硬编码于 JS；
- **`Su` 拼接顺序**：`data + key + time`（函数体是 `t + e + time`，参数名易混淆，认准实际顺序）；
- **`Cu` 拼参规则**：key 字典序排序 → `key=value&` → 空值/null 跳过 → 结尾带 `&`；
- **`ku` 值规范化**：数组递归删 null 字段，JSON 序列化后剥首尾引号；普通对象 JSON 串；标量原样；
- **时间戳双绑定**：sign 与 timestamp 必须同源配套，服务端用 timestamp 复算校验（防重放）；
- **请求堆栈调试口诀**：发射点断点 → Call Stack 回溯 → 逐层排查 → 进入加密函数；混淆改不了调用链；
- **execjs 备忘**：`execjs.compile(js代码).call("函数名", 参数...)`，Python 类型自动转 JS；需 Node.js + 对应 node_modules；
- **两把钥匙惯例**：请求加密 key 与响应解密 key 常不同（mmz：`55b3...` 加密 / `0a1f...` 解密），别只找一把；
- **CryptoJS 默认输出**：AES.encrypt(...).toString() 默认输出 base64（OpenSSL 格式时含 Salt 头，需注意）；
- **与作业的联系**：建设库 sign 作业已纯 Python 复刻（20 号脚本），招标网接口解密用到了同款堆栈定位思路（21 号系列）。
