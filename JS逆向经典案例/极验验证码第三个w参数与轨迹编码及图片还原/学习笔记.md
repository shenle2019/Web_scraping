## 0. 一句话认识本案例

第三个 w 出现在**手工拖动滑块完成滑动后**产生的 `ajax.php` 数据包中。整体公式与前两个 w 同骨架：

**w = h + u，其中 h = 自定义Base64( AES-CBC( 轨迹数据体 o , aeskey ) )，u = RSA(aeskey)**

本次的「新东西」不在加密骨架（已在前两课拆完），而在**数据体怎么造**：

1. **滑动距离 t**：下载的验证码背景图是**乱序**的，先用 canvas 还原逻辑逆出排序数组、用 PIL 把图拼回去，再用 OpenCV 模板匹配测出滑动距离；
2. **轨迹 e（本次最大难点）**：真滑动的鼠标轨迹无法模拟，必须逆出**轨迹生成的编码算法**——两层：`$_FD_`（差分压缩 + 方向字符编码）+ `$_BBED`（按 c/s 插字符）；
3. **userresponse**：由 H 函数把「滑动距离 + challenge 末两位」搅成乱序字符串。

## 2. 第三个 w 的定位与整体结构

### 2.1 定位

- 触发时机：**拖动滑块松手后**出现的 `ajax.php` 数据包；
- 在该包断点（XHR 断点或搜索 `\u0077`）后，观察到 **w = h + u** 的拼接位置，从该位置向上回溯到函数定义处，即 `get_third_w`；
- 反混淆后函数体已不太长（前两课已把加密零件拆干净，本课主要是把数据体拼装过程说清楚）。

### 2.2 反混淆后的主干（结构观察）

```js
function get_third_w(t, e, n) {
    // t=滑动距离 e=轨迹加密结果 n=滑动耗时
    var r = this, i = r['$_CJk'];   // i 是配置对象（后续被参数化）
    var o = {
        'lang': i['lang'] || 'zh-cn',
        'userresponse': H(t, i['challenge']),   // H 函数：距离+challenge 末两位
        'passtime': n,
        'imgload': r['$_CAGy'],                 // 固定值（示例 173/137）
        'aa': e,                                // 轨迹编码结果（核心）
        'ep': r['$_CCCY']()                     // 环境对象，可先写死（同第二 w）
    };
    // try-catch 一大段 window['_gct'] 逻辑 → 最终等效于 o['h9s9'] = '固定随机数'
    i['offline'] && (o['x'] = t),               // offline 为假，此句无意义
    o['rp'] = X(i['gt'] + i['challenge']['slice'](0, 32) + o['passtime']);  // X = MD5
    var u = r['$_CCDm']()                       // RSA(aeskey)（逻辑同第一 w 的 $_CCGZ）
      , l = V['encrypt'](gt['stringify'](o), r['$_CCEc']())  // AES-CBC
      , h = m['$_FEX'](l)                       // 自定义Base64（同第一 w 的 $_HED）
      , f = { 'gt':…, 'challenge':…, 'lang':…, '$_BCN':…, 'client_type':…, "w": h + u };
    return f;
}
```

**观察：`w = h + u` 与第一个 w 的 `w = i + r` 是同一套公式**——h 是自定义Base64 密文（变长），u 是 RSA 定长 256 字符串。三课共用同一 aeskey（id.key 缓存），这是极验多个 w 之间能"接力"的原因。

### 2.3 三个入参的由来（逆向后的参数表）

| 参数 | 含义 | 怎么来 |
| --- | --- | --- |
| `t` | 水平滑动距离 | OpenCV 对还原后的图做模板匹配得出 |
| `e` | 轨迹加密结果 | **不可能模拟，必须逆向**：`$_FD_(guiji)` + `$_BBED(tt, c, s)` 两步算出 |
| `n` | 滑动总耗时 | 轨迹生成算法返回的最后一个时间戳 |

### 2.4 函数签名改造

原函数依赖 `this`（W 对象）和内部配置对象 i，改造后：

```text
get_third_w(t, n, guiji, c, s, gt, challenge)
  ├─ 原参数 e 不再传入 → 由 guiji + c + s 在函数内算出
  └─ 原 r['$_CJk'] 的 lang/gt/challenge 三处引用 → 参数化传入
```

其中 `c`、`s` 不是随意写死的——**它们来自第二个 get.php 响应中的 `c` 和 `s` 字段**（见 §4.3）。

## 3. 数据源之一：图片乱序还原（canvas → PIL）

### 3.1 为什么图是乱的

第二个 `get.php` 返回 3 张图（bg 乱序背景 / fullbg 完整背景 / slice 滑块），从 static.geetest.com 下载后 `bg.jpg` 直接打开是碎的——**页面是在前端用 canvas 实时"拼图"还原的**，所以必须逆出前端还原逻辑。

### 3.2 定位手段：Event Listener Breakpoints（事件监听器断点）

- 位置：DevTools → Sources → Event Listener Breakpoints；
- 用法：勾选 canvas / 鼠标类事件，页面触发对应事件时自动断下，逐步跟到还原代码；
- 本次在事件断点后跟到 fullpage.js 中的还原函数。

### 3.3 还原代码（反混淆后）

```js
var o = i["getContext"]("2d");          // i = 不可见 canvas 312×160
o["drawImage"](t, 0, 0);                // t = 乱序背景图，先画在离屏画布上
var s = e["getContext"]("2d");          // e = 可见 canvas
e["height"] = 160; e["width"] = 260;    // 输出尺寸 260×160

for (var a = r / 2 /* =80 */, _ = 0; _ < 52; _ += 1) {
    var c = Ut[_] % 26 * 12 + 1               // 源块 x
      , u = 25 < Ut[_] ? a : 0                // 源块 y（上下两行）
      , l = o["getImageData"](c, u, 10, a);   // 源块：10 宽 × 80 高
    s["putImageData"](l, _ % 26 * 10, 25 < _ ? a : 0);  // 目标位置：步进 10
}
```

**观察要点：**

- `Ut` 是 52 个元素的**还原顺序数组**（26 列 × 2 行 = 52 块）；
- 乱序图块宽 **12px**（源步进 12，取其中 10px，+1 的偏移错开边界），拼回后块宽 **10px**——这就是实测 **312 → 260** 的来源（26×12=312，26×10=260）；
- 行高 80（`r/2`），上下两行各拼一次；
- `Ut[_] > 25` 决定源块在上半区还是下半区（`% 26` 取列）。

### 3.4 Python 改写要点（canvas → PIL）

```python
l = old_img.crop((c, u, c+10, u+a))   # js getImageData(x,y,w,h) → PIL (left,upper,right,lower)
new_img.paste(l, (x1, y1))            # 坐标换算：right=x+w, lower=y+h
```

- js 的 `getImageData(x, y, w, h)` 与 PIL 的 `crop(left, upper, right, lower)` 坐标语义不同，**换算关系是 right=x+w、lower=y+h**，这是改写时最容易写错的地方；
- `Image.new('RGB', (260, 160))` 好比 js 中的空白 canvas；`crop` ≈ `getImageData`，`paste` ≈ `putImageData`；
- 还原产物 `new_bg_img.jpg` 实测 260×160，用于下一步测距。

第二个 `get.php` 返回的 `challenge` 在**原 challenge 末尾多了 2 位字符**，后续第三个 w 全程要用这个 **new_challenge**（H 函数恰好也是拿它的末两位来做文章）。

## 4. 数据源之二：轨迹的生成与双层编码（本课核心）

### 4.1 原始轨迹长什么样

轨迹是一个数组：`[[x, y, t], …]`——**累计横坐标、累计纵坐标、累计时间戳**（毫秒）。真滑动的点无法模拟，所以要做两件事：

1. **生成轨迹**：用缓动函数造一条"像人"的点序列（§5.2，Python 侧）；
2. **编码轨迹**：逆出前端把轨迹数组编译成一串字符的算法——即 `e = $_BBED($_FD_(guiji), c, s)`。

### 4.2 第一层：`$_FD_(guiji)`——差分压缩 + 字符编码

整体分三步：

**第一步：相邻点差分**

```js
// 遍历轨迹相邻两点，求差值 e=dx, n=dy, r=dt
0 == e && 0 == n && 0 == r || (0 == e && 0 == n ? o += r : (i.push([e, n, r + o]), o = 0));
```

- 全 0 的差分直接跳过；
- `dx=dy=0`（原地停留）时，把 dt **累计到下一个有效点**（`o += r`，即"待机时间"合并）；
- 否则输出 `[dx, dy, dt+待机累计]`，待机清零；
- 收尾时若仍有待机累计，补一条 `[e, n, o]`。

**第二步：方向编码器（9 个常用方向 → 1 个字母）**

```js
var e = [[1,0],[2,0],[1,-1],[1,1],[0,1],[0,-1],[3,0],[2,-1],[2,1]];
if (t[0]==e[n][0] && t[1]==e[n][1]) return 'stuvwxyz~'[n];
```

- 9 组常见 (dx, dy) 映射到字符 `s t u v w x y z ~`；
- 命中方向表：**只往 y 段（i 数组）塞一个字母**；
- 未命中：x 归 x 段（r 数组）、y 归 y 段（i 数组），各自用下面的 n() 编码。

**第三步：数字编码函数 n(t)（64 字符表 + 前缀符号）**

```js
var e = '()*,-./0123456789:?@ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqr';  // 64 个字符
o = parseInt(|t| / 64)；若 o >= 64 则 cap 到 63；
前缀 '!'（t<0）+ '$'（有高位）+ charAt(o) + charAt(|t| % 64)
```

- 64 字符表本质是**一字符存 6 bit**（0~63）；
- 绝对值 ≥ 64 时用高位字符 + `$` 标高位，负数加 `!` 前缀——**这就是要"查 -1!! 这类怪串"格式的同款编码家族**；
- `n(t[2])`（时间）也走这个编码。

**输出拼装：**

```js
return r.join('') + '!!' + i.join('') + '!!' + o.join('');
```

三段用 `!!` 分隔：**x 段 ｜（方向字母+y段）｜ 时间段**。

（课件中对该函数的改造成本最低的方式：删掉 `this['$_HCb']`，把轨迹通过参数 `guiji` 直接传入；`ct` 包装类只保留 `$_CAE`（等于 map），因为 `new ct(t)['$_CAE'](fn)` 就是「对数组 t 逐项执行 fn」。）

### 4.3 第二层：`$_BBED(t, e, n)`——按 c/s 插字符

```js
function $_BBED(t, e, n) {         // t=第一层输出串 e=c（数组） n=s（字符串）
    if (!e || !n) return t;
    var r, i = 0, o = t, s = e[0], a = e[2], _ = e[4];   // c 只取第 0/2/4 位
    while (r = n['substr'](i, 2)) {                       // s 每 2 个字符一组 hex
        i += 2;
        var c = parseInt(r, 16)
          , u = String['fromCharCode'](c)                 // hex → 字符
          , l = (s * c * c + a * c + _) % t['length'];    // 二次多项式决定插入位置
        o = o['substr'](0, l) + u + o['substr'](l);       // 在位置 l 插入该字符
    }
    return o;
}
```

**观察要点：**

- `c`（数组）与 `s`（字符串）**直接来自第二个 get.php 响应**（课件示例 `c=[12,58,98,36,43,95,62,15,12]`、`s='28376170'`），每次会话不同，**必须动态传递，不能写死**；
- 二次多项式 `(c0·x² + c2·x + c4) % len` 算出插入点，把 s 拆成的 hex 字符逐个"埋"进第一层输出串里；
- 两层叠加后的字符流才是数据体 `o['aa']` 的值——即 `e`。

> 记忆钩子：**$_FD_ 负责"把轨迹翻译成字符"，$_BBED 负责"往字符流里埋干扰字符"，c/s 就是埋点的钥匙。**

### 4.4 H 函数（userresponse）

```js
function H(t, e) {                       // t=滑动距离 e=new_challenge
    var n = e['slice'](-2);              // 取末两位（hex 字符）
    // hex → int：>57 的减 87（a~f→10~15），否则减 48（0~9）
    n = 36 * r[0] + r[1];                // 两位按 36 进制拼成偏移量
    var a = Math['round'](t) + n;        // 目标值 = 距离 + 偏移
    // 把 challenge（去掉末两位）逐字符去重，轮转装进 5 个桶 _[0..4]
    // 用面额 g=[1,2,5,10,50] 从大到小贪心分解 a：
    //   f - g[d] >= 0 → 从第 d 个桶里随机取一个字符拼到结果串，f -= g[d]
    //   否则把该桶和面额一起删掉，d--
    return p;                            // 拼出的乱序字符串
}
```

**观察要点：**

- 结果字符串的**字符全部来自 challenge 本身**，只是被"面额分解 + 桶轮转随机"打乱了顺序；
- 末两位参与偏移，保证每次 challenge（末两位会变）算出的目标值都不同；
- 该函数与第二个 w 里的 `get_H_value`（MD5）**不是一回事**——H 是"打乱字符"，X 才是 MD5。

### 4.5 其余字段

| 字段 | 处理方式 |
| --- | --- |
| `imgload` | this 上固定值，直接写死（示例 173 / 137） |
| `ep` | 环境对象，同第二 w 的处理方式——写死一份即可 |
| `h9s9` | try-catch 里 `window['_gct']` 一大段逻辑，等效于给 o 加一个**随机数属性**，直接写死 |
| `rp` | `X(gt + challenge.slice(0,32) + passtime)`，**X 函数 = MD5**（node crypto 可平替） |
| `$_BCN` / `client_type` | this 上的固定值（示例 `$_BCN:0`、`client_type:'web'`） |
| `u` | `r['$_CCDm']()` = RSA(aeskey)，与第一 w `$_CCGZ()` 逻辑相同，直接复用 |
| `h` | `m['$_FEX'](l)` 与第一 w `$_HED(o)` 实现相同，直接复用 |

## 5. Python 侧：测距与轨迹生成

### 5.1 OpenCV 模板匹配算距离

```python
bg = cv2.imread('new_bg_img.jpg'); slice = cv2.imread('slice.jpg')  # 注意：用还原后的图
bg灰、slice灰 → cv2.Canny 边缘 → cv2.matchTemplate(bg_can, slice, cv2.TM_CCOEFF_NORMED)
minValue, MaxValue, minLoc, maxLoc = cv2.minMaxLoc(r)
return maxLoc[0]   # 最佳匹配的 x 即为滑动距离
```

**观察要点：**

- 必须有"**先还原再测距**"的顺序——拿乱序 bg.jpg 去匹配是错的；
- Canny(255,255) 用的是纯边缘图做模板匹配；`maxLoc[0]` 即缺口横坐标；
- slice.jpg 实测 55×52（比视觉上的 40 略大，含阴影边），不影响 maxLoc 取值。

### 5.2 轨迹生成算法（ease_out_expo 缓动）

```python
def __ease_out_expo(sep): return 1 if sep==1 else 1 - pow(2, -10*sep)

slide_track = [[randint(-50,-10), randint(-50,-10), 0], [0, 0, 0]]  # 起点带负偏移的抖动
count = 30 + int(distance / 2)          # 点数随距离增长
t = randint(50, 100)                    # 初始耗时
for i in range(count):
    x = round(__ease_out_expo(i/count) * distance)   # 先快后慢的位移曲线
    t += randint(10, 20)                # 每步耗时随机递增
    if x == _x: continue                # 相同 x 去重
    slide_track.append([x, 0, t])
slide_track.append([distance, 0, t])    # 收尾补终点
return slide_track, t                   # t 作为滑动总耗时 passtime
```

**观察要点：**

- 起点不是 (0,0)：是**负偏移随机点**（模拟人手按下前的抖动），第二条 [0,0,0] 才是起点；
- 位移走 `1 - 2^(-10x)` 指数缓动（前段快、尾段慢，模拟人手）；
- 时间每步 +10~20ms 递增，累加值即总耗时 n；
- 生成的点数组直接喂给 `$_FD_`——**所以第三个 w 的"轨迹"是人类行为算法的仿造品**。

| 8 | `ajax.php`（api.geevisit.com） | 带 w3 请求，响应中出现 `validate` 即滑动验证通过 |

**观察要点：**

- 第 5 步第二个 `get.php` 用的是 **api.geevisit.com**（前一个 get.php 是 api.geetest.com），两个域名交替出现是本案例的固定现象；
- `c`/`s`/`new_challenge` 都必须从第 5 步响应中动态提取，事后传给 `get_third_w`；
- `callback` 参数带毫秒时间戳即可（jsonp 解析用）；
- 轨迹生成放在 Python 侧（因为要动图/测距），轨迹**编码**放在 JS 侧（final_js.js）——职责分工。

## 7. 速查卡（第三个 w 逆向口令）

```text
时机    → 滑动松手后的 ajax.php，挑战值用 new_challenge（末两位变化）
定位    → w = h + u 断点向上回溯 get_third_w
公式    → w = 自定义Base64(AES-CBC(o, aeskey)) + RSA(aeskey)
数据体 o→ lang / userresponse(H) / passtime / imgload / aa(轨迹) / ep / h9s9 / rp(MD5) / td
距离 t  → 乱序图根据 Ut 数组 PIL 还原(312→260) → OpenCV matchTemplate → maxLoc[0]
轨迹 e  → guiji 数组 → $_FD_(差分+方向表+64字符表+!!三段) → $_BBED(二次多项式插字符,c/s)
c/s     → 第二个 get.php 响应的 c、s 字段（必须动态传）
rp      → MD5(gt + challenge[:32] + passtime)
复用的  → encrypt1 / $_HED(自定义Base64) / $_CCGZ(RSA) / $_CCHE(aeskey) 全部来自第一 w
图片定位→ DevTools Event Listener Breakpoints → canvas 断点
```

### 易错点

1. **challenge 用错**：第三个 w 所有字段必须用第二个 get.php 返回的 new_challenge（比原值多 2 位）；用旧的会导致 H 函数和 rp 全错；
2. **c/s 写死**：课件示例值只是当时会话的现场值，必须动态提取；
3. **拿乱序图测距**：必须先 PIL 还原出 new_bg_img.jpg 再 OpenCV，否则距离必错；
4. **PIL 坐标换算**：`getImageData(x,y,w,h)` → `crop((x, y, x+w, y+h))`，直接照抄 js 参数会糊；
5. **轨迹三段分隔符**：`$_FD_` 输出是 `x段!!y段!!时间段`，漏掉 `!!` 编码即废；
6. **e 与 t 别传反**：`get_third_w(t, n, guiji, c, s, gt, challenge)`，第一参是距离、第二参是耗时。

## 8. 三个 w 系列总对照（Day29 → Day31 复盘）

| 对比项 | 第一个 w（Day29） | 第二个 w（Day30） | 第三个 w（Day31） |
| --- | --- | --- | --- |
| 时机 | 首次 get.php | 点击"验证"后 ajax.php | 拖动滑块松手后 ajax.php |
| 定位方式 | 搜 `\u0077` | Initiator + 调用栈回溯 + 数字搜索 | w=h+u 断点直接回溯 |
| 数据体 | 极验配置 JSON | 点击 13 键 + captcha_token + 指纹 | 轨迹数据体（9 键） |
| 特有难点 | aeskey 生成 / 自定义Base64 | djb2 + toString 定值 + 指纹四件套 | **图片还原 + 轨迹生成 + 轨迹双层编码** |
| 指纹加密 | — | MD5 系列（H 函数） | H=字符乱序 / X=MD5(rp) |
| 轨迹 | 无 | 空轨迹 $_HDZ([]) | **$_FD_ + $_BBED 双层编码** |
| 共享骨架 | w = 自定义Base64(AES-CBC) + RSA | 同左（共享 aeskey） | 同左（共享 aeskey） |

**系列总结**：三个 w 是**同一个加密骨架装三份不同数据**——把"骨架零件"（AES/自定义Base64/RSA/aeskey缓存）拆一次即可复用到全部三个 w；每课的真正工作量都在**数据体的构造**上：第一课啃配置对象、第二课啃点击指纹、第三课啃滑动行为（图片、距离、轨迹）。逆向这些"人类行为数据"的通用套路是：**下载原始素材 → 找到前端加工点（canvas/编码函数）→ 逆出加工算法 → 在 Python/Node 中重建**。
