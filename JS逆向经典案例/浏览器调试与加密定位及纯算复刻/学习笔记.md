# 浏览器调试与加密定位及纯算复刻 · 操作手册

> 来源：综合本目录 5 篇案例笔记（路飞学城 Day20-24 课件）的调试方法提炼总结
> 适用案例：maomaozu 论坛 / 建设库 / 招标网 / 企名片 / 新东方搜课 / 精灵数据 / 扇贝单词 / 贝壳找房 / 惠农网
> 使用方式：以后做新案例时，按本手册"第 1 → 2 → 3 → 4 步"顺序操作即可

## 0. 先建立全局观：逆向四步法

```
① 看（Network 抓包）           找到"加密发生在请求还是响应"
         ↓
② 搜（Sources 全局搜索）       用关键字五法海选出"嫌疑 JS 文件"
         ↓
③ 追（XHR 断点 + Call Stack）  顺着调用链精确回溯到"加密函数那一行"
         ↓
④ 算（纯算复刻）               理解算法和参数 → Python 复刻 → 离线双验证
```

一句话总结：逆向 = 从看得见的"密文请求/响应"，倒推出看不见的"加密函数在哪、怎么算的"。

本篇对应的四个问题：
- "按了 F12 之后怎么做？选 Network 吗？" → 第 1 章
- "关键字搜索的流程是什么？" → 第 2 章
- "请求堆栈如何挨个查找执行函数？原理是什么？" → 第 3 章
- "纯算的逻辑是什么？操作步骤是什么？" → 第 4 章

## 1. 第一步：按 F12 之后的完整操作（抓包找接口）

### 1.1 怎么打开

三种方式：键盘 F12 / Ctrl+Shift+I（部分笔记本要先按 Fn）/ 页面右键 → 检查。

打开后顶部一排面板：Elements（元素）、Console（控制台）、Sources（源代码）、Network（网络）、Application（应用）。**逆向主要就用 Network 和 Sources 两个**，其他基本不碰。

### 1.2 是的，第一站就是 Network（网络面板）

F12 打开后手动点顶部 Network。然后严格按下面顺序操作：

1. **勾选"保留日志"（Preserve log）**：重要！否则页面一跳转/刷新，请求记录全被清空，又得重来。
2. **点 "Fetch/XHR" 分类过滤**：列表里混杂着 html、css、js、图片、统计埋点，点开 Fetch/XHR 过滤后只剩接口请求——真正的数据接口都是 XHR/fetch 发出的。
3. **清空 + 刷新**：点左上角禁止符号清空列表，然后 F5 刷新页面（或手动触发操作：点搜索、翻页、登录按钮）。
4. **在列表里找目标接口**：看四列——
   - Name：接口名，常有语义（search、list、page、build.json……）
   - Status：200 是正常
   - Size：数据接口一般响应较大（几 KB ~ 几百 KB）
   - Type：xhr 或 fetch
5. **点开请求，逐个标签页看（核心）**：
   - **Headers（标头）**：请求头里有没有 `sign`、`timestamp`、`X-Client-Sign`、`token` 这类自定义字段？
   - **Payload（载荷）**：请求参数是明文 JSON？还是 base64/乱码？有没有 `expire`、`nonce` 等动态字段？
   - **Response（响应）**：返回是明文 JSON？还是整段乱码？还是 JSON 里某个字段（如 `encrypt_data`）是密文？
   - **Initiator（发起程序）**：会显示"是哪个 JS 文件发起了这个请求"——可能直接指向嫌疑 JS！
6. **留好现场**：
   - 右键请求 → Copy → Copy as cURL：方便之后还原请求
   - 右键 → Copy response：保存密文样本，离线复算要用

### 1.3 三看看出"加密位置"（最重要的判断）

| 看哪里 | 现象 | 结论 | 本目录案例 |
| :--- | :--- | :--- | :--- |
| 请求头 | 有 sign / X-Client-Sign / timestamp 等自定义字段 | 请求签名（防篡改） | 建设库、新东方、惠农网 |
| 请求体 | body 是一串 base64/乱码 | 请求体加密 | maomaozu |
| 响应体 | 整段返回都是 base64"乱码" | 响应整体加密 | 招标网 czw |
| 响应体 | 返回 JSON，但某字段（encrypt_data、data）是密文 | 响应字段加密 | 企名片、精灵数据、扇贝 |
| 请求体 | password 字段是 base64 | 单字段加密（多为 RSA） | 贝壳找房 |

> 判断出加密位置，决定了第 2 步搜索时用什么关键字。

### 1.4 常见问题

- **列表里没有目标请求？** ① 忘了刷新/触发太早；② 接口在别的域名（跨域），检查过滤条件；③ 数据直接在页面初始 HTML 里（不是接口拿的），去 Doc 类型里找。
- **请求太多？** Filter 输入框打关键字过滤（如输入 api、search）。

## 2. 第二步：关键字搜索（在 JS 里找加密代码）

抓包只能看到"密文长什么样"，不知道"谁生成的"。接下来去 JS 源码里搜。

### 2.1 在哪搜：Sources 面板 + 全局搜索

1. 点顶部 **Sources（源代码）** 面板。
2. **按 Ctrl+Shift+F 打开全局搜索**（在所有文件里搜；当前单文件内搜是 Ctrl+F，别搞混）。
3. 输入关键字回车，左侧列出所有命中位置。
4. 逐个点开结果 → 看那一行上下文（前后几行）→ 判断是不是"生成密文/签名"的代码。

### 2.2 搜什么：关键字五法（核心中的核心）

| # | 类型 | 搜什么 | 为什么有效 | 案例 |
| :-: | :--- | :--- | :--- | :--- |
| 1 | key/iv 关键字 | `key`、`iv`、`secret` | 对称加密密钥常以此命名 | 惠农网 secret |
| 2 | 接口路径关键字 | URL 路径片段，如 `build.json`、`recommendInfo`、`search/enterprice` | 直接反查调用该接口的代码 | 全案例通用 |
| 3 | 特殊方法关键字 | `encrypt`、`decrypt`、`JSON.stringify`、`JSON.parse` | 加解密/序列化方法的通用命名 | maomaozu、精灵数据 |
| 4 | 拦截器关键字 | `interceptors`、`transformRequest` | axios 统一封装加密的突破口 | — |
| 5 | headers 关键字 | 自定义头名：`sign`、`X-Client-Sign`、`timestamp`、`nonce` | 从头名顺藤摸瓜找生成处 | 建设库、惠农网、新东方 |

**优先级**：先搜"接口路径"和"headers 字段"（命中最准、结果最少）；不够再补 `encrypt/decrypt`、`key/iv`（通用词命中多，需人工筛）。

### 2.3 搜到结果之后怎么筛

1. **优先点业务 JS**：跳过 jquery.min.js、vendor、chunk-vendors 等第三方库（除非是调用处）。
2. **同时命中多个关键字的文件 = 嫌疑头号文件**：比如一个文件既命中 `build.json` 又命中 `encrypt`，重点研究它。
3. **直接在嫌疑行打断点**（点行号）→ 回页面触发操作 → 看是否断下、变量值是什么。

### 2.4 搜不到怎么办

- 试变体：`encrypt` 搜不到就试 `Encrypt`、`aes`、`encryptData`、`_encrypt`；
- 换 URL 另一段：搜不到 `recommendInfo` 试 `channelInformation`；
- 搜字面量/符号：`"&"`、`getTime`（时间戳）、`String.fromCharCode`；
- webpack 打包的代码直接搜内容依然有效，只是位置深；
- 全都搜不到（WASM/重度混淆）→ 改用第 3 章堆栈法。

### 2.5 案例速查（当时搜的词）

| 案例 | 搜的关键字 | 命中内容 |
| :--- | :--- | :--- |
| maomaozu | `build.json` / encrypt | 请求体加密函数 |
| 建设库 | `sign`（headers） | 三层 MD5 签名 |
| 精灵数据 | `decrypt` / `AES` | 响应解密函数 |
| 惠农网 | `X-Client-Sign` / `cryptoSha384` | 五段组合签名 |
| 贝壳 | `encrypt` / `setPublicKey` | RSA 密码加密 |

## 3. 第三步：请求堆栈调试（精确回溯到加密函数）

关键字搜索是"广撒网"，堆栈法是"顺藤摸瓜"，两者配合使用。

### 3.1 原理：为什么顺着堆栈就能找到加密函数

- 浏览器执行 JS 是函数一层层调用进行的，每发生一次调用都会记录到**调用堆栈（Call Stack）**；
- 请求发出时，堆栈完整保存了"这个请求是谁发的、谁调用了它、数据从哪来"的整条链；
- **打包/混淆能改函数名，改不掉调用链**：谁调用谁、数据在哪层变成密文，是真实执行出来的事实；
- 所以策略是：**在"发射点"（请求发出处）拦截 → 从后往前逐层检查数据形态（明文/密文）→ 找到"明文变密文"的那一层 → 那里就是加密函数。**

### 3.2 课件演示代码（03 请求堆栈.html，先看懂再上真实网站）

```javascript
function encrypt(data) { return "asdfghjkl" }   // 假加密函数
function a() { b() }                             // ① 入口
function b() {
    let data = "hello yuan"
    let encrypt_data = encrypt(data)             // ② 加密发生在这一层！
    c(encrypt_data)
}
function c(encrypt_data) {
    params = { "a": "apple", "b": "banana", "encrypt_data": encrypt_data }
    d(params)
}
function d(params) { e(params) }
function e(params) { console.log("发射的机密数据:", params) }  // ③ 相当于请求发出
a()
```

调用链：`a → b（加密）→ c → d → e（发射）`。
你能拦住的只有 e（发射点），但堆栈会显示出 `e ← d ← c ← b ← a` 的完整链——往上点进 b 就看到 `encrypt(data)`，**发射点回溯加密点，完成**。

### 3.3 真实网站操作步骤（手把手 10 步）

1. **Network 里找到目标请求**（第 1 章）。
2. **给请求下断点**：右键请求 → **Break on → XHR/fetch**（在 Fetch/XHR 断点处中断）。
   - 或：Sources 面板 → 右侧栏 XHR/fetch Breakpoints → `+` → 填请求 URL 片段（如 `GetSearchProHandler`）。
3. **回页面重新触发操作**（点击/翻页/刷新）→ 页面变灰停住（提示 "Paused in debugger"）。
4. **此时停在"发包函数"里**（发送请求那一行）。右侧 **Call Stack（调用堆栈）** 显示整条调用链：最下面是触发起点，栈顶是当前停住的位置。
5. **从栈顶开始逐个点击函数名** → 左侧代码区跳到对应函数代码，右侧 Scope/Local（作用域/局部变量）同步显示当时的变量值。
6. **逐层检查数据形态**：找出"分界点"——某一层已经是密文，再往上找一层数据还是明文 → **加密就发生在这两层之间**。
7. **进入加密函数**：找到类似 `xxx = encrypt(data)` / `sign(...)` 的调用行，点函数名或按 F11（Step into）进入内部。
8. **在加密函数内部细看（核心时刻）**：
   - 看入参：明文是什么、有哪些动态字段（时间戳、nonce）
   - 看字面量：key、iv、salt 常以字符串常量出现
   - 看调用的库：`CryptoJS.AES.encrypt(...)` / `JSEncrypt` / 自定义函数
   - 看返回值：密文格式（base64/hex/长度）
9. **验证理解**：在 Console 里直接调用该函数测试（如输入 `encrypt("test")`），输出与抓包一致即确认。
10. **记录全部参数**（key/iv/mode/padding/拼接顺序/盐）→ 进入第 4 章纯算。

### 3.4 断点操作按钮速查（停住之后怎么走）

| 按钮/快捷键 | 名称 | 作用 |
| :--- | :--- | :--- |
| F8 / ▶ | Resume 恢复执行 | 放行，继续跑 |
| F10 | Step over 步过 | 执行当前行，**不进**函数内部 |
| F11 | Step into 步入 | **进入**当前行的函数内部（追加密就用它） |
| Shift+F11 | Step out 步出 | 从当前函数跳出，回到调用它的地方 |
| 右键行号 | Add conditional breakpoint | 条件断点：满足条件才停（如 `data.length > 500`） |
| 右键行号 | Add logpoint | 日志断点：不暂停，只打印变量（不打断执行流） |

**排查技巧**：在疑似加密行"执行前/后"各停一次，看同一个变量——前后从明文变密文，实锤。

**偷懒技巧（Console 验证法）**：函数若挂在全局（window 上），直接在 Console 里 `函数名.toString()` 看源码，或直接调用看输出。

### 3.5 两种定位法的关系

| 方法 | 适用 | 特点 |
| :--- | :--- | :--- |
| 关键字搜索（Ctrl+Shift+F） | 知道现象特征（头名、路径、方法名） | 广撒网、快，但可能命中太多 |
| 请求堆栈（断点回溯） | 只知道是哪个请求；或代码混淆搜不到 | 精确定位，但要一层层排查 |

实战顺序：**先搜；搜不到或搜乱了用堆栈；也可交替用**（堆栈拿到函数名后再搜它还有哪里被调用）。

### 3.6 本目录案例印证

- **建设库**：搜 `sign` 命中 → 断点看 `get_sign(param, time)` 入参出参 → 还原三层 MD5；
- **招标网**：抓 XHR → 响应整段密文 → 对请求断点，Call Stack 回溯到 `searchv17.js` 的 `AESDecrypt`；
- **惠农网**：搜 `X-Client-Sign` 命中 → 断点逐步步入 → 看到 MD5/SHA1/SHA384 五段哈希拼接。

## 4. 第四步：纯算的逻辑与操作步骤

### 4.1 什么是"纯算"

纯算（纯算法复刻）= **不用 execjs/node 跑原版 JS，而是彻底读懂算法后，用 Python 自己的库重新实现一遍**。

本目录已有大量纯算实践：建设库（20 号脚本纯 Python）、惠农网 H5（纯 Python 交付）、精灵数据/扇贝/招标网/企名片/新东方（全部完成 Python 复刻 + 离线验证）。

### 4.2 纯算为什么可行（逻辑原理）

1. **前端加密 99% 是"公开算法库 + 一组参数"**：AES、DES、MD5、SHA、RSA 都是公开标准，JS 里 `CryptoJS.AES.encrypt(明文, key)` 与 Python `AES.new(key,...).encrypt()` 的结果**天然一致**（都遵循同一标准）；
2. **前端不可能自创加密算法**：服务端要能解，两端必须同标准——算法族是确定的，要还原的只是"参数"；
3. 所以 **纯算 = 识别算法族 + 还原参数（key/iv/模式/填充/拼接规则/编码链）+ Python 调同名库**。

### 4.3 纯算六步操作法

**第 1 步 · 断点处收集证据**（在第 3 章定位到的加密函数里全部记下来）：
- key、iv、salt、secret 的实际值（字符串/WordArray/hex）
- 模式（CBC/ECB）、填充（ZeroPadding/Pkcs7）
- 参与运算的字段清单和拼接顺序（如 `k1=v1&k2=v2&`）
- 动态字段：时间戳、nonce、随机数怎么生成
- 编码链：明文→(JSON序列化)→(UTF-8)→(补齐填充)→(加密)→(base64)，每一步都记

**第 2 步 · 识别算法族（特征对照表）**：

| JS 里看到 | 算法 | 案例 |
| :--- | :--- | :--- |
| `CryptoJS.AES`，key/iv 为 16/24/32 字节 | AES | maomaozu、招标网、精灵数据 |
| key 长度 16/24，`DES`/`3des` 字样 | 3DES | 企名片 |
| `CryptoJS.MD5`，32 位 hex 输出 | MD5 | 建设库、新东方 |
| `SHA1` / `SHA384`，40/96 位 hex | SHA 系 | 惠农网 |
| `JSEncrypt`、`setPublicKey`、`010001` | RSA | 贝壳找房 |
| 32 符号表 `A-Z2-7` + 摇号逻辑 | 自定义编码 | 扇贝 |
| 常量 `1812433253` | MT19937 伪随机 | 扇贝 |

**第 3 步 · 把数据流写成一条流水线**：
例（maomaozu 请求加密）：`dict → JSON字符串 → UTF-8 bytes → PKCS7 填充 → AES-CBC 加密 → base64 字符串 → 放入 body`。
写成一行，Python 就照着这一行 + 第 4 步的对照表写。

**第 4 步 · Python 对应实现（JS ↔ Python 对照表）**：

| 环节 | JS 写法 | Python 写法 |
| :--- | :--- | :--- |
| AES | `CryptoJS.AES.encrypt(data, key, {iv,mode,padding})` | `AES.new(key, AES.MODE_CBC, iv).encrypt(pad(data, 16))` |
| MD5 | `CryptoJS.MD5(s).toString()` | `hashlib.md5(s.encode()).hexdigest()` |
| SHA1 | `CryptoJS.SHA1(s).toString()` | `hashlib.sha1(s.encode()).hexdigest()` |
| SHA384 | `CryptoJS.SHA384(s).toString()` | `hashlib.sha384(s.encode()).hexdigest()` |
| RSA 加密 | `JSEncrypt.encrypt(s)` | `pub.encrypt(s, padding.PKCS1v15())` + base64 |
| 3DES | 自定义 DES 内核调用 | `DES3.new(key24, DES3.MODE_ECB)` |
| base64 | `btoa` / `Base64.encode` | `base64.b64encode` |
| 大数 hex→十进 | `long.js fromString` + `toString(10)` | `str(int(hex_str, 16))` |

**第 5 步 · 离线复算验证**：拿第 1 步记下的**同一份输入**（固定样本）在 Python 里算，输出与断点处/抓包的**同一份输出**逐字符对比。不一致 → 回头核对第 1 步记录（一般是某个参数或顺序错了）。

**第 6 步 · Node + Python 双路线对照（本目录验证规范）**：Node 跑原版 JS 得结果 A，Python 纯算得结果 B，A == B 且与抓包样本一致，三条对齐才算结论可靠（参考各案例笔记"离线验证"章节）。

### 4.4 纯算七大坑（全部来自本目录案例教训）

| # | 坑 | 表现 | 正确做法 | 案例 |
| :-: | :--- | :--- | :--- | :--- |
| 1 | ZeroPadding 忘了去 | `json.loads` 报错 | 解密后 `rstrip("\x00")` | 招标网 |
| 2 | 填充方式混用 | 解密尾部多几个字节 | 照抄 JS 的 padding 配置 | 企名片 |
| 3 | ECB 却带着 iv | 分析半天 iv 没有用 | **以实测为准**：ECB 下 iv 是摆设 | 精灵数据 |
| 4 | WordArray 密钥 | key 是 `{words:[..], sigBytes:16}` | 大端展开：`struct.pack('>4I', *words)` | 精灵数据、招标网 |
| 5 | JS 位运算语义 | PRNG 复刻全错甚至死循环 | 按 uint32 复刻：`& 0xFFFFFFFF`；`-1` 位取反是"全 1"技巧 | 扇贝 |
| 6 | 大数精度 | JS 里 `parseInt` 结果对不上 | JS 用 long.js 的，Python 直接 `int()` | 惠农网 |
| 7 | 拼接细节 | 签名总是不一致 | 排序、空值过滤、拼接顺序、`substring` 左闭右开全部照抄 | 建设库、惠农网 |
| 8 | 编码链错位 | 能解开但乱码 | UTF-8 / URL 编码每步与 JS 对齐 | 全案例 |

### 4.5 纯算 vs execjs（什么时候别硬算）

- 算法是"整段库内核"（如 3DES 魔数表、复杂 RSA 实现）→ **先 execjs 跑通，别硬啃位运算**；
- 纯算适合：标准算法（AES/DES/MD5/SHA/RSA）+ 参数明确 + 逻辑清晰；
- 推荐路线：**execjs 快速打通拿结论 → 有时间再纯算 → 纯算与 Node 双验证**。
