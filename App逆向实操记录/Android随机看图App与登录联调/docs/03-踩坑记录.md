# 踩坑记录

按遇到顺序排列，每条都给出“现象 → 原因 → 处理 → 教训”。

## 1. AGP 拒绝中文工程路径

**现象**：`assembleDebug` 直接失败：

```
Your project path contains non-ASCII characters.
```

**原因**：AGP 8.x 默认禁止非 ASCII 路径，避免 Windows 下 aapt/资源打包出现编码问题。

**处理**：在 `gradle.properties` 增加：

```properties
android.overridePathCheck=true
```

构建随即通过。

**教训**：中文目录不是不能做安卓工程，而是要在 AGP 层显式放行；但下游工具（aapt、部分脚本）仍可能不认，能换 ASCII 路径就换。

## 2. aapt 读不了中文路径下的 APK

**现象**：

```
ziparchive W ... Unable to open '...apk': Illegal byte sequence
ERROR: dump failed because no AndroidManifest.xml found
```

**原因**：build-tools 30.0.3 的 aapt 用本地编码处理路径，遇到中文直接报 `Illegal byte sequence`。

**处理**：把 APK 复制到 `C:\Users\Administrator\AppData\Local\Temp\sjh_apk\final.apk` 再 dump，元信息全部正常。

**教训**：Gradle 能构建不代表所有 SDK 工具都能处理中文路径；做元信息检查时先复制到 ASCII 目录。

## 3. ImageGen 额度不足

**现象**：生成图标返回 `code 112`（insufficient quota）。

**处理**：改用 PIL 程序化绘制：渐变背景、圆角遮罩、高斯阴影、旋转拍立得、心形与星芒多边形。迭代三轮：

1. 第一版有和纸胶带装饰，缩小到桌面尺寸后显得脏，去掉；
2. 爱心压在相框上，缩小后看不清，移到相框外右下；
3. 白底贴纸在桌面上偏弱，改为“透明 motif 前景 + 渐变背景”的自适应图标，图标变饱满。

**教训**：AI 生图适合一次性视觉稿，程序化绘制适合需要多密度、可复现、无版权风险的图标；两者可以互相兜底。

## 4. Flask 在中文 Windows 上启动即崩

**现象**：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc9 in position ...
```

栈底是 `socket.getfqdn()`。

**原因**：werkzeug 启动时调用 `socket.getfqdn`，中文主机名被按 GBK 返回，再按 UTF-8 解码就炸。

**处理**：在 `import` 之后、`app.run` 之前替换：

```python
_raw_getfqdn = socket.getfqdn

def _safe_getfqdn(name=""):
    try:
        return _raw_getfqdn(name)
    except Exception:
        return "localhost"

socket.getfqdn = _safe_getfqdn
```

**教训**：Windows 中文环境下的“服务起不来”，先看主机名相关的编码异常，不要一上来怀疑端口占用。

## 5. PowerShell 改文件导致中文全变乱码

**现象**：用

```powershell
(Get-Content app.py) -replace "host='127.0.0.1'", "host='0.0.0.0'" | Set-Content -Encoding UTF8 app.py
```

改一行 host，结果文件里所有中文变成“鐧诲綍…”这类双重编码字符。

**原因**：`Get-Content` 按 ANSI/GBK 读出 UTF-8 字节，再以 UTF-8 写回，等于把中文重新编码了一遍。

**处理**：用编辑器/写入工具整文件重写，恢复中文；后续改 UTF-8 中文文件一律不走 `Set-Content`。

**教训**：批量文本替换前先确认读取编码；PowerShell 5 的 `-Encoding UTF8` 还会写 BOM，跨工具使用时容易再出问题。

## 6. Invoke-RestMethod 显示 JSON 乱码

**现象**：Flask 返回 `登录成功`，PowerShell 控制台显示 `ç™»å½•æˆåŠŸ`。

**原因**：`Invoke-RestMethod` 在响应头没有明确 charset 时按 ISO-8859-1 解码 UTF-8 字节。服务端 `jsonify` 默认 `application/json`，不带 charset。

**处理**：curl 或 Python 客户端验证；确认服务端返回结构正确（code 100 + token），乱码只是客户端显示问题。

**教训**：先用 `curl.exe` 或 Python 复核，再判断是不是服务端 bug，避免改错地方。

## 7. 真机 nc 发 POST 到不了 Flask

**现象**：`adb reverse tcp:8080 tcp:8080` 已建立，手机 Chrome 访问 `127.0.0.1:8080/ping` 能在 Flask 日志留下 200；但用 toybox `nc` 发 POST，服务端始终没有记录。

**尝试**：`nc -w`、`-q`、`-W`、文件重定向、shell 脚本、HTTP/1.0、手动 `\r\n`，全部失败；换 App 的 `HttpURLConnection` 一次成功。

**原因**：toybox `nc` 的 stdin 关闭/半关闭行为与 HTTP 服务端等待 body 的方式不匹配，请求没有完整发出。

**教训**：连通性验证和协议验证要分开。先用 GET 证明通道通，再用真正的 HTTP 客户端发 POST；不要拿 `nc` 当调试 HTTP 的默认工具。

## 8. adb 点击坐标差 10px 没命中

**现象**：点“加载网络图片”后毫无反应，logcat 没有 `load photo start`。

**原因**：按钮实际 bounds 是 `[63,1102][1017,1239]`，点击用了 `y=1092`，落在按钮上沿外 10px。之前的登录按钮恰好点在范围内，所以没暴露。

**处理**：`uiautomator dump` 拿真实 bounds，改点 `(540, 1170)`，一次命中。

**教训**：肉眼估坐标不可靠，尤其是按钮密集的页面；点击前先 dump UI，用 bounds 的中心点。

## 9. Button 文字被强制大写

**现象**：`加载网络图片（Flask /photo）` 显示成 `加载网络图片（FLASK /PHOTO）`。

**原因**：Material/AppCompat 的 Button 默认 `textAllCaps=true`，会把拉丁字母转大写。

**处理**：三个按钮统一加 `android:textAllCaps="false"`。

**教训**：中文按钮里夹英文/品牌名时，先关掉 allCaps，否则截图和设计稿对不上。

## 10. 3:4 卡片把提示文字挤出屏幕

**现象**：第一版布局里，卡片高度按 3:4 撑满，底部提示文字被按钮盖住，心形图标贴在屏幕最左边。

**原因**：`ConstraintLayout` 里卡片用 `layout_constraintDimensionRatio="3:4"` + 左右撑满，在 411dp 宽的机器上高度约 473dp，加上标题和按钮超过一屏；按钮用 `match_parent` 又让 drawableStart 贴边。

**处理**：

- 卡片左右 margin 加到 24dp，高度随宽度收敛；
- 标题 30sp → 28sp；
- 按钮改 `wrap_content` + `minWidth 220dp` + 水平 padding 34dp，居中显示；
- 提示文字与按钮之间留 14dp。

**教训**：按比例撑满的卡片必须先算目标机型的高度预算；`wrap_content` 的胶囊按钮比 `match_parent` 更不容易贴边。

## 11. 图标前景太大导致桌面被裁

**现象**：第一版自适应图标在桌面上只看到相框一角。

**原因**：自适应图标的安全区只有中间 66dp（108dp 画布），前景按满画布绘制会被裁掉四周。

**处理**：`make_icon.py` 导出前景时先按内容 bbox 裁剪，再等比缩放到 760px（约 74%），四周留透明边距。

**教训**：自适应图标要按“前景 108dp、安全区 66dp”设计，不能把普通图标直接塞进前景层。
