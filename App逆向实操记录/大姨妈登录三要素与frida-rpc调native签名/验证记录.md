## 二、三要素实测数据

### 1. device

hook `PeriodAPIV2.setDeviceCode` + `MessageDigest.update` 拿到的 sha1 明文：

```
null437474656aa92b44walleyegooglearm64-v8awalleyeRP1A.201005.004.A1abfarm873RP1A.201005.004.A1GooglePixel 2walleyerelease-keysuserandroid-buildEE:FA:A8:03:A9:1002:00:00:00:00:00
```

本地 `hashlib.sha1` 复算：

```
885105cf0494dd2301b70faf94b0b39d41540e55
```

与 app 的 `getDeviceCode()` 返回值完全一致（evidence\02_device_sha1_check.txt）。

### 2. password

hook `AESUtil.encrypt(str, key, iv)` 抓到的入参：

```
明文=123456  key=9eb091a1fb36369d  iv=yoloho_dayima!%_  密文=vz80nR0HLbmsZ4xP6TX30g==
```

本地 AES-128-CBC/PKCS5 复算 `md5("189****5221")[:16] = 9eb091a1fb36369d`，
密文一致；课件里另一密码 `lqz*****` 对应密文 `WA89qByLlDeaGjmVNzXm/w==`，与课件记录相同。

### 3. sign

hook `Crypt.encrypt_data`（native）抓到登录请求的入参：

```
j2=0
明文=885105cf0494dd2301b70faf94b0b39d41540e55user/login189****5221vz80nR0HLbmsZ4xP6TX30g==
长度=85
结果=8386dcb48abaef8a9cc376991de1a951
```

另外抓到一条一键登录的签名样例（拼接规则相同）：

```
明文=885105cf0494dd2301b70faf94b0b39d41540e55dayima.oneclick.oauth.android1793013417119885105cf0494dd2301b70faf94b0b39d41540e55
长度=122 结果=895fca786eea61296cccf9aabe0928ef
```

用 `02_rpc_sign.py` 对同一明文重复调用，返回值稳定为
`5bcd65ecd0bc26785ccbbdac1d06051f`（换密码后的明文），说明 native 签名是纯函数，
PC 侧无需逆向 so。

## 三、服务端真实响应

`POST https://uicapi.yoloho.com/user/login`（query 带 device/ver/机型参数，body 带
username/password/sign/androidid/mac/density/brand）：

```
HTTP 200
{"errorLimie":1,"errno":"1","errdesc":"账号或密码输错太多次了，试试找回密码吧～","timestamp":1793023267}
```

半小时后再试：

```
HTTP 200
{"errorLimie":0,"errno":"1","errdesc":"账号或密码错误太多次啦，请半小时后再试噢~","timestamp":1793023310}
```

等待 34 分钟后（22:21）：

```
HTTP 200
{"errorLimie":0,"errno":"1","errdesc":"失败太多次啦，请半小时后再试噢~","timestamp":1793024503}
```

再等 31 分钟（22:52，限流已解除）：

```
HTTP 200
{"errorLimie":0,"errno":"1","errdesc":"账号或密码错误啦~","timestamp":1793026356}
```

这一条说明请求已经过了签名这一关，进到账号密码比对：课件里的测试号
`189****5221` 用课件文档里的 `lqz*****` 也登不进去（账号可能已改密或已失效）。

原始输出见 `evidence\03_replay_login_response.txt`。

## 四、结论

- `device`：sha1 公式完全还原，本地复算 = app 结果。
- `password`：AES 参数（key 来源、iv 固定值）完全还原，本地复算 = app 结果。
- `sign`：native 算法未逆，用 frida-rpc 黑箱调用 app 自身方法得到，可稳定复现。
- 三要素拼出的请求**通过了服务端签名校验**：服务端返回的都是账号维度的业务错误
  （试错次数限制、账号或密码错误），不是签名错误，说明 device/sign 被服务端接受。
- **最终「登录成功拿 token」没有拿到**：课件测试号用文档里的两个密码（`123456`、`lqz*****`）
  都返回账号或密码错误，账号可能已改密或失效；为避免把账号试到再次限流，没有继续猜密码。
  如实记录，不伪造成功结果。

## 五、失败与限制

1. **登录页禁截屏**：`FLAG_SECURE`，`screencap` 出来 0 字节，只能 `uiautomator dump` 留证（evidence\04_login_page.xml）。
2. **okhttp3 hook 无效**：app 用的是 Android 平台内置 `HttpURLConnection`（`com.android.okhttp.*`），
   挂 `okhttp3.internal.http.RealInterceptorChain` 一条请求都抓不到，改挂 `java.net.URL` 才有输出。
3. **更新弹窗只能用断网启动绕过**：返回键、点外部、`WindowManagerGlobal.removeView` 均无效。
4. **账号被限流**：连续用预填密码 123456 试错触发服务端风控，半小时窗口内再试会重置/延长限制；
   22:52 限流解除后用课件密码 `lqz*****` 依然返回账号或密码错误，说明课件测试号已不可用。
5. 登录页每次失败后「我已阅读并同意」会复位，脚本点「确定」前必须先点 `ivCheck`，
   否则只有吐司、不会发请求。
