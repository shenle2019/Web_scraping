## 四、jadx 反编译验证

```
jadx -d jadx_out app-debug.apk -> 16 个业务类全部反编译成功
```

关键命中：

```java
// com.shenjiahang.netapp.net.Signer
public static String bodySign(String user, String rawPwd, String t1) {
    return Md5Utils.md5(t1 + user + Md5Utils.md5(rawPwd));
}
public static String headerSign(String ctime) {
    return Md5Utils.md5(ctime + NetConfig.SALT);
}
```

```java
// com.shenjiahang.netapp.net.SignInterceptor
Request.Builder builder = origin.newBuilder()
    .header("ctime", ctime)
    .header("hsign", Signer.headerSign(ctime))
    .header("X-Client", "netapp/1.0 (okhttp)");
if (!TextUtils.isEmpty(token)) builder.header("Authorization", "Bearer " + token);
```

```java
// com.shenjiahang.netapp.net.NetConfig
public static final String BASE_URL = "http://192.168.31.220:8080/";
public static final String SALT = "SJH_2026_APP";
```

逆向结论：签名算法、盐值、拦截器注入点全部可从 APK 静态还原；`SALT` 硬编码是可被直接利用的反模式。

### 6.3 抓包环境冲突排查（真实踩坑）

现象：mitmproxy 在 8890 监听正常、PC 本机 `curl -x` 可通过，但手机与 App 的请求始终不进 `capture.log`；同时 `settings get global http_proxy` 反复从 8890 变回 8888。

定位过程：
1. `Get-NetTCPConnection -LocalPort 8890` 确认监听正常，`mitm.err` 无报错；
2. PC 本机 `curl -x http://127.0.0.1:8890` 返回 400（Flask 缺签名的正常拒绝），说明 mitmproxy 本身工作；
3. 手机 `toybox nc 192.168.31.220 8888` 有响应、8890 无响应；
4. 杀掉 Charles 后发现代理又被改回 8888；
5. `Get-ScheduledTask` 命中计划任务 `AutoCapture-CharlesProxy`，动作是
   `powershell -File "e:\路飞学城\课件\APP逆向(12期)\工具-自动抓包\auto_capture.ps1" -Watch`，
   脚本每 10 秒把手机全局代理设为 `电脑IP:8888`，并在 Charles 不在时自动拉起 Charles。

处理：`Disable-ScheduledTask AutoCapture-CharlesProxy` -> 抓包 -> `Enable-ScheduledTask` 恢复。恢复后计划任务状态 `Ready`，课件工具链保持可用。
