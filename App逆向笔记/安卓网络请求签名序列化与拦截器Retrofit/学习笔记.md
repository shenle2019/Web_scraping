## 一、登录案例：从裸请求开始

### 1.1 布局

- 外层 `LinearLayout` 撑满，内层灰底卡片（`#dddddd`、`layout_marginTop="150dp"`、高 250dp）。
- 标题 `TextView`：`textAlignment="center"`、25dp。
- 两行 `TextView + EditText`：用户名 `@+id/txt_user`，密码 `@+id/txt_pwd`（`inputType="textPassword"`）。
- 两个 `Button`：`@+id/btn_login`、`@+id/btn_reset`。
- 逆向视角：布局本身不重要，但 **id 名是 jadx 里的定位锚点**——`R.id.txt_user` 编译成 `2131230xxx` 这类数字后读起来费劲，读代码时靠"控件类型 + 调用链"（`EditText.getText()` 之后流向哪）比靠 id 数字靠谱。

### 1.2 OkHttp 发请求的五步

`new OkHttpClient.Builder().build()` → `new FormBody.Builder().add(k,v).build()` → `new Request.Builder().url(...).post(form).build()` → `client.newCall(req)` → `call.execute().body().string()`。

- `FormBody` 就是表单编码，等价于 python 的 `data={}`；发 json 要换 `RequestBody` + `MediaType`。
- `body().string()` 只能调一次，读完流就关；转出来的就是 json 字符串，后面交给 Gson。
- 整段必须包在 `try/catch (IOException)` 里，且在子线程中执行。

### 1.3 三处配置（少一处就发不出去）

| 位置 | 加什么 | 作用 |
|---|---|---|
| `app/build.gradle` | `implementation "com.squareup.okhttp3:okhttp:4.9.1"` | 引入库，等价 `pip install requests` |
| `AndroidManifest.xml` | `<uses-permission android:name="android.permission.INTERNET"/>` | 允许联网 |
| `res/xml/security.xml` + `<application>` 上挂 `android:networkSecurityConfig="@xml/security"` | `<base-config cleartextTrafficPermitted="true"/>` | 放行明文 http（Android 9 起默认禁） |

只建 `security.xml` 不引用是无效的——基础 md 第 3 步只写"在 AndroidManifest.xml 加入"，漏掉了属性名。

### 1.4 Flask 端

- `@app.route('/login', methods=['POST'])` + `request.form.get(...)` + `jsonify({...})`，给 App 的接口只返 JSON，不返页面。
- 登录成功发 `str(uuid.uuid4())` 当 token，失败给业务码。
- `app.run(host='0.0.0.0', port=8080)`：只有绑定 `0.0.0.0`，同局域网的手机才能用电脑 IP 访问；写 `127.0.0.1` 手机连不上。
- URL 里的 `192.168.1.12` / `192.168.71.100` 是讲课时的电脑 IP，自己跑要换成 `ipconfig` 查到的地址。

### 1.5 线程规约

- 请求放 `new Thread(){ run(){...} }.start()`；所有改 UI 的动作回 `runOnUiThread(new Runnable(){...})`，课堂版统一封了个 `showToast(String)`。
- 基础 md 有个混写：先 `Toast t = Toast.makeText(...)`，再在子线程里 `t.show()`。Toast 内部会 post 到主线程队列，多数机型不崩，但改 View 就会抛异常，自己写别学这个。

**坑：两端字段名。** 基础 md 1.2 发的是 `user` / `pwd`，1.4 的 Flask 读的却是 `username` / `password`，照抄永远走"用户名或密码错误"。课堂版两端统一成 `user` / `pwd`——day09 那个坑在这版修掉了。

## 二、请求加密：密码 + sign + 时间戳

### 2.1 客户端四套写法（课件的演进顺序）

| 版本 | 请求体 | header | 签名口径 |
|---|---|---|---|
| v1 裸请求 | `user` / `pwd` 明文 | 无 | 无 |
| v2（基础 md 前段） | `user` / `pwd` / `sign` | `ctime`（秒级） | `md5(username + "justin")` |
| v3（基础 md 后段，配拦截器） | `username` / `password` / `sign` / `t1` | 无 | `md5(t1 + username)` |
| v4（课堂版） | `user` / `pwd`(已 md5) / `sign` | 无 | `md5(user + md5(password))` |

加盐串 `"justin"`、时间戳拼在签名的前面还是后面，就是"只有自己公司知道"的那部分——正是逆向要还原的东西。字段名也在变（`user` vs `username`），抄代码前先确认是哪一版。

### 2.2 Md5 工具类

- `MessageDigest.getInstance("MD5")` → `digest(s.getBytes())` → 逐字节 `& 255` 再 `Integer.toHexString`。
- 关键一步：`val < 16` 时补一个 `"0"`。Java 没有 `hexdigest`，漏了这步会得到 31 位甚至更短的串，和标准的 32 位对不上，联调时极难发现。
- 两种形态：基础 md 写成实例方法（`new Utils().md5(...)`），工程里改成了 `public static`（`Utils.md5(...)`）。hook 时挂的类相同，但静态/实例在 `overload` 和 `this` 处理上不同。

### 2.3 后端三套校验口径

| 源码位置 | sign 校验 | 附加校验 | 失败码 |
|---|---|---|---|
| 基础 md 2.2 前半 | `sign == md5(username + 'justin')` | `@app.before_request` 读 header `ctime`，`time.time()-ctime > 1000` 直接挡 | 888 超时 / 105 签名错 |
| 基础 md 2.2 后半 | `sign == md5(t1 + username)`（t1 从表单取） | 无 | 102 签名错 |
| 课堂 2.2 | `sign == md5(user + pwd)`（pwd 本身已是 md5） | 无 | 102 签名错 |

三道防线分工写得很清楚：**sign 挡"参数被篡改"，时间戳挡"请求被重放"**。两者都不校验请求来源，所以拿到算法就能伪造——这就是逆向的意义。

顺带解释三个随处可见的密码常量：`202cb962ac59075b964b07152d234b70` 是 `md5('123')`，`53dd9c6005f3cdfc5a69c5c07388016d` 是 `md5('justin')`，`get_md5('123456')` 则是课堂版的口令。同一个课件里并列三套，抄的时候要认准配哪套后端。

### 2.4 从抓包反推口径（最值得复用的一节）

基础 md 2.3 的 Charles 截图里，`POST /login` 的表单是：

`username=justin`、`password=53dd9c6005f3cdfc5a69c5c07388016d`、`sign=0c879ea002d66d33efc9ea6e486d7554`、`t1=1712758013`，返回 `{"code":100,"msg":"\u767b\u5f55\u6210\u529f","token":"26af4c3d-…"}`。

推法（这三个常量对得上）：

- `md5('justin')` = `53dd9c60…` → 那次输入的密码本身就是 `justin`，不是常见的弱口令，所以别看到一个 32 位串就默认是 `md5('123456')`；
- `md5('1712758013justin')` = `0c879ea0…` → 这台 demo 用的是 **v3 口径**：sign = 时间戳在前 + 用户名，t1 同时放在请求体里；
- 密码字段只有 32 位 hex 而 `sign` 也是 32 位 hex，说明密码在客户端就先 md5 了，后端拿到的永远不是明文。

方法总结：**抓到一个完整样本，把候选口径各算一遍，谁能对上就是谁**。比盲读反编译代码快得多，也是后面所有加签类 App 的第一招。

### 2.5 回放与三个坑

- `requests.post(url, data={...})` 对应 `request.form`；对端收 json 时要用 `json=`，别混。
- 坑一：带 `ctime` 校验（基础 md 2.2 前半）的后端，时间窗 1000 秒，回放必须现算时间戳，写死样本会返 888。
- 坑二：基础 md 2.3 的回放脚本把 `t1` 写成 `int(time.time())`、`sign` 写成固定串——它对面是 `md5(username+'justin')` 那套后端，t1 根本没进签名。要是拿这份脚本去请求 `md5(t1+username)` 的后端，必然 102。
- 坑三：三套后端字段名（`username` vs `user`）、签名口径全不同，回放脚本必须和后端版本成套使用，不能混拼。

## 三、序列化与反序列化（Gson）

### 3.1 概念与三方对照

- 对象 → 字符串 = 序列化；字符串 → 对象 = 反序列化。http 通信用的是字符串，所以两端都要转。
- python：`json.dumps` / `json.loads`；js：`JSON.stringify` / `JSON.parse`；java：`fastjson`（阿里开源，出过漏洞，已弃用）、内置 Serializable（不用于 http 通信）、**Gson**（Google 开源，安卓主流）。

### 3.2 四步用法

依赖 `implementation 'com.google.code.gson:gson:2.8.6'` → 建实体类 → `new Gson().toJson(obj)` 序列化 → `new Gson().fromJson(str, X.class)` 反序列化。

### 3.3 实体类怎么写

- 字段 `public`，名字与 json key 逐字一致（Gson 默认按字段名匹配，不认 getter/setter）。
- 反序列化走反射直接塞字段，所以构造方法不是硬要求；课件留了构造方法并注"给序列化用"，属于习惯（`toJson` 需要一个已存在的对象，得能先 new 出来）。
- 嵌套结构逐层建类：`Films` 里 `public ArrayList<FilmsReal> films;`，`FilmsReal` 里才是 `name` / `poster` / `synopsis`。集合元素的类名随便起，字段名必须对。
- 成功/失败结构不一致时（成功多一个 `token`）：抽 `CommonResponse`（`code` / `msg`）当父类，`LoginResponse extends CommonResponse` 只加 `token`。缺的字段 Gson 自动给默认值（对象 `null`、int `0`），不会报错。
- **坑**：结构对不上会抛 `JsonSyntaxException`，它是 RuntimeException，`catch (IOException)` 接不住，App 会直接崩。字段类型也要一致（后端给 `"code":"100"` 字符串、实体写 `int`，同样会炸）。

### 3.4 判断登录成功

`obj.code == 100` → 弹 `obj.msg` 并跳转；否则只弹 `obj.msg`。100/101/102/888 全是后端自定义的业务码，和 http 状态码（200/500）无关——Charles 里那个 500 是服务端异常，别和 101 混。

## 四、页面跳转与电影列表页

### 4.1 Intent 跳转

`new Intent(MainActivity.this, IndexActivity.class)` + `startActivity(intent)`。新建 Activity 必须在 `AndroidManifest.xml` 注册（AS 用向导建类会自动加 `<activity android:name=".IndexActivity" android:exported="false"/>`），漏注册就是 `ActivityNotFoundException`。

### 4.2 ListView + BaseAdapter

- 布局：`activity_index.xml` 里只放一个 `ListView`（`@+id/mylist`），每行的样式单独放 `layout/list_item.xml`（`ImageView` + 竖排两个 `TextView`）。
- 适配器四件套：`getCount`（列表长度）、`getItem` / `getItemId`（课件直接返回 null / 0，无所谓）、`getView`（造一行）。
- `getView` 里 `LayoutInflater.from(ctx).inflate(R.layout.list_item, parent, false)`，第三个参数 `false` 表示先不挂到父容器上，交给 ListView 自己挂；再 `findViewById` 取三个控件塞值。
- 图片用 Glide：`Glide.with(ctx).load(poster).placeholder(R.mipmap.ic_launcher).into(img)`——主线程发起、内部线程池加载、自带缓存和占位图。day09 那个 `BitmapFactory.decodeStream(url.openStream())` 是最原始写法，这里才算工程做法。
- **坑**：每次 `getView` 都重新 inflate，没有复用 `convertView`，也没用 ViewHolder，列表一长就卡。课件为讲解简化了，真项目要补。
- **坑**：`setAdapter` 必须在 UI 线程，包在 `runOnUiThread` 里；`obj` 是外层匿名 `Runnable` 里的局部变量，内层再引用靠的是 Java 8 的 effectively final（老语法要显式 `final`）。
- **坑：id 对不上**。基础 md 的 `activity_index.xml` 写 `@+id/mylist`，同一份文档另一段代码 `findViewById(R.id.listview)`，抄混了就是空指针；工程里统一是 `mylist`。

### 4.3 数据接口

`GET /films` 直接读 `films.json`（20KB、10 部电影）`jsonify` 出去，字段 `name` / `poster` / `synopsis` 与 `FilmsReal` 一一对上。列表页是"登录成功的产物"——跳转发生在 `code==100` 分支里，所以电影接口本身不做鉴权，这点和真实 App 不一样。

## 五、SharedPreferences：token 落到 xml

- 落盘位置：`/data/data/<包名>/shared_prefs/sp_token.xml`。`adb shell` → `su` → `cd /data/data/<包名>/shared_prefs` → `cat sp_token.xml` 直接看。
- 写：`getSharedPreferences("sp_token", MODE_PRIVATE).edit().putString(k, v)` → `commit()`。
- 删：`editor.remove(k)`；读：`sp.getString("token", "")`（第二个参数是默认值）。
- `commit()` 同步写并返回 boolean，`apply()` 异步写不返回；课件用 `commit()`。
- 逆向价值：**登录后的 token、设备 id、各种风控开关，常落在这堆 xml 里**。有 root 直接 cat，比 hook 省事。注意这些值一般只在"刚启动 / 刚登录"时写入，过期了得重新登一次再读。

## 六、拦截器（Interceptor）

### 6.1 动机

每个请求都要带 `ctime` / `sign`，写在业务代码里既重复又容易漏。塞进拦截器，配置一次全局生效——这是安卓 App 加签最常见的落点。

### 6.2 两种写法和调用链

- 实现类：`public class CommonInterceptor implements Interceptor`，重写 `intercept(Chain chain)`。
- 匿名：`new Interceptor(){ intercept(...) }` 直接塞给 builder。
- 链式三步：`chain.request().newBuilder().addHeader(k, v).build()` → `chain.proceed(request)` → 把 `Response` 返回回去。**漏掉 `chain.proceed` 请求就发不出去**。
- 基础 md 的骨架里 `addHeader("ctime","")`、`addHeader("sign","")` 是空串占位，属于伪代码，照抄等于没加签。

### 6.3 挂载与全局复用

`new OkHttpClient.Builder().addInterceptor(interceptor).build()`。工程习惯再抽一层：`Common` 类里 `public static Interceptor interceptor = new CommonInterceptor();`，各处直接 `addInterceptor(Common.interceptor)`，不必每次 new。

### 6.4 逆向怎么定位

- **静态**：全局搜 `Interceptor`。核心判断是——请求里某个参数在业务代码里找不到赋值处，多半就在拦截器里生成。
- **动态**：hook `okhttp3.OkHttpClient.Builder.addInterceptor`，打印拦截器对象、数执行次数就知道有几个。原理链条是 `new OkHttpClient.Builder()` → `addInterceptor(x)` → `build()`，所以 hook 点选 `Builder.addInterceptor`，不是 `OkHttpClient` 本身。
- 课件脚本两处要注意：`Java.user(...)` 是笔误，应为 `Java.use(...)`；`implementation` 里只 `console.log` 没有返回原方法的返回值，`addInterceptor` 返回 undefined 会让 `build()` 链断掉、App 崩——真跑要保留原逻辑再把结果 return（或先把原方法存下来再 `.call(this, ...)`）。
- 打印 Java 对象别用 `JSON.stringify`（拿到的是 `{}`），用 `getClass().getName()` 或 `toString()`。

## 七、Retrofit：注解式请求

### 7.1 定位

Retrofit 是对 OkHttp 的封装，底层还是 OkHttp，把"拼请求"变成"声明接口 + 调方法"。OkHttp 是手写 builder，Retrofit 是一行注解。

### 7.2 四步用法

依赖 `implementation "com.squareup.retrofit2:retrofit:2.9.0"` → 写接口 `HttpReq` → `new Retrofit.Builder().baseUrl("http://ip:8080/").build().create(HttpReq.class)` → `call.execute().body().string()`（同步，仍要在子线程）。

### 7.3 三个注解的语义

| 注解 | 效果 | 对应 OkHttp |
|---|---|---|
| `@POST` + `@FormUrlEncoded` + `@Field("name")` | 拼成 `name=xx&pwd=xx` 表单 | `FormBody.Builder().add(...)` |
| `@GET` + `@Query("age")` | 拼到 url 后 `?age=19` | url 自己拼字符串 |
| `@POST` + `@Body RequestBody` | 整个对象当 json 体 | `RequestBody.create(JSON, ...)` |

- `baseUrl` **必须以 `/` 结尾**，否则直接 `IllegalArgumentException`。
- 注解里路径带前导 `/`（`@POST("/login")`）是绝对路径，会覆盖 baseUrl 的 path 部分：`http://host/api/` + `@POST("/login")` 得到的是 `http://host/login`，不是 `/api/login`。

### 7.4 和拦截器的关系

`Retrofit.Builder().baseUrl(...).client(new OkHttpClient.Builder().addInterceptor(Common.interceptor).build())` 才能带上拦截器。**不显式 `.client()` 时 Retrofit 自己 new 一个默认 OkHttpClient，拦截器不生效**——逆向时看到 Retrofit 没配 client，就别去拦截器里找加签了，逻辑在别处（业务层或拦截器之外的 OkHttp 实例）。

### 7.5 逆向定位

- 搜 URL 路径，去掉域名和端口：`/login`、`/film`；课件给的实战例子是合伙人 App 搜 `/v1/partnerLogin/login`，一搜就落到接口声明。
- 顺着接口声明能一眼看清"要哪些参数、什么编码"（`@Field` 表单 / `@Query` url / `@Body` json），比在 `FormBody.Builder` 里翻更集中。
- 但注解里看不到 sign 怎么算——**Retrofit 只暴露"发什么"，不暴露"怎么签"**，签名还在拦截器或调用点。

## 八、闭环：逆向自己的 App

- 三步：Build APK → Charles 抓包 → jadx 打开 apk。
- 目的不是"逆向自己的代码"，而是建立对应关系：抓包里的每个参数 → 反编译代码里的哪一行 → 为什么会变成这样（多 dex、匿名类 `$1`、常量内联这些 day09 记过的产物）。
- 课堂截图里 Charles 列表同时有 `192.168.71.100:8080 /login` 和一堆 `connecttest.txt` 的 503——后者是手机系统的联网检测（mumu 模拟器、`ipv6.msftconnecttest.com` 等），和 App 无关，抓包时别被干扰。
- 顺带能验证一件事：抓包看到的字段名和顺序，和 `FormBody.Builder().add()` 的写法完全一致，这就是"从抓包反推代码"的物理依据。

## 十、关键知识清单

- 三处配置缺一不可：Module 级 `build.gradle` 加 okhttp、Manifest 加 `INTERNET`、`security.xml` + `<application>` 上挂 `networkSecurityConfig`。
- Flask 给 App 的接口只返 JSON；`0.0.0.0` 才能被局域网手机访问；URL 里的 IP 换成自己电脑的。
- 请求必须子线程、UI 必须回主线程（`runOnUiThread`）；Toast 混写多数能跑但别依赖。
- 加签四件套：密码先 md5、sign、时间戳、（可选）固定盐。口径至少三种：`md5(user+pwd)`、`md5(username+盐)`、`md5(t1+username)`，字段名和口径必须与后端成套。
- 后端 `ctime` 校验防重放（1000 秒窗口），sign 校验防篡改；都不校验来源，拿到算法就能伪造。
- 从抓包反推口径：抓一个完整样本，候选算法各算一遍，对上即命中。`53dd9c60…=md5('justin')`、`0c879ea0…=md5('1712758013justin')`、`202cb962…=md5('123')`。
- Gson：字段 `public` + 名字对齐 json key + 嵌套集合逐层建类；`toJson` / `fromJson`；结构或类型不符抛 `JsonSyntaxException`（RuntimeException，`catch IOException` 接不住）。
- 成功多字段、失败少字段的接口：父类装 `code`/`msg`，子类挂 `token`。
- 跳转 = `Intent` + `startActivity`，新 Activity 必须在 Manifest 注册。
- ListView = 布局里一个 ListView + `BaseAdapter` 四件套 + item 布局；Glide 加载网络图；`setAdapter` 回 UI 线程；课件没做 `convertView` 复用。
- SharedPreferences 落在 `/data/data/<包名>/shared_prefs/*.xml`，root 后直接 cat；token、设备 id、风控开关常在这，且只在刚启动/刚登录时写。
- 拦截器 = `implements Interceptor` + `chain.proceed()`，`addInterceptor` 挂到 Builder；全局加签的标准位置，参数在业务代码里找不到赋值就去这。
- 逆向定位拦截器：搜 `Interceptor` 关键字，或 hook `okhttp3.OkHttpClient.Builder.addInterceptor`。
- Retrofit = 注解接口 + `baseUrl`（必须以 `/` 结尾）+ `create()`；`@Field` 要配 `@FormUrlEncoded`、`@Query` 拼 url、`@Body` 发 json；定位搜 URL 路径（如 `/v1/partnerLogin/login`）。
- Retrofit 不显式 `.client(...)` 时用默认 OkHttpClient，拦截器不生效——这是判断"加签到底在不在拦截器"的一个依据。
- 逆向自己的 App = 编译 + 抓包 + jadx 对照，目的是建立"抓包参数 ↔ 反编译代码"的对应关系，而不是破解。
