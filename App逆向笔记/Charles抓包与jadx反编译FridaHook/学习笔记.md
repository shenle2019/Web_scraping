## 一、数据包抓取（Charles）

### 工具选型与安装
- 四款常见工具：Wireshark（开源、多协议分析）、Fiddler（HTTP/HTTPS 跨平台）、**Charles Proxy（课程主用：图形化界面、移动端抓包友好）**、Tcpdump（Linux 命令行）
- 安装：mac 用 `Charles_4.5.6_xclient.info.dmg`；win 用 `charles-proxy-4.5.6-win64.msi`；打开软件输入 sn 破解（课件提供三组 name/serial）
- 建议统一 4.5.6 版本：老师以此版本讲，其他版本按钮位置不同，自行解决

### 抓包原理（一句话）
- Charles 在电脑上开一个代理服务充当"中间人"：手机把请求发给 Charles，Charles 转发给服务器并记录往返数据——所以手机必须把代理指向电脑

### 抓 HTTP 包的前置条件与配置
- **手机和电脑必须在同一路由器**：电脑有线连接、手机无线连接，尽量同一网段（如手机 192.168.1.11 / 电脑 192.168.1.20）
- 关闭电脑防火墙
- 电脑端：Proxy → Proxy Settings 确认端口；Help → Local IP Address 查本机 IP（或 ipconfig / ifconfig）
- 多网卡注意：装了虚拟机有虚拟网卡，选与手机同网段的那个 IP
- 手机端（真机/模拟器相同）：设置 → WLAN → 连同一无线 → 长按/点齿轮 → 修改网络 → 手动代理 → 填电脑 IP + Charles 端口
- 案例：**爱学生 app** 登录包——POST json 至 `/app/v1/patriarchLogin/1`，username/password 为明文字段，可直接 requests 模拟登录

### Charles 常用操作（课堂补充）
- **改包重发**：选中请求改内容 → 点 Execute 重新发送。用途：破解字段前先删字段试发，能通说明该字段不重要、无需破解
- **屏蔽电脑自身的包**：Proxy → Windows Proxy 取消勾选（电脑+手机混抓时过滤麻烦）

### 抓 HTTPS 包（核心：装证书，安卓 7+ 需 root）
- https = http + ssl，需在手机安装 Charles 根证书，Charles 才能解密流量
- 版本分界线：
  - 安卓 7 以下（真机已少见）：装完证书直接可抓
  - **安卓 7 以上（当今主流）：证书默认进"用户证书"区，app 不信任 → 必须迁成"系统证书"→ 需 root + Magisk 刷 movecert 模块**
- 用户证书 vs 系统证书：用户证书=用户自行安装（个人身份验证/加密通信）；系统证书=系统或厂商预装的根证书（校验应用签名、SSL/TLS 通信）
- 操作流程：
  1. 手机配好代理后浏览器访问 `chls.pro/ssl` 下载证书（不配代理访问不了这个地址）
  2. 设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选中下载的证书安装
  3. 信任的凭据里能看到证书暂在"用户"分区（此时还抓不了 https）
  4. `movecert-1.9-4.zip` push 到 `/sdcard/Download/` → Magisk → 模块 → 从本地安装刷入 → 重启手机
  5. 重启后证书从用户级迁到系统级 → 可正常抓 https
- 模拟器（安卓 6.0.1）：版本低于 7，不 root、不迁移，装完证书即可
- 抓不到 https 的排查方向：证书没装好/没迁移；或 proxy → SSL Proxying Settings 相关设置不对（见课件图）
- 案例：**今日南川 app** 抓 https——登录接口 `api.cqliving.com/login.html`，参数带 `hashSign`、`pwd`（32 位 md5 形态），请求头带 `sign`、`t` 时间戳，已见签名反爬痕迹，属后续课程深入点

## 三、反编译后的代码定位（车智赢案例）

- 目标：抓包发现 `pwd` 是 32 位密文，反编译定位加密代码
- 检索套路：
  1. **按请求地址搜索**（登录地址唯一）：搜 `login/login.ashx` → 命中常量 `LOGIN_URL = "/tradercloud/sealed/login/login.ashx"`
  2. **按参数关键字搜索**：`pwd` / `"pwd"` / `put("pwd` 等多形式试探
  3. 在命中的变量上**右键 → 查找用例**（谁用了它），一路追到调用点：`param("pwd", SecurityUtil.encodeMD5(str3))`
  4. 对 `encodeMD5` **右键 → 跳转到声明**，读实现：标准 MD5（`MessageDigest.getInstance("MD5")`，逐字节转十六进制字符后 `toLowerCase`）
- 课件的结论：该加密即标准 MD5（32 位小写 hex），课件用 Python `hashlib` 对明文/密文做了对照
- 关键认知：定位靠"地址/参数关键字 + 查找用例"，但真正读懂代码需要 Java / 安卓开发功底——课程后续会补

## 四、Frida Hook 框架

### 概念
- Hook = 在运行时拦截并修改应用程序行为：劫持方法调用、改参数、篡改返回值，用于修改/增强/调试 app
- 常见框架：**Xposed**（开源模块化，改系统层，需重启）、**Frida**（跨平台动态 Hook，提供 JS API 运行时注入）——课程主用 Frida

### 安装（电脑端与手机端版本必须对应）
- 电脑端（先有 Python 环境）：
  - `pip install frida==16.0.1` + `pip install frida-tools==12.0.1`（或最新：frida 16.0.9 / frida-tools 12.1.2）
  - 装不上时按 **frida版本 + Python版本 + 操作系统** 下载对应 egg/whl 手动装（如 pypi.doubanio.com/simple/frida/）
- 手机端 frida-server：
  1. 查架构：`adb shell getprop ro.product.cpu.abi`（arm64-v8a）
  2. github.com/frida/frida/releases 下对应版本（如 frida-server-16.0.19-android-arm64）
  3. push 到手机：`adb push frida-server-... /data/local/tmp/`
  4. 赋权限：`adb shell` → `su` → `cd /data/local/tmp` → `chmod 755 frida-server-...`

### 启动与端口转发
- 手机端启动：`./frida-server-16.0.19-android-arm64`（前台运行）
- 启动报错的处理：方案一重启手机；方案二 `adb shell setenforce 0`（临时关 SELinux）
- 电脑端端口转发（不做则 Python 连不上设备）：
  ```
  adb forward tcp:27042 tcp:27042
  adb forward tcp:27043 tcp:27043
  ```
- 验证：Python 里 `frida.get_remote_device()` → `enumerate_processes()` 枚举全部进程、`get_frontmost_application()` 取前台 app

### Hook 案例：车智赢 encodeMD5
- 目标类：`com.autohome.ahkit.utils.SecurityUtil`（包名+类名来自反编译首行），包名 `com.che168.autotradercloud`
- Hook 脚本核心三件事：
  1. `Java.perform()` 包裹全部逻辑
  2. `Java.use("类名")` 拿到类对象
  3. 替换目标方法的 `implementation`——打印参数 → `this.方法名(参数)` 调原函数拿真实结果 → 打印返回值；**返回任意值即可篡改**（如直接返回假 token）
- 连接方式：`rdev.attach("车智赢+")`，按 app 进程名 attach

### 两种注入方式（场景区分）
| 方式 | 时机 | 适用场景 |
|---|---|---|
| **spawn** | app 启动时直接注入 | Hook 启动早期逻辑：初始化过程、全局/静态变量、需要自定义初始化 |
| **attach** | 连到已运行的 app | 运行时拦截特定方法、实时监视与修改行为（改参/篡改返回值）、调试分析 |

### Python Hook 与 JS Hook
- **Python 脚本方式**：
  - attach：先手动打开 app，再 `rdev.attach("车智赢+")` → create_script(js代码) → script.load()
  - spawn：`pid = rdev.spawn(["com.che168.autotradercloud"])` → attach(pid) → 加载脚本 → `rdev.resume(pid)` 放行（自动重启 app）
- **JS 脚本 + 终端方式**（hook.js 里只写 `Java.perform(...)` 部分）：
  - attach：`frida -UF -l hook.js`
  - spawn：`frida -U -f com.che168.autotradercloud -l hook.js`
  - 退出：输入 `q` + 回车

## 五、Python 侧算法还原基础（hook 之外的另一条路）

- 加密分类：
  1. 单向加密（不可逆）：MD5、SHA 系列
  2. 对称加密：AES、DES
  3. 非对称加密：RSA、DSA
  4. 补充算法：Base64（编码，非加密）
- **MD5 / SHA1**：`hashlib` 库，update + hexdigest
- **DES**：`pycryptodomex` 库（`Cryptodome.Cipher.DES`）——64 位分组、密钥 56 位、同一算法加密解密、ECB 模式、不足 8 字节需手动补位
- **RSA**：`rsa` 库——`newkeys(1024)` 生成公钥/私钥；公钥加密、私钥解密；私钥签名 `sign`、公钥验签 `verify`（内容对不上会抛异常）
- **Base64**：`b64encode` / `b64decode`

## 关键知识清单（速查）

- 抓包原理：Charles 当代理"中间人"，手机代理 → 电脑 IP + 端口；前置条件=同一路由器+关防火墙

- Charles 改包重发（Execute）= 删字段试探，判断字段是否重要

- jadx 用 1.4.7 日常 + 留 1.2.0 备用；路径不带中文；多版本共存
- Frida 两端版本必须对应；PC 侧先 `adb forward` 27042/27043
- spawn=启动早期注入（脚本自动重启 app，resume 放行）；attach=连运行中 app（`frida -UF -l`）
- Hook 脚本三板斧：Java.perform → Java.use 找类 → 替换 implementation（打参数、调原函数、改返回值）
- 32 位小写 md5 特征 → Python hashlib 对照确认
