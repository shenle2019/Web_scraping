## 一、类与对象

- **类**：实体对象的概念模型，笼统不具体（人类、动物类、鸟类），描述一组有相同属性和相同行为的对象的集合。
- **对象**：类具体化的实体（人类里的厨师、学生、老师），各有不同的姓名年龄，但都具备说话走路这些方法。

### 类定义语法模板

```java
[public] [abstract|final] class 类名 [extends 父类] [implements 接口] {
    属性类型 属性名;              // String name;
    public static void 方法名() { }  // 静态方法（类方法）
    public int add(int a, int b) { return a + b; }  // 成员方法
}
```

方括号可省，`|` 表示**两者互斥**——`abstract`（抽象类，不可实例化）与 `final`（不可被继承）不会同时出现。

课堂列出的合法组合：`public class`、`public abstract class`、`public final class`、`class`、`final class`、`class X extends Y implements Z`、`class X implements Z`。

### 属性的语法与组合

```java
[public|protected|private] [static] [final] <类型> <变量名>
```

Demo001 一个文件里把五种组合摆齐了：

| 写法 | 含义 |
|---|---|
| `public String name;` | 公开的对象属性 |
| `private int age;` | 私有属性，外部只能通过方法访问 |
| `public final int gender = 1;` | 常量，声明时必须赋值，之后永不可改 |
| `public static String school;` | 静态属性 → 属于**类**，类名调用 |
| `public static final int height = 180;` | 静态常量（全局常量） |

### 构造方法

与类同名、**没有返回值、不需要写 void**、可以有多个（即构造方法重载）。Demo003 用三个构造演示了最关键的一条规则：

```java
Dog dog  = new Dog("小野狗");     // 对应一个参数的构造
Dog dog1 = new Dog("小野狗", 9);  // 对应两个参数的构造
Dog dog2 = new Dog();            // 对应无参构造——没写无参构造时这行直接编译不过
```

也就是说：**写构造方法就会顶掉默认的无参构造**，想 `new X()` 就必须显式补一个无参构造。

### this

类内部使用，代指当前对象，等同 python 的 `self`。Demo004 的 `Cat.setName(String name)` 里 `this.name = name` 是典型用法——参数名和属性名撞车时，靠 `this` 区分。

## 二、访问控制修饰符

| 访问范围 | private | friendly(默认) | protected | public |
|---|---|---|---|---|
| 同一个类 | 可访问 | 可访问 | 可访问 | 可访问 |
| 同一包中的其他类 | 不可访问 | 可访问 | 可访问 | 可访问 |
| 不同包中的子类 | 不可访问 | 不可访问 | 可访问 | 可访问 |
| 不同包中的非子类 | 不可访问 | 不可访问 | 不可访问 | 可访问 |

- **private**：保护级别最高，只被本类自身的方法访问，子类也不行。
- **friendly（不写）**：包访问性（package private），只对同包可见，即使别包里有子类也看不到。
- **protected**：专门给"跨包的子类"开口子。
- **public**：任意位置 + import 即可用。

记住一句话就够用：**private 只给自己，默认只给同包，protected 给同包 + 跨包子类，public 给所有人**。

## 三、静态成员（static）

- 被 `static` 修饰的属性和方法叫静态属性 / 静态方法，归属于**类**，用类名调用。
- 没被 `static` 修饰的是成员属性 / 成员方法，归属于**对象**，必须 new 之后用对象调。
- JVM 加载类时就为静态变量分配内存，**只分配一次**，被所有实例共享；实例变量每 new 一次分配一次。
- **静态方法里没有 this**（也没有 super），因此不能直接访问实例变量和实例方法，但可以直接访问静态成员。

课堂点了一个"能跑但不正统"的特例：`student.getSchool()` 用对象调静态方法不会报错，但规范写法是 `Student.getSchool()`。反编译里两种都会出现，看到对象调静态方法不用奇怪。

## 四、继承

`class 子类 extends 父类 { }`，Java **只支持单继承**，但可以链式多层（子子类 extends 子类）。

课堂配图画了四种关系：单继承、多重继承（A←B←C 链式）、不同类继承同一个父类、以及**多继承（不支持）**——`class C extends A, B` 在 Java 里是语法错误。

### 继承时的构造方法规则（本篇最容易踩的坑）

1. 子类**没写**构造方法 → 默认调用父类的**无参**构造。
2. 子类没写构造方法 → **不会**自动使用父类的**有参**构造，所以 `new Bird("小野鸟")` 直接报错。

想给子类传参，必须自己写构造方法，并在里面二选一：

```java
class Bird extends Animal {
    public Bird(String name) {
        this.name = name;   // 写法1：直接操作继承来的属性
        // super(name);     // 写法2：调用父类的有参构造
    }
}
```

### super

代指父类对象，等同 python 的 `super()`。两个用途：

- 成员方法里 `super.eat()`：在重写的方法中调回父类原实现
- 构造方法里 `super(name)`：显式调用父类有参构造

Demo006 里 `Bird` 同时写了 `BirdEat()` 和 `eat()`：`BirdEat()` 里 `super.eat()` 输出父类版本，再补一句"吃完了"；而直接调 `bird.eat()` 走的是子类重写版本。同一个方法名，走 super 还是走自己，输出完全不同。

## 五、重写（Override）与重载（Overload）

| | 重写 Override | 重载 Overload |
|---|---|---|
| 发生位置 | 子类对父类 | **同一个类内** |
| 方法名 | 相同 | 相同 |
| 参数列表 | **必须完全相同** | **必须不同**（个数或类型） |
| 返回值 | **不能改变** | 可同可不同 |
| 关键字 | `@Override` 校验 | 无 |

Demo007 里有个特别值得记的细节：

- 父类有 `eat(String name)`
- 子类 `public void eat(String name)` 加了 `@Override` → 是**重写**
- 子类另写 `public void eat(String name, int age)` → 参数变了，这**不是重写**，而是重载；把 `@Override` 去掉就不报错了，因为它变成了重载方法

**逆向意义**：重写决定"运行时到底跑谁的实现"（多态的根基）；重载决定"Frida hook 时必须写 overload 指定签名"（day07 已记）。这两个概念混了，读反编译代码会判断错调用链。

> 补充一条与课件表述不同的地方：课件写"final 修饰方法表示不能被重写或重载"。Java 里 `final` 实际只禁止**重写**（override），同一个类里对 final 方法做重载在语法上是允许的。读反编译代码时以"final 方法不会被覆盖"为准即可。

## 六、接口（interface）

接口是**抽象方法的集合**，用 `interface` 声明，和类是两回事：类描述对象的属性和方法，接口只规定"必须实现哪些方法"。

```java
interface Duck {
    final String name = "justin";   // 只能是 final / static 字段
    public static int age = 19;
    public void Speak();            // 抽象方法，不能有具体实现
    public void Run();
}
```

要点清单：

- 接口**没有构造方法**，不能被 `new`（但接口类型可以声明变量，指向实现类对象）
- 接口里所有方法必须是抽象方法，不能有方法体
- 接口不能包含普通成员变量，只能是 `static` / `final`
- 类与接口是**实现**关系（implements），不叫继承
- 实现类必须实现接口里**所有**方法，否则自己也得声明成 abstract
- **接口支持多继承**：`interface Foo extends Duck, TDuck { }`，extends 只写一次，后面跟多个接口

Demo008 用"普通鸭子"和"唐老鸭"两个实现类演示：两个类都 implements Duck，`Duck d = p;` 可以用接口类型接住任意一个实现对象——这就是接口实现多态的基础。

## 七、抽象类（abstract class）

```java
abstract class Animal {
    public abstract void Speak();     // 抽象方法：只有签名
    public void Run() { }             // 具体方法：有实现
}
class Bird extends Animal {
    @Override public void Speak() { }  // 子类必须重写全部抽象方法
}
```

- 抽象类**不能被实例化**
- 抽象类里可以同时有抽象方法和具体方法（这是它和接口最大的区别）
- 继承抽象类的子类必须实现全部抽象方法，除非子类自己也是抽象类
- `abstract` 和 `final` 互斥（一个要求被继承，一个禁止被继承）

## 八、封装

Java 一般不直接操作对象属性，而是通过方法设置和获取——**更安全**。

Demo009 的对比很直观：

```java
class Too {
    public String name;       // public：别的类能直接读改
    private int age;          // private：只能走 setAge / getAge
    public int getAge() { return age + 10; }   // 注意这里做了变换
    public void setAge(int age) { this.age = age; }
}
```

- `name` 是 public，外部 `t.name = "彭于晏"` 随便改
- `age` 是 private，外部拿不到，只能 `setAge(99)` / `getAge()`

**坑（逆向时非常要紧）**：getter 里可以有任意逻辑——课件的 `getAge()` 返回的是 `age + 10`，不是字段原值。**不要假设 `getXxx()` 一定等于字段本身**，签名里如果用 getter 取值，就要跟着 getter 的逻辑走。

## 九、多态（本篇核心）

多态 = 同一类事物的多种形态，调用同一个方法时表现出不同行为。

**三个必要条件**（缺一不可）：

1. 有继承（或实现）关系的父类和子类
2. 子类**重写**父类方法
3. **父类引用指向子类对象**（`Animal dog = new Dog()`）

### 成员变量：编译运行都看左边

```java
Animal dog = new Dog();    // Animal.age = 11, Dog.age = 33
System.out.println(dog.age);   // 输出 11，父类的值
```

变量是跟着**引用类型**走的，`dog` 声明成 Animal，取的就是 Animal 的 age。

### 成员方法：编译看左边，运行看右边

```java
dog.eat();   // 输出"狗吃饭"，跑的是子类重写版本
```

编译时校验"Animal 里有没有 eat"，运行时执行"Dog 里的实现"。反过来，子类独有方法在校验阶段就被拦掉：

```java
dog.walk();   // 编译不过——Animal 里没有 walk
```

### 引用类型转换

- **向上转型**（子 → 父）：自动、默认，`Animal dog = new Dog()` 本身就是向上转型
- **向下转型**（父 → 子）：必须强转 `Dog dog1 = (Dog) dog;`，转完才能调 `walk()`
- 转错类型会抛**类型转换异常**（ClassCastException）
- 正确姿势是先判断再转：

```java
Animal cat = new Cat();
if (cat instanceof Cat) {
    Cat c = (Cat) cat;
    c.sleep();
}
```

### 三种实现多态的方式

| 方式 | 写法 |
|---|---|
| 继承 | `Animal a = new Dog()`，Dog extends Animal 并重写 speak |
| 抽象类 | `Animal a = new Dog()`，Animal 是 abstract，Dog 实现抽象方法 |
| 接口 | `Animal2 a = new Dog2()`，Dog2 implements Animal2 |

Demo010 / Demo011 的做法最能说明多态的价值：写一个 `speak(Animal p)` 方法，传人、狗、猫进去都行，方法体只写 `p.speak()`，**调用方完全不关心具体类型**。Demo010 里还留着注释掉的 `AnimalSpeak(Person1 p)` 版本——那是没有多态时要为每个类型写一个重载方法的写法，多态把这堆重载消掉了。

**逆向意义**：`Animal a = new Dog()` 这种"父类型接子对象"在反编译代码里遍地都是。看方法调用时不能只看声明类型，要顺着 `new` 的实例去找真正执行的实现——**hook 时要 hook 子类那个方法，不是父类的**。

## 十、枚举

枚举是特殊的类，表示一组常量（四季、十二个月、男/女/未知）。

```java
enum Sex { Male, Female, Unknown; }                       // 简单枚举

enum Week {
    SUNDAY(0, "星期日"), MONDAY(1, "星期一"), ... ;          // 带字段的枚举
    public int id;
    public String meaning;
    Week(int id, String meaning) {                        // 枚举可以有构造方法
        this.id = id;
        this.meaning = meaning;
    }
}
```

- `Sex.Male` 直接取常量
- `Week.SUNDAY.ordinal()` → 顺序值（从 0 开始）→ 0
- `Week.MONDAY.id` / `.meaning` → 自定义字段

**逆向意义**：枚举常量和它的构造参数在 dex 里由类初始化块 `<clinit>` 一次性建立；`ordinal()`、`name()` 常被 App 拿去拼签名或做参数映射，看到枚举就顺手检查有没有这类调用。

## 十一、包（package）

包用于区分命名空间，本质就是目录。

```java
package com.lqz;          // 必须写在文件第一行

import com.lqz.*;         // 导入包下所有类
import com.lqz.Helper;    // 导入指定类
```

三个作用：把相关类组织在一起方便查找；**避免类名冲突**（不同包可以有同名类）；限定访问权限（包访问性）。

Demo012 就是"同名类冲突"的现场：`com.lqz.Utils` 和 `util.Utils` 两个同名类，靠 `import com.lqz.Utils;` 引入一个，另一个必须写全限定名 `util.Utils u1 = new util.Utils();` 才能用。

**逆向意义**：jadx 里类名的完整路径就是包路径，`com.lqz.Helper` 对应 `com/lqz/Helper.smali`。找类、写 Frida 的 `Java.use("包名.类名")` 都靠这层映射。

## 十二、常用加密与编码（逆向实操核心）

这一节的每一条在后面的案例里都会反复出现，是本篇最该背下来的部分。

### 12.1 字符串被藏成字节数组

反编译回来的代码里，有些字符串不用明文写，而是用字节数组藏着，目的就是藏真正的字符串：

```java
String salt = "sign";
new String(new byte[]{115, 105, 103, 110});   // 还原出来就是 "sign"
```

逆向时看到一长串纯数字的 `new byte[]{...}`，先按 ±256 还原成字符串看看，往往就是签名用的盐或固定参数。

### 12.2 UUID

```java
String uid = UUID.randomUUID().toString();     // 8-4-4-4-12，共 36 字符
```

```python
uid = str(uuid.uuid4())
```

课件配图是支付宝的 `UUID.randomUUID().toString()`——重点是它外面那层逻辑：**先从 SharedPreferences 读缓存（key 为 `random`），读不到才生成，生成后写回缓存**。这是"设备指纹/随机标识只生成一次、之后复用"的标准写法，抓包时同一个设备多次请求该字段不变，就是因为走了缓存。

### 12.3 随机值 + 十六进制

```java
BigInteger v4 = new BigInteger(80, new SecureRandom());  // 80 位 ≈ 10 字节
String res = v4.toString(16);                            // 转十六进制字符串
```

优酷那张截图里，这段代码后面还有两段处理，都是实战里常见的手工加工：

- `if (v4.charAt(0) == '-') v4 = v4.substring(1);` —— `BigInteger.toString(16)` 可能带负号，先去掉
- `while (v1 > 0) { v5.append('F'); --v1; }` —— 长度不够就循环补 `'F'`，把随机串凑到固定长度

python 侧等价写法（3.9+ 有 `randbytes`）：

```python
data = random.randbytes(10)                          # 10 个字节
"".join([hex(item)[2:] for item in random.randbytes(10)])   # 直接拼
```

3.9 以前没有 `randbytes`，用 `random.randint(0, 255)` 循环 10 次造字节列表。

**坑**：`hex(item)[2:]` 会吃掉前导零（`0x0a` 出来是 `'a'` 而不是 `'0a'`）。想保证"一个字节 = 两个字符"，必须 `.rjust(2, "0")`；只是要一个随机 hex 串、不关心字节对齐时，课件也就直接 join 了。

### 12.5 字节转十六进制字符串

B站心跳方法的反编译截图（`public static String H(byte[] arg5)`）是标准实现：

```java
for (int i = 0; i < len; i++) {
    int v3 = arg5[i] & 0xFF;           // ← 关键：把有符号 byte 拉回 0~255
    if (v3 < 16) sb.append('0');       // ← 不足两位补 0
    sb.append(Integer.toHexString(v3));
}
```

`& 0xFF` 和 python 里"负数 +256"是**同一件事**：Java 的 byte 有符号（-128~127），按位与 255 之后变成无符号（0~255），再转 hex 才是正确字节。

python 等价：

```python
"".join([hex(i)[2:].rjust(2, "0") for i in b"pengyuyan"])
```

### 12.6 MD5

```java
MessageDigest md = MessageDigest.getInstance("MD5");
md.update("xxx".getBytes("UTF-8"));
byte[] digest = md.digest();     // 返回 byte[]
```

```python
obj = hashlib.md5('yyy'.encode('utf-8'))
obj.update('xxxxx'.encode('utf-8'))   # 可以多次 update，等价于拼接后一次算
v1 = obj.hexdigest()   # d3c0aaaf596e3299f695591f00fd75cb（32 位小写 hex 字符串）
v2 = obj.digest()      # b'\xd3\xc0...'（16 字节原始值）
```

**Java 没有 `hexdigest` 这种东西**——`MessageDigest.digest()` 只给 `byte[]`，转成 32 位 hex 字符串必须自己写。配图里的实现就是自己写的那套：

- 先建一张字符表 `char[] = {'0','1',...,'f'}`
- 每个字节 `& 255` 拿到 0~255
- `>> 4` 取高 4 位查表、`& 15` 取低 4 位查表，两个字符拼成一个字节的 hex

看懂了这段，jadx 里那些 `final char[] f61220a = {'0', '1', ...}` 的类就能一眼认出是"字节转 hex 工具"，再往上就能找到 MD5 计算入口。

### 12.7 Base64

```java
String res = Base64.getEncoder().encodeToString(name.getBytes());  // "彭于晏" → 5b2t5LqO5pmP
byte[] origin = Base64.getDecoder().decode(res);
String data = new String(origin);
```

```python
res = base64.b64encode("彭于晏".encode('utf-8'))   # b'5b2t5LqO5pmP'
origin = base64.b64decode(res).decode('utf-8')
```

两个语言侧的差异要留意：Java 的 `encodeToString` 直接给 **String**，python 的 `b64encode` 给 **bytes**（带 `b''`）。

另外 Android 里还有一套 `android.util.Base64`，方法签名带 flags（如 `encodeToString(bytes, Base64.NO_WRAP)`）；反编译里这套出现频率不比 JDK 的低，看到 `android.util.Base64` 不要当成 JDK 的 `java.util.Base64`。

## 十四、关键知识清单

- 类定义模板：`[public] [abstract|final] class 名 [extends 父类] [implements 接口]`，**abstract 与 final 互斥**。
- 属性语法 `[public|protected|private] [static] [final] 类型 名`；`final` 常量声明时必须赋值。
- 构造方法同名、无返回值、不写 void、可重载；**写了构造就顶掉默认无参构造**。
- `this` = 当前对象（≈ python self），`super` = 父类对象（≈ python super()）。
- 访问权限四档：private 只给本类 → 默认只给同包 → protected 给同包 + 跨包子类 → public 给所有人。
- `static` 成员属于类、只分配一次内存、被所有实例共享；**静态方法里没有 this / super**，不能直接访问实例成员。
- 对象也能调静态方法（能编译但不正统），反编译里两种写法都会出现。
- Java **单继承**、接口可**多继承**、类可**实现多个接口**。
- 子类没写构造方法 → 默认调父类**无参**构造；**不会**自动调父类有参构造，`new 子类(参数)` 会编译失败。
- **重写**：跨类、同名同参同返回值、`@Override`；**重载**：同类、同名不同参。改参数就不是重写，去掉 `@Override` 会变成重载。
- 接口：不能 new、没有构造方法、方法全抽象、字段只能 static/final、实现类必须实现全部方法。
- 抽象类：不能实例化、可同时有抽象与具体方法、子类必须实现全部抽象方法、与 final 互斥。
- 封装：属性 private + get/set；**getter 里可能有变换逻辑，不要假设 getXxx 就是字段原值**。
- 多态三条件：继承/实现关系 + 子类重写 + 父类引用指向子类对象。
- **成员变量编译运行都看左边；成员方法编译看左边、运行看右边**；子类独有方法通过父类引用调不到。
- 向上转型自动，向下转型要强转，转错抛 ClassCastException；先 `instanceof` 再转。
- 枚举可带字段和构造方法；`ordinal()` 拿顺序值（从 0 起）。
- `package` 写在文件首行，包路径 = 目录路径；同名类靠全限定名区分。
- 字符串藏成 `new byte[]{...}` 时，按"负数 +256"还原。
- `BigInteger.toString(16)` 可能带负号，要先去掉首字符 `-`；长度不够常被循环补 `'F'` 到定长。
- `hex(x)[2:]` 会丢前导零，需要 `.rjust(2, "0")` 才是规范的"一字节两字符"。
- `System.currentTimeMillis()` 毫秒，`/1000` 得秒；python 用 `time.time()`。
- **字节转 hex 靠 `& 0xFF`（等价 python 的负数 +256）+ 补零 + `toHexString`**；MD5 的 32 位 hex 字符串在 Java 里必须自己实现（没有 hexdigest）。
- Base64：Java `Base64.getEncoder().encodeToString(bytes)` 返回 String，python `b64encode` 返回 bytes；Android 侧还有 `android.util.Base64` 另一套 API。
