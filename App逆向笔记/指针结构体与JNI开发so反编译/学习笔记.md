## 二、指针：C 里最容易被讲糊涂的一块

**一句话定义**：指针是存储变量内存地址的变量。变量有值，指针的值是"另一个变量的门牌号"。

### 2.1 三个符号，三种含义

课件在课堂笔记里把这条讲得最清楚，值得原样记住：

| 写法 | 位置 | 含义 |
| --- | --- | --- |
| `int *v2` | 声明中 | 定义一个"指向 int 的指针"变量 |
| `&v1` | 表达式 | 取 v1 的地址，结果是指针类型；64 位下 8 字节 |
| `*v2` | 表达式 | 解引用：把地址还原成那个变量本身 |

两个 `*` 长得一样、含义完全不同——声明里的 `*` 是类型的一部分，表达式里的 `*` 是运算。读 so 伪 C 时混淆这两者，会把"声明了一个指针"误读成"解引用了某个东西"。

`*v2` 出现在赋值左边时就是"改它指向的那块内存"：`*v2 = 99` 与 `v1 = 99` 完全等价，因为动的是同一块内存。

### 2.2 指针大小与类型无关

`int *`、`char *`、`long *` 在 64 位下 `sizeof` 都是 8。指针只存地址，不存指向的数据，所以宽度由平台位数决定，不由指向类型决定。这条纠正一个常见直觉错误：以为 `char *` 就小一号。

零值用 `NULL`，打印出来是 `0x0`，`if (!v2)` 判空成立。课件注释掉的 `int *v2;` 是野指针——没初始化就解引用，读到的是随机地址，轻则乱值重则崩溃。so 里也一样，未初始化的指针字段是崩溃的常见原因。

### 2.3 传参一律是值传递

这是本课最该记住的机制：

- `changeA(int a)` 里 `a = 99`，函数内打印是 99，函数外的 `a` 还是 1。因为形参只是实参的**一份拷贝**。
- `changePointA(int *p)` 里 `*p = 99`，外面的 `a` 真的变了。原因不是"指针按引用传"，而是**拷贝的是地址，地址指向的还是原来那块内存**。

结论：C 没有引用传递，想通过函数改外部变量，只能传地址。这个机制直接解释了为什么 so 里的函数参数动不动就是指针——那是它在往外写结果。

课上顺带一句值得记：Python 里"一切皆对象、变量都是引用"，本质上就是 C 的指针在撑。

### 2.4 指针运算：步长等于元素大小

```c
int a[3] = {11, 22, 33};
int *p = &a;        // 取到的是第 0 个元素的地址
*(p + 2)            // 33
```

`&a` 拿到的是数组首元素地址，`p + 1` 加的不是 1 字节，而是 `sizeof(int)` = 4 字节。**编译器按指针类型算步长**：`char *` 走 1，`int *` 走 4。这解释了 day11 打印数组地址时"int 数组相邻差 4、char 数组相邻差 1"的现象。

`p + 1` 不改变 p 自己，`++p` 会。课上两种写法都给了，实际遍历时要注意用哪个。

配套的还有"指针数组"：`int *p1[] = {&i, &x, &y}` 是数组，元素是三个指针；取值要 `**p1`——先取 `p1[0]` 得到 `&i`，再解一次才到 10。

### 2.5 指针的指针

```c
int a = 100;
int *p1 = &a;
int **p2 = &p1;
int ***p3 = &p2;
```

`p3` 存 p2 的地址，`*p3` 得 p1 的地址，`**p3` 得 a 的地址，`***p3` 才是 100。逐层剥壳，剥几层取决于指针的层数。Java 里没有对应的东西，但读 so 时会大量遇到：`int **` 常用于"函数内分配内存，把新地址写回调用方"。

## 三、字符串与指针的几个实操点

### 3.1 sprintf 逐字节拼字符串

课件用 `sprintf(p, "%c", 'j')` 加 `p += 1` 走位，一个字符一个字符把 `char a[6]` 填成 `"justin"`。`p += 1` 之所以是走 1 字节，因为 p 是 `char *`——又回到"步长等于元素大小"。

这条演示的用意是让人看见"字符串就是一段连续字节"，而不是一个对象。以后在 so 里看到循环逐字节写缓冲区、最后补 0，就是同一件事。

### 3.2 三个常用函数

| 函数 | 作用 | 用法要点 |
| --- | --- | --- |
| `strstr(s, sub)` | 找子串首次出现位置 | 返回指针，找不到返回 NULL，判空用 `if (!res)` |
| `strcpy(dst, src)` | 复制 | dst 必须有足够空间，不检查越界 |
| `strcat(dst, src)` | 追加到 dst 末尾 | 从 dst 的 `\0` 处开始覆盖 |

`strlen`、`strcmp`、`strchr` 是同一套 `string.h` 家族的另三个，课件列了六件套表格。这六个函数在 so 里出现频率极高，是识别"这是在做字符串拼接/比较/查表"的指纹。

### 3.3 malloc 的正确用法

```c
char *s = malloc(strlen(name) + strlen(role) + 1);
strcpy(s, name);
strcat(s, role);
```

`+1` 是给结尾的 `\0` 留位置，少了这个 1 就是典型的堆溢出。课件这里示范的是正确写法：目标缓冲区必须自己申请，长度必须把结束符算进去。不 malloc 直接往字面量上 strcat 会崩——字面量在只读段。

## 四、结构体、链表与内存布局

### 4.1 结构体的本质

`struct` 是用户自定义的复合类型，成员可以是基本类型、其他结构体、指针。逆向视角看，它就是一个**按声明顺序首尾相接排布的内存块**：第一个字段在基址偏移 0，第二个在偏移 `sizeof(第一个字段)`，依此类推。

这一条是把 C 和汇编连起来的关键。IDA 里反编译出来的 `*(_QWORD *)(a1 + 8)`、`*(int *)(v3 + 16)`，就是在按偏移取结构体字段。知道字段声明顺序，才知道偏移对应谁。

访问方式有两种，等价：`(*p).age` 和 `p->age`。`->` 只是 `(* ).` 的语法糖，课件专门用 `(*(*v1.next).next).data` 和 `v1.next->next->data` 对照，证明两者是同一件事。

（补充一句课件没讲的：实际内存里字段之间还有对齐填充，`struct {char a; int b;}` 不一定是 5 字节。课件只讲了"顺序连续"，做逆向时偏移要以实际二进制为准。）

### 4.2 单向链表

```c
struct Node {
    int data;
    struct Node *next;
};
```

课件用三个栈上变量手工串起来：`v3 = {33}`、`v2 = {22, &v3}`、`v1 = {11, &v2}`，然后 `v1.next->next->data` 拿到 33。

关键认知：**链表不是语言特性，是"结构体里放一个指向同类型结构体的指针"这个约定的名字**。`next` 指向下一个节点，走到 NULL 就结束。so 里所有链表、树、队列，都是这个骨架加变体。

### 4.3 双向链表与双向循环链表

双向链表加一个 `prev` 指回前一个，于是能从尾部倒着走：`p3.prev->prev->data` 得 11。

双向**循环**链表把头尾互指起来：`p1.prev = &p3`、`p3.next = &p1`。结果是连走 6 步会转回起点，`p1.next->next->next->data` 又回到 11。课件用打印序列演示了这个"绕圈"现象。

课堂上留了一个思考题：**如何判断链表有没有环——快慢指针**。一个走一步、一个走两步，追上就有环。这题不是 C 语法，是数据结构常识，so 里防死循环的写法也常用它。

## 五、预处理与头文件

### 5.1 宏是文本替换，发生在编译之前

`#define ME 200` 定义的不是变量是常量，后续 `ME = 33` 编译不过——因为在编译器看到代码之前，`ME` 已经被替换成字面量了。

带参宏同理，纯文本替换：

```c
#define DB(x1, x2) (x1 * x2)
DB(2 + 1, 4)   // 展开成 (2 + 1 * 4) = 6，不是 12
```

这是宏最经典的坑：**参数和整体都要加括号**，否则运算符优先级会把表达式拆散。写 `(x1) * (x2)` 才能得到 12。这条在逆向里的意义是：读伪 C 时看到 `#define` 是给人类看的，编译后只剩展开结果，so 里不会有宏名。

### 5.2 头文件三件套

```
项目目录
├── main.c     // 调用方，#include "utils.h"
├── utils.c    // 定义，int add(int a, int b) { return a + b; }
└── utils.h    // 声明，int add(int a, int b);
```

声明与定义分离，是为了让多个 .c 文件能共享同一份签名而不重复实现。`#include <xxx.h>` 从系统目录找，`#include "xxx.h"` 先找当前目录——这对尖括号与双引号的区别，就是 JNI 里 `#include <jni.h>` 与本地头文件的区别来源。

JNI 开发时在自己的 c 文件里 `#include <jni.h>`，用的就是这套机制；头文件里声明了 `JNIEnv`、`jclass`、`JNIEXPORT` 这些类型和宏，不引入就没法编译。

### 5.3 顺藤摸到 cpython 源码

课件给了一条很有价值的线索：**Python 的 list、dict 在 C 层就是结构体**。

- `Objects/listobject.c` 是列表的实现
- `Include/listobject.h` 是它的头文件

沿着 `Include/` 看头文件里结构体的字段，再回 `Objects/` 看函数怎么操作这些字段，就是读一个真实大型 C 项目的方法。对做逆向的人来说，这也是理解"高级语言对象在内存里长什么样"最便宜的一手材料。

## 六、JNI 与 NDK

### 6.1 两个概念

- **JNI**：Java Native Interface，Java 本地开发接口。作用是让 Java 调 C/C++，也让 C 回调 Java。Android 上 Java 层写 `native` 方法，实现放在 so 里。
- **NDK**：Native Development Kit，JNI 开发工具包，负责把 C 代码交叉编译成各 CPU 架构的 so。Android Studio 里下载即可。

### 6.2 两种建工程的路子

| 模板 | 内容 | 适合 |
| --- | --- | --- |
| Empty Activity（纯 Java） | 只有 Java，要自己加 cpp 目录、CMake 配置 | 想看清每个配置项在干什么 |
| Native C++（Java + C） | 模板已配好 CMake、so 加载、示例算法 | 快速起步；但会生成一堆用不上的默认文件（native-lib.cpp 等），课上建议先留着，学会自己配了再回来删 |

### 6.3 接入一个 native 方法的五步

这是本课最实用的一段流程，顺序不能乱：

1. **写 C 实现**（放 cpp 目录下，文件后缀要是 `.c`）：

```c
#include <jni.h>
JNIEXPORT jint JNICALL
Java_com_justin_s8day12_Utils_v1(JNIEnv *env, jclass clazz, jint v1, jint v2) {
    return v1 + v2;
}
```

2. **Java 侧声明 native 方法**，不带方法体：

```java
package com.justin.s8day12;
public class Utils {
    public static native int v1(int a1, int a2);
}
```

3. **加载 so**，写在静态代码块里，类加载时执行一次：

```java
static { System.loadLibrary("utils"); }
```

名字写 `utils`，不带 `lib` 前缀也不带 `.so` 后缀——实际文件是 `libutils.so`，但加载时只写中间那段。

4. **CMakeLists.txt 登记**：

```cmake
add_library(utils SHARED utils.c)        # 库名 utils，源文件 utils.c
target_link_libraries(utils ${log-lib})  # 链接日志库
```

`add_library` 的库名要和 `System.loadLibrary` 的名字对上，这是最容易漏的一步：C 写了、Java 声明了，忘了登记，编译产物里就没有这个 so。

5. **Java 调用**：`Utils.v1(33, 44)`。

### 6.4 函数名就是注册表

`Java_com_justin_s8day12_Utils_v1` 拆开看：`Java_` 固定前缀 + 包名 `com.justin.s8day12` + 类名 `Utils` + 方法名 `v1`，非字母数字的字符（`.`、`_`、`$`）用下划线替代。

这就是 JNI 的**静态注册**：靠命名约定把 Java 的 native 方法和 so 里的符号绑在一起，不需要任何配置文件。一旦包名或类名被混淆，这个符号名也跟着变，但**反过来的价值更大**——在 IDA 的导出表里看到 `Java_xxx_yyy_ZZZ`，等于直接告诉你这个函数对应哪个包、哪个类、哪个方法，这是 so 逆向里最省事的一条线索。

参数上还有一条固定规则：静态方法的头两个参数是 `(JNIEnv *env, jclass clazz)`，实例方法第二个是 `jobject thiz`。`jint`、`jstring` 这些是 JNI 定义的 Java 类型在 C 侧的对应物。

（补充：除了这套命名约定，JNI 还有 `RegisterNatives` 动态注册，靠调用时传函数表绑定，符号名可以任意。加固和商业 so 常这么干，导出表里找不到 `Java_` 前缀，就得去 `JNI_OnLoad` 或 `.init_array` 里找。课件此行只讲了静态注册，这个差异先记个位置。）

## 七、把自己写的东西反编译一遍

课件最后一步是整个 day11–day12 的验收动作：拿自己写的 apk 走一遍逆向流程，知道每个环节对上的是什么。

**Java 层**：apk 拖进 jadx。搜到 `Utils` 类，只会看到 `public static native int v1(int, int);` 这样一行空方法——**这就是 so 加密比 Java 加密难破的原因**：jadx 里没有方法体可看，代码根本不在 dex 里。

**so 层**：

1. 用压缩工具解压 apk；
2. 进 `lib/arm64-v8a/`（其他架构目录同理），找到 `libutils.so`；
3. 拖进 IDA；
4. 在 exports（导出符号）里找到 `Java_com_justin_s8day12_Utils_v1`；
5. 双击进函数看汇编；
6. 按 F5，得到伪 C 代码。

伪 C 能读，靠的就是前面几节：认 `a1 + 8` 是结构体偏移、认 `*(int *)` 是在按类型解读内存、认循环里逐字节写缓冲区是在拼字符串、认 `(**a3)` 是在往外写结果。

一条完整的对应关系到此闭合：**Java 声明（jadx 可见）→ 命名约定（决定符号名）→ so 导出符号（IDA 可见）→ 汇编 → 伪 C**。以后遇到第三方 App 的 so，只是把"自己写的简单加法"换成"复杂的签名算法"，路径完全一样。

## 八、课件口径偏差与坑

1. **`int *p = &a;`（a 是 `int[3]`）严格来说类型不匹配**。`&a` 的类型是 `int (*)[3]`，赋给 `int *` 编译器会给警告。课件能跑是因为地址值相同，属教学简化。规范写法是 `int *p = a;`（数组退化）或 `int *p = &a[0];`。
2. **long double 的字节数两份笔记不一致**：主文档写 16 字节，课堂笔记写 12 字节。实际宽度随平台和编译器变化（x86-64 GCC 是 16），唯一可靠的判断是 `sizeof`。
3. **`long double` 的输出格式必须配套**：`%Lf` / `%Le` 配大写 `L` 后缀。课堂笔记写的是 `long double f3 = 365.123456789l;` 配 `%f`，自己标了"存疑--有问题"——这是对的，`%f` 按 double 解析，传 long double 进去结果错乱。主文档已改成 `365.123456789L` 加 `%Lf`。
4. **`sprintf` 逐字节写 `char a[6]` 会越界 1 字节**。`sprintf(p, "%c", c)` 每次会写"字符 + `\0`"两个字节，填第 6 个字符时那个 `\0` 落在 `a[6]`，超出数组边界。课件这里能打印出 `justin` 是撞运气（后面的栈内存恰好是 0）。教学演示无害，但要知道这是 UB，不要照着写生产代码。
5. **带参宏不加括号的坑**：`DB(2 + 1, 4)` 得 6 而不是 12，课件专门演示了这一点，属于必须记住的行为而不是 bug。
6. **两份文档的小节编号都重了**：主文档两个 3.1（基本使用 / 单向链表），课堂笔记两个 3.2（单向链表 / 双向链表）。内容没错，对照引用时按标题找而不是按编号找。
7. **结构体对齐课件没讲**：只讲了"字段按顺序连续"，实际有 padding。做逆向算偏移时不能凭字段大小直接累加。
8. **`System.loadLibrary("utils")` 与 `add_library(utils ...)` 的库名必须一致**，且前者的参数字符串不带 `lib` 前缀、不带 `.so` 后缀。

## 关键知识清单

- **指针三符号**：`int *p` 声明指针、`&v` 取地址、`*p` 解引用；指针宽度只与平台有关（64 位 8 字节），与指向类型无关。
- **传参是值传递**：想改外部变量只能传地址，`*p = 99` 改的是原内存；这也是 so 函数参数普遍是指针的原因。
- **指针运算步长 = 元素大小**：`int *` 加 1 走 4 字节，`char *` 加 1 走 1 字节；`p+1` 不改 p，`++p` 改。
- **指针的指针**：`***p3` 逐层剥壳；`int **` 常见于"函数内分配、把地址写回调用方"。
- **字符串函数六件套**：`strcpy/strcat/strlen/strcmp/strchr/strstr`，都是"按字节走到 `\0`"，是识别 so 字符串操作的指纹。
- **malloc 长度要 +1**：给 `\0` 留位；目标缓冲区必须自己申请，字面量在只读段不能写。
- **结构体 = 按顺序排列的内存块**：字段偏移 = 前面字段大小之和（实际有对齐填充），`p->x` 等价 `(*p).x`，IDA 里的 `a1 + 8` 就是字段偏移。
- **链表 = 结构体里放同类型指针**：单链表靠 `next`、双向加 `prev`、循环链表头尾互指；判环用快慢指针。
- **宏是编译前的文本替换**：带参宏的参数和整体都要加括号，否则 `DB(2+1,4)` 得 6。
- **头文件分工**：`.h` 放声明、`.c` 放定义，`<>` 找系统目录、`""` 先找当前目录；JNI 里 `#include <jni.h>` 是同一机制。
- **JNI 五步**：写 C（`Java_包_类_方法`）→ Java 声明 native → `System.loadLibrary("utils")` → CMake `add_library(utils SHARED utils.c)` → Java 调用；库名三处必须一致。
- **静态注册的意义**：函数名就是注册表，IDA 导出表里看到 `Java_` 前缀就知道对应哪个 Java 方法；动态注册符号名随意，得去 `JNI_OnLoad` 里找。
- **so 反编译链路**：jadx 看 native 声明（空方法体）→ 解压 apk 取 `lib/arm64-v8a/*.so` → IDA 看 exports → 双击看汇编 → F5 出伪 C；读伪 C 靠结构体偏移、指针层级、字符串逐字节写这几个认知。
