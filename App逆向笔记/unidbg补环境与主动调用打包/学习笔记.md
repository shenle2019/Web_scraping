## 1. unidbg 是什么：为什么要走这条路

### 1.1 破解 so 加密的四条路

| 路线 | 做法 | 代价 | 典型 |
| --- | --- | --- | --- |
| 1 硬核破解 | 反编译读 so 逻辑，用 Python 重写算法 | 难度最大，算法一改就废 | 得物 newSign |
| 2 frida-rpc | hook 后 RPC 调 so 里的方法，传参拿结果 | 破得简单，交付麻烦（要真机 + frida-server） | 大姨妈 |
| 3 自写 APK | 自己写个安卓 App 把别人 so 装进去调 | 简单，交付麻烦（要给安装包） | —— |
| 4 unidbg | 用 Java 模拟安卓设备，直接加载 apk + so 调用 native 方法 | 集合 1/2/3 优点，不用手机也不用读懂算法 | 本课全部案例 |

### 1.2 定位与交付形态

- unidbg 是 Java 开源项目（`zhkl0228/unidbg`），底层是 **unicorn**（CPU 指令级模拟），可以模拟 Android / iOS 的 native library。
- 它模拟的是「手机的执行环境」：把 APK 和 so 丢进模拟器里跑，App 认为自己在一台真机上。
- 我们的目标不是读懂 so，而是**直接调用 so 里的某个加密方法**：传对参数 → 拿回密文。
- 交付形态：**Python 脚本 + 一个 Java jar 包**。Python 用 `subprocess` 调 `java -jar`，把参数（待签名的请求体）传进去，把签名拿回来。

### 1.3 下载与验证

- 下载：`https://github.com/zhkl0228/unidbg/releases`，用 **v0.9.7**。
- 用 IDEA 打开源码项目，前提是 JDK + IDEA 环境就绪；**项目路径不能有中文**。
- 验证方式：跑框架自带示例 `unidbg-android/src/test/java/com/anjuke.mobile.sign/SignUtil`，能正常打印结果说明环境通了。

## 2. 六步模板：每次只需改三处

所有案例的构造方法几乎一字不差，只在三处变动：`for32Bit/for64Bit` + 包名、apk 路径、so 路径。

```java
public class Xxx extends AbstractJni {           // 继承 AbstractJni：为补环境做准备
    public static AndroidEmulator emulator;
    public static Memory memory;
    public static VM vm;
    public static Module module;

    public Xxx() {
        // 1 创建设备：32 位对应 armeabi-v7a，64 位对应 arm64-v8a
        emulator = AndroidEmulatorBuilder.for32Bit().setProcessName("com.che168.autotradercloud").build();
        // 2 取内存对象
        memory = emulator.getMemory();
        // 3 设置安卓 SDK 版本：只支持 19 / 23
        memory.setLibraryResolver(new AndroidResolver(23));
        // 4 创建虚拟机（相当于 Python 解释器），setJni 把当前类注册成补环境入口
        vm = emulator.createDalvikVM(new File("apks/che/che3.32.1.apk"));
        vm.setJni(this);
        // vm.setVerbose(true);                     // 打印调用细节，调试补环境时很有用
        // 5 加载 so
        DalvikModule dm = vm.loadLibrary(new File("apks/che/libnative-lib.so"), false);
        dm.callJNI_OnLoad(emulator);                // 动态注册必须调，静态注册可不调
        // 6 拿到 module，代表这个 so，后续拿基址/偏移/符号都靠它
        module = dm.getModule();
    }
}
```

逐步要点：

1. **位数必须和 so 目录对齐**：so 在 `armeabi-v7a` 就是 32 位，在 `arm64-v8a` 就是 64 位。`setProcessName` 写包名，只是给模拟进程一个名字，随便写但建议写包名。
2. `AndroidResolver` 只接受 19 和 23 两个 SDK 版本。
3. `setJni(this)` 就是把「C 调 Java 时缺的东西」补在这个类里，所以类必须 `extends AbstractJni`。
4. `callJNI_OnLoad` 的取舍看注册方式：**动态注册（JNI_OnLoad 里 RegisterNatives）必须调**；静态注册（符号名就是 Java_包_类_方法）可以不调。
5. `dm.getModule()` 得到的 `module` 是后续主动调用 C 函数的入口。

## 3. 调用 native 方法：签名与传参

### 3.1 JNI 签名

Java 方法在 so 里靠「方法名 + 签名串」定位，签名由参数类型和返回值类型拼成：

| Java 类型 | 签名 |
| --- | --- |
| boolean | Z |
| int | I |
| long | J |
| byte[] | [B |
| String | Ljava/lang/String; |
| Object | Ljava/lang/Object; |
| 类 | L包/路径/类; |
| void | V |

例：`get3desKey(Context ctx)` 返回 String → `get3desKey(Landroid/content/Context;)Ljava/lang/String;`

### 3.2 调用的三段式

```java
// 1 定位类：包路径用 / 分隔
DvmClass cls = vm.resolveClass("com/autohome/ahkit/jni/CheckSignUtil");
// 2 调 native 方法（静态方法用 callStaticJniMethodObject，实例方法用 callJniMethodObject）
StringObject obj = cls.callStaticJniMethodObject(emulator, method, arg1, arg2, ...);
// 3 取值：返回的是 unidbg 的包裹对象，不是原生类型
String result = obj.getValue();
```

### 3.3 传参映射表（最容易踩的地方）

| 要传的东西 | 写法 |
| --- | --- |
| 字符串 | `new StringObject(vm, "skey")` |
| 字节数组 | `new ByteArray(vm, bytes)` |
| 布尔 / 数字 / null | 直接传（`false`、`0`、`null`） |
| 需要构造的 Java 对象 | `vm.resolveClass("android/content/Context").newObject(实参)` |
| 无法伪造的系统对象 | 同上但传 `null`，造一个**空壳对象** |

两个易错点：

- **空壳对象 ≠ null**。传 `null` 是空引用，so 里一调方法就崩；`newObject(null)` 造出的是一张「有类没实现」的壳子，只要 so 没真去用它的方法就能过。
- `ProxyDvmObject.createObject(vm, null)` 会直接返回 null，所以**它不能用来造空壳 Context**，空壳只能 `resolveClass(...).newObject(null)`。

## 6. 案例三：得物 AESEncrypt（要先做一步 0/1 反转）

调用链不是一步到位，得先取一个「掩码串」再喂给加密方法：

1. `com.duapp.aesjni.AESEncrypt.getByteValues()` 取出一串 0/1 字符串；
2. 把这串**反转**：`0 → 1`、`1 → 0`（课件里是逐个字符替换后重新拼接）；
3. 调 `encodeByte([BLjava/lang/String;)Ljava/lang/String;`：参数一为上一步反转后的字节数组（`ByteArray`），参数二为待加密 body。

待加密 body 是「参数名 + 值」直接首尾相连的裸串（`loginToken` + `platform` + `android` + `routerVersion` + `569` + `timestamp` + ... + `v4.74.5`），不是 `k=v&` 形式——顺序错了结果就错，取值顺序要从 Java 层拼接逻辑里抄准。

## 7. 案例四：海南航空（先 hook 找门，再 unidbg 收口）

### 7.1 定位链

- 搜 `hnairSign` → 找到 `signRequest(aVar)` → 里面调 `HNASignature.getHNASignature(5 个 String)`。
- 该方法返回的是 `A>>B>>C` 形式，按 `>>` 切开取**第 0 段**才是最终 hnairSign。
- 5 个入参靠 hook 拿：`{}`、`{}`、一大段 JSON、`21047C...`、`F6B15...`。
- 拿到 5 个值后，unidbg 里 5 个 `StringObject` 依次传入即可。

### 7.2 定位 so 的两套脚本（通用工具，值得记住）

so 可能静态注册也可能动态注册，对应两种 hook 定位法：

**动态注册**（JNI_OnLoad 里调 `RegisterNatives`）：

```javascript
// 枚举 libart.so 的符号，找 RegisterNatives（注意不同 Android 版本符号名可能不同）
var symbols = Module.enumerateSymbolsSync("libart.so");
// 按名字过滤出 RegisterNatives 的地址后 hook，读第 3 个参数（JNINativeMethod 数组）
// 每个元素是 {name, signature, fnPtr}，过滤目标类名后打印
// 用 Process.findModuleByAddress(fnPtr) 得出 fnPtr 落在哪个 so、偏移多少
```

**静态注册**（符号名即 `Java_包_类_方法`）：

```javascript
// hook libdl.so 的 dlsym，App 加载 so 时必然调用
var dlsym = Module.findExportByName("libdl.so", "dlsym");
Interceptor.attach(dlsym, {
    onEnter: function (args) { this.funcName = args[1].readCString(); },
    onLeave: function (retval) {
        if (this.funcName && this.funcName.indexOf("目标方法名") >= 0) {
            // retval 就是函数地址，反查所属 module 得到 so 名
            var m = Process.findModuleByAddress(retval);
            console.log(m.name, retval.sub(m.base));
        }
    }
});
```

这两套脚本在三个案例（海南航空、拼多多等）里反复用，属于「换了 App 只改类名/方法名」的模板。配套文件：`day27-unidbg下\代码\1-静态注册.js`、`2-动态注册.js`、`3-hook-查看入参.py`、`0-端口转发.py`。

## 9. 补环境方法论（本课最核心的一节）

### 9.1 什么时候需要补

- so 的加密全用 C 写，从不回调 Java → **不用补**（大姨妈）。
- so 里通过 JNI 回调 Java（取包名、占权限、循环 Map、new 对象）→ **必须补**（唯品会、识货、B 站、拼多多）。
- 所谓补环境 = 用 Java 代码把「C 调 Java 时环境里缺的类和方法」补完整。

### 9.2 报错信息就是 signature

unidbg 抛出的异常长这样：

```
java.lang.UnsupportedOperationException: java/util/TreeMap->entrySet()Ljava/util/Set;
```

冒号后面那一整串 `类->方法(参数)返回值` 就是**要补的签名**，也是 `if` 判断的条件。同时异常栈里的 `AbstractJni.callObjectMethod` 告诉你该重写哪个方法：

| 报错栈里的方法 | 重写谁 | 返回 |
| --- | --- | --- |
| `callObjectMethod` | `public DvmObject<?> callObjectMethod(...)` | 包裹对象 / `ProxyDvmObject.createObject(vm, 结果)` |
| `callBooleanMethod` | `public boolean callBooleanMethod(...)` | 直接 `return true/false` |
| `callStaticVoidMethodV` | `public void callStaticVoidMethodV(...)` | 直接 return，什么都不做 |

### 9.3 完整范式：唯品会循环 Map 的整条链

so 内部要用传入的 map 取 key/value，C 写循环不好用，于是回头调 Java 的迭代器。所以必须把 Java 里那段循环用到的每个方法都补上：

```java
Map map = ...;
Set set = map.entrySet();
Iterator it = set.iterator();
while (it.hasNext()) {
    Map.Entry e = (Map.Entry) it.next();
    e.getKey(); e.getValue();
}
```

对应补 6 个签名（顺序就是报错顺序）：

```java
@Override
public DvmObject<?> callObjectMethod(BaseVM vm, DvmObject<?> dvmObject, String signature, VarArg varArg) {
    if (signature.equals("java/util/TreeMap->entrySet()Ljava/util/Set;")) {
        TreeMap map = (TreeMap) dvmObject.getValue();      // 包裹对象先 getValue 还原
        return ProxyDvmObject.createObject(vm, map.entrySet());
    }
    if (signature.equals("java/util/Set->iterator()Ljava/util/Iterator;")) {
        Set set = (Set) dvmObject.getValue();
        return vm.resolveClass("java/util/Iterator").newObject(set.iterator());
    }
    if (signature.equals("java/util/Iterator->next()Ljava/lang/Object;")) {
        Iterator it = (Iterator) dvmObject.getValue();
        return ProxyDvmObject.createObject(vm, it.next());
    }
    if (signature.equals("java/util/Map$Entry->getKey()Ljava/lang/Object;")) {
        Map.Entry e = (Map.Entry) dvmObject.getValue();
        return ProxyDvmObject.createObject(vm, e.getKey());
    }
    if (signature.equals("java/util/Map$Entry->getValue()Ljava/lang/Object;")) {
        Map.Entry e = (Map.Entry) dvmObject.getValue();
        return ProxyDvmObject.createObject(vm, e.getValue());
    }
    return super.callObjectMethod(vm, dvmObject, signature, varArg);   // 务必保留
}

@Override
public boolean callBooleanMethod(BaseVM vm, DvmObject<?> dvmObject, String signature, VarArg varArg) {
    if (signature.equals("java/util/Iterator->hasNext()Z")) {
        return ((Iterator) dvmObject.getValue()).hasNext();   // 布尔直接返回
    }
    return super.callBooleanMethod(vm, dvmObject, signature, varArg);
}
```

三条铁律：

1. **`super.xxx(...)` 绝不能删**，父类里已经默认补了大量环境，删了就什么都跑不动。
2. 补的对象往往要「喂回给 C」，返回值统一用 `ProxyDvmObject.createObject(vm, 结果)` 最省事，它内部按 `byte[]/short[]/int[]/float[]/double[]/String/数组/普通对象` 自动转成合适的 DvmObject。
3. 想知道 `Object` 实际是什么类型，`getClass()` 打一下，确认后可以换成更精确的包裹（如 `new StringObject(vm, s)`），但用 `createObject` 兜底永远不出错。

### 9.4 三类 Java 对象，三种补法

| 类型 | 例子 | 补法 |
| --- | --- | --- |
| JDK 对象 | `TreeMap`、`Iterator`、`Map.Entry`、`String` | 直接用 JDK 真实类 new 出来补，通用、可复用 |
| 安卓 SDK 对象 | `Context`、`Application`、`ActivityThread`、`PackageManager`、`TelephonyManager` | 无法伪造，先 `newObject(null)` 造空壳，报什么方法补什么方法 |
| App 自定义对象 | `SignedQuery`、`EU` | 两种走法：把反编译的类整段 copy 进工程 new 出来；或只在构造/方法调用里把参数取走 |

系统对象记忆锚点：

- `ActivityThread` = 进程主线程入口，`currentActivityThread()` 是很多 SDK 的起点；
- `Application` = 应用对象，`getApplication()` 之后通常接着 `getPackageManager()`、`getPackageName()`（unidbg 里包名可直接 `vm.getPackageName()`）、取设备信息、读写缓存；
- `PackageManager` = 装包/删包/查权限/查已装应用。
- 查 AOSP 源码：`aospxref.com`、`androidxref.com`（判断某个 SDK 类该返回什么值）。

### 9.5 定位「这次该补哪个方法」的顺序

1. 开 `vm.setVerbose(true)`，看 C 最后一步想调什么；
2. 看异常 type：`UnsupportedOperationException` 一律是环境缺失，签名就在消息里；
3. 补一个 → 重跑 → 下一个报错 → 继续补，直到跑通；
4. 同类报错（如 `String->replaceAll`）注意 `VarArg` 取值：`varArg.getObjectArg(0).getValue()` 拿第 1 个参数。

## 10. 案例六：唯品会（反射链 + Map 补环境）

### 10.1 skey

- 链路：`KeyInfoFetcher.getInfo` → 反射调 `KeyInfo.getInfo` → native `getNavInfo(Context, String)`，第二参固定 `"skey"`。
- 结论：hook 多次换设备发现返回值恒为 `6692c461c3810ab150c9a980d0c275ec`，**可以直接写死**——先验证再决定，能写死就别调 so。
- if 不写死：`com/vip/vcsp/KeyInfo` + `getNavInfo(Landroid/content/Context;Ljava/lang/String;)Ljava/lang/String;`，空壳 Context + `new StringObject(vm,"skey")`，此时**不用补环境**。

### 10.2 api_sign（authorization）

完整链路：

```
builder.addHeader("Authorization", "OAuth api_sign=" + str)
  → b.b(context, treeMap, str, str2)      // 顺手把 skey 塞进 treeMap
  → a(context, treeMap, str)
  → VCSPSecurityBasicService.apiSign(context, treeMap, str)
  → VCSPSecurityConfig.getMapParamsSign(...)   // 遍历 map 找 user_token，决定 str 取值
  → getSignHash(...) → gs(...)                 // 反射
  → KeyInfo.gs(context, map, str, boolean)
  → native gsNav(Context, Map, String, boolean)
```

`gs` 里那四句反射要能背下来：

```java
clazz = KeyInfo.class;
object = clazz.newInstance();
gsMethod = clazz.getMethod("gs", Context.class, Map.class, String.class, Boolean.TYPE);
gsMethod.invoke(object, context, map, str, z);
```

本质就是执行 `KeyInfo.gs`，然后进 native `gsNav`，传入待签参数 map，返回签名串。

unidbg 侧：调 `com/vip/vcsp/KeyInfo` 的 `gsNav(Landroid/content/Context;Ljava/util/Map;Ljava/lang/String;Z)Ljava/lang/String;`，参数是空壳 Context、构造好的 TreeMap、token secret 或 null、`false`。这一路必然报 `TreeMap->entrySet` 相关的错，按 9.3 那六段补完即可。

## 11. 案例七：B 站 SignedQuery（返回自定义类型）

- 目标：`static native SignedQuery s(SortedMap<String, String>)`。返回值是 App 自定义类，不是字符串，所以拿不到 `getValue()`。
- 这个类有两个字段：`SignedQuery(String rawParams, String sign)`，即 so 在内部把 sign 算好后回头 new 这个对象。

两种破法：

**方案一（省事）**：在 `newObject` 补环境里，直接把构造函数的第 2 个参数打印出来——那就是 sign。

```java
if (signature.equals("com/bilibili/nativelibrary/SignedQuery-><init>(Ljava/lang/String;Ljava/lang/String;)V")) {
    System.out.println(varArg.getObjectArg(1).getValue());   // 第 2 个参数就是 sign
    // 仍要返回一个对象给 C，否则后续崩
}
```

**方案二（完整）**：把反编译出来的 `SignedQuery` 类整段 copy 进工程（含 `r(Map)` 排序拼串、`b/c` 两个 URL 编码方法），自己 `new SignedQuery(param, sign)` 后 `toString()`，得到的才是参数串 + `&sign=` 的完整结果。

B 站这一路要补四项（报错顺序）：

1. `java/util/Map->isEmpty()Z` → `callBooleanMethod` 直接 return；
2. `java/util/Map->get(Ljava/lang/Object;)Ljava/lang/Object;` → `callObjectMethod`，key 从 `varArg.getObjectArg(0).getValue()` 取，返回 `ProxyDvmObject.createObject(vm, map.get(key))`；
3. `com/bilibili/nativelibrary/SignedQuery->r(Ljava/util/Map;)Ljava/lang/String;` → `callStaticObjectMethod`（静态方法，注意不是 callObjectMethod），返回排好序拼好的串；
4. `SignedQuery-><init>(Ljava/lang/String;Ljava/lang/String;)V` → `newObject`，在这里截 sign。

判断依据只有一条：**异常栈里出现 `callStaticObjectMethod` 就重写静态版本，不要硬套实例版本的签名**。

## 12. 案例八：拼多多 anti-token（SDK 对象巨量补环境）

### 12.1 定位链

- 搜 `anti-token` → `hashMap.put("anti-token", f)`。
- `f` 是接口方法 `String f(Context, Long)`，实现类 `u` 里调 `SecureNative.deviceInfo2(context, Long.valueOf(c))`。
- 再往下：`public static native String info2(Context, long)`，c 是时间戳。
- so：`libpdd_secure.so`（**64 位**），用 7.2 的动态注册脚本定位（目标类 `com.xunmeng.pinduoduo.secure.DeviceNative`）。

### 12.2 抓包小技巧（App 有防抓包时）

SocksDroid 做转发 + 关掉手机全局代理 + **先不开 Charles 让 App 处于无网状态** + 再开 Charles 点加载。目的：让 App 走一次「首次无网」的容错分支，绕开代理检测后再吃到流量。

### 12.3 补环境清单（按报错顺序，可直接当模板抄）

| 签名 | 返回 |
| --- | --- |
| `com/tencent/mars/xlog/PLog->i(Ljava/lang/String;Ljava/lang/String;)V` | 直接 return（重写 `callStaticVoidMethodV`） |
| `android/content/Context->checkSelfPermission(Ljava/lang/String;)I` | `-1`（PERMISSION_DENIED；GRANTED 是 0） |
| `android/content/Context->getSystemService(Ljava/lang/String;)Ljava/lang/Object;` | `vm.resolveClass("android/telephony/TelephonyManager").newObject(null)` |
| `TelephonyManager->getSimState()I` | `5`（SIM_STATE_READY） |
| `TelephonyManager->getSimOperatorName()Ljava/lang/String;` | `"中国电信"` |
| `TelephonyManager->getSimCountryIso()Ljava/lang/String;` | `"cn"` |
| `TelephonyManager->getNetworkType()I` | `13` |
| `TelephonyManager->getNetworkOperator()Ljava/lang/String;` | `"46003"` |
| `TelephonyManager->getNetworkCountryIso()Ljava/lang/String;` | `"cn"` |
| `TelephonyManager->getDataState()I` | `0` |
| `TelephonyManager->getDataActivity()I` | `4` |
| `com/xunmeng/pinduoduo/secure/EU->gad()Ljava/lang/String;` | 写死 `7202111111112f2` |
| `android/os/Debug->isDebuggerConnected()Z` | `false`（`callStaticBooleanMethod`） |
| `java/lang/Throwable-><init>(...)V` / `getStackTrace()` / `StackTraceElement->getClassName()` | 建个真 Throwable 返回或在空壳上兜底 |
| `java/lang/String->replaceAll(...)` | `callObjectMethodV`，`vaList.getObjectArg(i)` 取参 |
| `java/io/ByteArrayOutputStream` 的 `<init>` / `write` / `close` | 用真实 JDK 类补 |
| `java/util/zip/GZIPOutputStream` 的 `<init>` / `write` / `finish` / `close` | 用真实 JDK 类补 |

要点：**SDK 对象的返回值要让 so 觉得"这是一台正常手机"**——SIM 就绪、运营商中国电信、网络类型 13、数据已连接。返回值瞎给会导致签名算出来和服务端不一致，且不报错，最难查。

### 12.4 该案例的调用终点

`info2(Context, long)` → 返回一长串 Base64 的 anti-token，直接塞进请求头。时间戳入参用「当前毫秒」还是「抓包里的值」要跟服务端校验规则对齐，先拿抓包值跑通再换动态时间。

## 13. 主动调用 C 函数（绕过 Java 层直接调 so）

### 13.1 三种目标定位方式

```java
// ① 符号名（静态注册或 so 里自带的导出符号）
Number n = module.callFunction(emulator, "Java_com_yoloho_libcore_util_Crypt_encrypt_1data", args...);
// ② 文件偏移（IDA 里看到的地址）；32 位 so 要 +1（Thumb 指令集）
Number n2 = module.callFunction(emulator, 0x2414 + 1, args...);
// ③ Symbol 对象
Symbol sym = module.findSymbolByName("符号名", true);
Number n3 = module.callFunction(emulator, sym, args...);
// 需要地址/指针时
long addr = sym.getAddress();
Pointer p = sym.createPointer(emulator);
```

### 13.2 两个固定认知

- **只加载一个 so 时，基址恒为 `0x40000000`**，所以「IDA 偏移」和「运行时地址」相差一个常量；想改基址去改 `com/github/unidbg/memory/Memory.java`。
- 返回值 `Number` 是 unidbg 内部对象 id（不是 0 就是负数/句柄），取真实值：`vm.getObject(n.intValue()).getValue()`。

### 13.3 传参两种形式

```java
// 位置传参：逐个跟在后面
module.callFunction(emulator, sym, vm.getJNIEnv(), vm.addLocalObject(类对象), 0,
                    vm.addLocalObject(new StringObject(vm, "明文")), 85);

// 数组传参：参数多时更清爽
List<Object> args = new ArrayList<>();
args.add(vm.getJNIEnv());
args.add(vm.addLocalObject(vm.resolveClass("com/yoloho/libcore/util/Crypt")));
args.add(0);
args.add(vm.addLocalObject(new StringObject(vm, "明文")));
args.add(85);
module.callFunction(emulator, sym, args.toArray());
```

规则：JNI 函数前两个参数固定是 `JNIEnv*` 和 `jclass/jobject`，**必须用 `vm.getJNIEnv()` 和 `vm.addLocalObject(...)` 包一层**，否则引用无效。大姨妈案例的四种写法就是「符号 / 偏移」×「位置 / 数组」的组合。

### 13.4 纯 C 函数调用（不是 JNI，没有 env）

```java
UnidbgPointer in  = memory.malloc(100, false).getPointer();   // 入参缓冲区
in.write("待加密明文".getBytes());
UnidbgPointer out = memory.malloc(100, false).getPointer();   // 出参缓冲区
module.callFunction(emulator, 0x1DA0, 0, in, 85, out);        // 第一个 0 是占位（无 JNIEnv）
System.out.println(out.getString(0));                         // 从 buffer 读结果
```

区别在于：**纯 C 函数不传 `vm.getJNIEnv()`**，参数就是 C 原型本身；字符串用 `malloc + write`，结果用 `getString(0)` 读。

## 14. 打包成 jar 交给 Python

### 14.1 出包

1. IDEA → Project Structure → **Artifacts** → 加一个 `JAR → From modules with dependencies`，Main Class 选入口类，输出目录默认 `out/artifacts/...`。
2. Build → Build Artifacts → Build，产物在 `out/` 下，**`unidbg-0.9.7.jar` 是主 jar**。
3. 把 `apks/` 目录一起复制到 jar 同级目录（jar 里的相对路径 `apks/xxx.apk` 是按工作目录找的）。
4. 终端验证：`java -jar unidbg-0.9.7.jar`，能打印结果说明打包成功。

### 14.2 参数化（让 Python 能传参）

```java
public static void main(String[] args) {
    Bili b = new Bili();
    String body = args[0];          // Python 传进来的请求体
    System.out.println(b.sign(body));
}
```

三个坑（B 站案例踩全了）：

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `&` | 请求体里的 `&` 被 shell 当后台符，参数被截断 | 整个参数用**双引号**包起来 |
| 空格 | 明文里有空格会被拆成多个 args | 同上，双引号包住 |
| 超长字符串 | 终端参数长度上限，长密文传不进去 | 写临时文件，Java 侧读文件；或 8.3 的切片拼字符串 |

另有一条根本限制：**Python → Java 只能传字符串**，所以 byte[] 类的入参通常在 Java 侧做 Base64 解码后再用。

### 14.3 Python 调用

```python
import subprocess

body = "actual_played_time=0&aid=466565149&...&ts=1647952932"
cmd = f'java -jar unidbg-0.9.7.jar "{body}"'          # 双引号必须加
res = subprocess.check_output(cmd, shell=True, cwd="unidbg_0_9_7_jar")
signature = res.strip().decode("utf-8").split("\n")[-1]   # 最后一行才是结果
```

`split("\n")[-1]` 是惯例：unidbg 会往 stdout 打大量日志，**结果永远在最后一行**，Java 侧用 `System.out.println` 输出。识货案例同样结构，只是入参换成长 Base64 密文（走文件或引号 + 切片）。

## 15. 坑清单

1. **位数不匹配**：so 在 `arm64-v8a` 却用 `for32Bit()`，加载直接失败，报错信息不一定直白。
2. **路径带中文**：unidbg 项目、APK、so 路径都不能有中文。
3. **静态 vs 动态注册搞混**：动态注册不调 `callJNI_OnLoad` 会报「找不到方法」，静态注册调了也无害但没必要。
4. **`callJNI_OnLoad` 的返回值**：部分 so 的 `JNI_OnLoad` 里有初始化逻辑（如申请全局引用），漏调会导致后续调用崩溃或结果异常。
5. **空壳 Context 与 null 混用**：`ProxyDvmObject.createObject(vm, null)` 返回 null，不能代替空壳；真 null 会让 so 段错误。
6. **`super` 被删**：补环境方法里删掉 `super.xxx` 等于把框架自带的几百条补环境全废掉。
7. **异常栈里的方法名被忽略**：`callStaticObjectMethod` / `callStaticVoidMethodV` / `callObjectMethodV` 都是不同的重写点，签名对了但方法名不对照样不生效。
8. **返回值类型判断错**：`Object` 看起来像字符串，实际可能是 `byte[]`；`getClass()` 确认后再决定用 `StringObject` 还是 `ByteArray`。
9. **32 位偏移少 +1**：`callFunction(emulator, 0x2414, ...)` 在 Thumb 下必然崩，`0x2415` 才对。
10. **结果取错行**：Python 端忘了 `split("\n")[-1]`，把日志当签名。
11. **参数顺序/编码**：得物那种裸拼串、识货那种 URL-safe Base64，差一个字符结果全错且不报错——这类问题只能靠「抓包原文 + 同一时刻参数」对齐验证。
12. **写死的值要留证据**：唯品会 skey 能写死是因为「换设备 hook 多次值不变」，没验证就写死等于埋雷。

## 16. 关键知识清单

- unidbg = unicorn 打底的 Java 模拟器，加载 APK + so 后可直接调用 native 方法，交付物是 **Python + jar**。
- 破解 so 加密四路：硬核逆向 / frida-rpc / 自写 APK / unidbg；只有 unidbg 同时免真机、免读算法、易交付。
- 六步模板：`for32Bit/for64Bit + setProcessName` → `getMemory` → `AndroidResolver(19|23)` → `createDalvikVM(apk) + setJni(this)` → `loadLibrary(so) + callJNI_OnLoad` → `getModule()`。
- JNI 签名规则：`Z I J V [B Ljava/lang/String; L包/类;`，方法名 + 签名才能定位。
- 传参：字符串 `StringObject`、字节数组 `ByteArray`、基本类型直传、自定义类型 `resolveClass().newObject()`、系统对象先空壳。
- 判「要不要补环境」只看一件事：so 有没有回调 Java。全 C 实现不用补。
- 补环境核心：**报错信息就是 signature**，看异常栈决定重写 `callObjectMethod` / `callBooleanMethod` / `callStaticObjectMethod` / `callStaticVoidMethodV`，按报错顺序逐个补，`super` 必须保留。
- `ProxyDvmObject.createObject(vm, 任意结果)` 是万能回传方式，但对 `null` 返回 `null`，不能造空壳。
- 循环 Map 要补整条链：`TreeMap->entrySet` → `Set->iterator` → `Iterator->next` / `hasNext` → `Map$Entry->getKey` / `getValue`。
- 三类对象三种补法：JDK 对象直接补；SDK 对象空壳 + 逐个方法；App 自定义类 copy 进来或只在构造处截参数。
- 返回自定义类型（B 站 SignedQuery）时：**sign 就在构造函数第 2 个参数里**，打印即可，不必还原整个类。
- 定位 so 两套 frida 脚本：动态注册 hook `libart.so` 的 `RegisterNatives`；静态注册 hook `libdl.so` 的 `dlsym`，`Process.findModuleByAddress(retval)` 反查 so 名。
- 主动调用：`module.callFunction(emulator, 符号|偏移|Symbol, args...)`，32 位偏移 +1，单 so 基址 `0x40000000`，JNI 函数首两参必须 `getJNIEnv()` + `addLocalObject`，纯 C 函数用 `memory.malloc` 造缓冲区。
- 打包：Artifacts → `out/` 里的 `unidbg-0.9.7.jar` + 同级 `apks/` → `java -jar`；参数走 `main(String[] args)`，`&` 和空格靠双引号、超长串靠文件、Python 侧取 stdout 最后一行。
- 抓包受阻可试：SocksDroid 转发 + 关全局代理 + 先断网后开抓包工具点加载。
- 弱化 so 的思路优先级：hook 能拿常量的（唯品会 skey）就写死 → 能 unidbg 跑的再跑 → 最后才考虑读 so 逻辑。
