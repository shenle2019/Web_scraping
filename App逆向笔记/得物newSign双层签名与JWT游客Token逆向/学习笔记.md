## 一、目标与一句话结论

采集首页推荐流：

```
GET https://app.dewu.com/sns-rec/v1/recommend/all/feed
```

抓包看到三类"要破"的东西：

| 字段 | 位置 | 是否必须 | 结论 |
| --- | --- | --- | --- |
| `X-Auth-Token` | 请求头 | 必须，不带不行 | JWT，游客接口 `getVisitorUserId` 的响应头直接给 |
| `newSign` | 查询参数 | 这个接口可以不带 | 作为练手，其他接口要带 |
| `duuuid` / `shumeiid` | 请求头 | 可以不带 | 设备标识，可自造 |

`newSign` 的生成链路一句话：

```
请求参数 + uuid/platform/v/loginToken/timestamp
  → 按 key 字典序排序，拼成 key1value1key2value2...
  → AES-128-ECB/PKCS5 加密，key = d245a0ba8d678a61
  → Base64
  → MD5（32 位小写十六进制）
```

## 四、抓包：SocksDroid 转发

这个 App 做了代理检测，手机系统代理一开就抓不到业务请求。课件方案：

1. 手机设置里**删掉**系统代理（这一步必须先做）
2. 打开 SocksDroid，填 PC 的 IP + Charles 端口，右上角开关打开
3. PC 端 Charles 确认监听端口一致
4. 再操作 App，抓到的请求走 SocksDroid 的 VPN 层转发

抓到的 feed 请求：

```
GET /sns-rec/v1/recommend/all/feed

  abType=social_brand_strategy_v454
```

## 五、newSign 定位：静态搜索 + Hook 验证

### 5.1 jadx 搜索

搜字符串 `"newSign"`，出来 8 处，其中 5 处在同一个类里。点进去是
`WebRequestInterceptor`——典型的 OkHttp 拦截器，重写了 `intercept`，在里面对请求头、请求体、查询参数做手脚。

静态阅读能看到类似：

```java
host.addQueryParameter("newSign", RequestUtils.c(hashMap2, currentTimeMillis));
```

也就是说：`newSign` 由 `RequestUtils.c(Map, long)` 生成，入参是"除 newSign 外的全部查询参数"和当前时间戳。

### 5.2 Hook 验证

```js
var RequestUtils = Java.use("com.shizhuang.duapp.common.utils.RequestUtils");
RequestUtils.c.implementation = function (map, j2) {
    console.log("1.", map);                 // [object Object]
    console.log("2.", JSON.stringify(map)); // <instance: java.util.Map, $className: java.util.HashMap>
    var HashMap = Java.use("java.util.HashMap");
    var obj = Java.cast(map, HashMap);
    console.log("3.", obj.toString());      // 键值对能看了
    var res = this.c(map, j2);
    console.log("4.", res);
    return res;
};
```

课件里的输出：

```
{abValue=1, deliveryProjectId=0, abRectagFengge=0, abType=social_brand_strategy_v454,
 limit=20, lastId=, abRecReason=0, abVideoCover=2}
newSign = 16aa2e250ac6c28c3166cce3d0561be8
```

Hook 出来的值和抓包一致，位置就确定了。

> 注意：静态阅读会被 `PatchProxy.proxy(...)` 干扰。这是美团系的热修复代理框架，真正的调用点未必能直接搜到，所以 Hook 验证比硬读代码省时间。

## 六、RequestUtils.c 的核心逻辑

去掉热修复壳之后是五步：

```java
map.put("uuid", DuHttpConfig.d.getUUID());
map.put("platform", "android");
map.put("v", DuHttpConfig.d.getAppVersion());
map.put("loginToken", DuHttpConfig.d.getLoginToken());
map.put("timestamp", String.valueOf(j2));

ArrayList list = new ArrayList(map.entrySet());
Collections.sort(list, (a, b) -> a.getKey().compareTo(b.getKey()));

StringBuilder sb = new StringBuilder();
for (Map.Entry e : list) {
    sb.append(e.getKey()).append(e.getValue());
}
return a(AESEncrypt.encode(DuHttpConfig.f15796c, sb.toString()));
```

两个细节：

1. `map.put` 是**原地修改**。所以最终发出去的 URL 上也会带 `uuid/platform/v/loginToken/timestamp`，newSign 和实际参数必须是同一套值。
2. 排序是 `String.compareTo`，即 key 的字典序（`abRecReason` < `abType` < `deliveryProjectId` < `lastId` < `limit` < `loginToken` < `platform` < `timestamp` < `uuid` < `v`）。

`a(...)` 就是 MD5，返回 32 位小写 hex。

## 七、AESEncrypt.encode：一层障眼法

Java 层长这样：

```java
public static String encode(Object obj, String str) {
    String byteValues = getByteValues();          // native，返回 0101 串
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < byteValues.length(); i++) {
        sb.append(byteValues.charAt(i) == '0' ? '1' : '0');   // 逐位取反
    }
    return encodeByte(str.getBytes(), sb.toString());         // native
}
```

第一眼看像是"用 0101 串当密钥"，实际不是：

- `getByteValues()` 多次 Hook 返回同一个值，是固定串；
- so 里的 `encode` 压根没使用第二个参数；
- 真正的 key 是 so 内部 `getValue()` 返回的 `d245a0ba8d678a61`。

所以 0101 串和取反都是干扰项，不用花时间还原。

## 八、libJNIEncrypt.so：动态注册与 encode

### 8.1 找注册关系

IDA 打开 `libJNIEncrypt.so`，Exports 里没有 `Java_com_duapp_aesjni_AESEncrypt_*`，说明是**动态注册**。

`JNI_OnLoad` 里：

```c
v4 = (*env)->FindClass(env, "com/duapp/aesjni/AESEncrypt");
(*env)->RegisterNatives(env, v4, off_15010, 8);
```

双击 `off_15010` 看 `JNINativeMethod` 数组，找到 `encodeByte` 对应的 C 函数 `encode`。

### 8.2 encode 做了什么

```c
jstring encode(JNIEnv *env, jobject thiz, jbyteArray arr, jstring s) {
    const char *utf = env->GetStringUTFChars(env, s, 0);
    int key = getValue();                       // 固定 key
    int len = env->GetArrayLength(env, arr);
    jbyte *bytes = env->GetByteArrayElements(env, arr, 0);
    char *buf = malloc(len + 1);
    memcpy(buf, bytes, len);
    buf[len] = 0;
    const char *out = AES_128_ECB_PKCS5Padding_Encrypt(buf, key);
    return env->NewStringUTF(env, out);
}
```

`AES_128_ECB_PKCS5Padding_Encrypt` 内部：

- 按 16 字节分组循环 `AES128_ECB_encrypt`
- 最后 `b64_encode`

### 8.3 用 Hook 确认，不用硬啃汇编

```js
var addr = Module.findExportByName("libJNIEncrypt.so", "AES_128_ECB_PKCS5Padding_Encrypt");
Interceptor.attach(addr, {
    onEnter: function (args) {
        console.log("明文:", args[0].readUtf8String());
        console.log("key :", args[1].readUtf8String());
    },
    onLeave: function (ret) {
        console.log("密文:", ret.readUtf8String());
    }
});
```

课件输出：

```
明文: loginTokenplatformandroidrouterVersion569timestamp1690882175032uuidaa39fda5dfb88d79v4.74.5
key : d245a0ba8d678a61
密文: knGGXR0bR7LQn4eRCvJsdYgYdJOA87lB9pdSj5LyZPp5O1D7em+oNjsR/hxGs9U+qpTFl9wV3uwai4JQsrMnVtb6Kw/bXTHjZ7jViuThKQT+5aY2HvkoCjEoBzHTyfw1
```

把密文再做一次 MD5，就等于抓包里的 `newSign`。到这里算法闭环。

> 课件的两份笔记分别用 32 位和 64 位 so 讲，注册流程一样，只是寄存器/函数签名长相不同；看自己 APK 里带的是哪个架构即可。

## 九、Python 复刻

### 9.1 三个基础函数

```python
def md5(b):
    return hashlib.md5(b).hexdigest()

def aes_encrypt(s):
    aes = AES.new(key=b"d245a0ba8d678a61", mode=AES.MODE_ECB)
    return aes.encrypt(pad(s.encode(), 16))
```

排序拼接：

```python
ordered = "".join(f"{k}{d[k]}" for k in sorted(d))
```

Base64 有一个坑：`base64.encodebytes()` 每 76 字符会插 `\n`，必须去掉：

```python
b64 = base64.encodebytes(aes_encrypt(ordered)).replace(b"\n", b"")
sign = md5(b64)
```

### 9.2 uuid 从哪来

`DuHttpConfig.getUUID()` 最终落到 `HPDeviceInfo.a()`：

- 有 `READ_PHONE_STATE` 权限：`TelephonyManager.getDeviceId()`（IMEI）
- 没权限：`Settings.Secure.getString(resolver, "android_id")`

课件结论：这个值服务端不校验真实性，自己生成 16 位十六进制即可：

```python
"".join(random.sample("0123456789ABCDEF", 2) for _ in range(8)).lower()
```

### 9.3 拼装顺序

```python
uid = create_android_id()
ctime = str(int(time.time() * 1000))

params = {"lastId": "1", "limit": "20"}
sign_map = dict(params)
sign_map.update({"loginToken": "", "platform": "android",
                 "timestamp": ctime, "uuid": uid, "v": "4.74.5"})

ordered = "".join(f"{k}{sign_map[k]}" for k in sorted(sign_map))
params["newSign"] = md5(base64.encodebytes(aes_encrypt(ordered)).replace(b"\n", b""))
```

请求时 URL 参数是 `params`，`timestamp` 用同一个 `ctime`，否则签名对不上。

## 十、X-Auth-Token：JWT 游客 token

### 10.1 token 结构

三段 Base64，用 `.` 分隔：

```
eyJhbGciOiJSUzI1NiJ9 . eyJpYXQiOi... . Ql_NS3XIrpFSTtK9...
      header                payload          signature
```

payload 解出来：

```json
{"iat":1723126022,"exp":1754662022,"iss":"45f14913ce37cf60",
 "sub":"45f14913ce37cf60","uuid":"45f14913ce37cf60",
 "userId":2321218292,"isGuest":true}
```

- `isGuest=true`：游客 token，不需要登录
- `uuid` 就是设备 id，和 newSign 里用的是同一个
- `exp` 约为签发后一年
- 第三段是 RSA 签名，逆不出东西，也没必要逆

### 10.2 从哪个接口拿

token 是后端生成的，所以找"哪个请求的响应头带 X-Auth-Token"：

```
POST https://app.dewu.com/api/v1/app/user_core/users/getVisitorUserId
body: {"loginToken":"","newSign":"...","platform":"android",
       "timestamp":"...","uuid":"...","v":"4.74.5"}
响应头: X-Auth-Token
```

这个请求自己也要 newSign，但 body 只有 5 个字段（没有 lastId/limit 那些业务参数），签名方式完全一样。

### 10.3 拿 token 再请求 feed

```python
token = requests.post(url, json=param_dict, headers={...}, verify=False).headers["X-Auth-Token"]

requests.get(
    "https://app.dewu.com/sns-rec/v1/recommend/all/feed/",
    params=reply_param_dict,          # 含 newSign
    headers={"X-Auth-Token": token, "User-Agent": "duapp/4.74.5(android;11)"},
    verify=False
)
```

课件里 header 是直接放 token 串；有的抓包会带 `Bearer ` 前缀，以实际抓到的为准，两种都试一次即可。

## 十一、完整链路

```
1. 断网启动 App → 进首页 → 联网
2. SocksDroid 转发，删掉系统代理
3. 抓 feed：看到 newSign / X-Auth-Token
4. jadx 搜 newSign → WebRequestInterceptor → RequestUtils.c
5. Hook RequestUtils.c，确认入参与输出
6. 读 c：补 5 个字段 → 排序 → 拼接 → AES → MD5
7. AESEncrypt.encode 是 native → IDA 找 JNI_OnLoad → 动态注册
8. Hook AES_128_ECB_PKCS5Padding_Encrypt：拿到明文、key、密文
9. Python 复刻 AES-ECB + Base64 + MD5
10. 请求 getVisitorUserId（同样要 newSign）→ 响应头拿 X-Auth-Token
11. 带 token + newSign 请求 feed
```

## 十二、坑与要点

| 坑 | 说明 |
| --- | --- |
| `console.log(map)` 只出 `[object Object]` | 先 `Java.cast(map, Java.use("java.util.HashMap"))` 再 `.toString()` |
| 静态搜不到调用点 | 有 `PatchProxy` 热修复代理，直接 Hook 验证更快 |
| 以为 0101 串是密钥 | `getByteValues()` 是干扰项，so 里没用第二个参数 |
| Base64 多出换行 | `encodebytes` 每 76 字符插 `\n`，必须 `replace(b"\n", b"")` |
| 排序用插入顺序 | 必须按 key 字典序，`sorted(d)` |
| timestamp 不一致 | 签名用的和 URL 发出去的必须是同一个值 |
| 只改 URL 参数不重算签名 | 服务端按收到的参数重算，`lastId` 变了就要重签 |
| 以为 feed 必须要 newSign | 课件实测这个接口可以不带，但别的接口要 |
| 直接开系统代理抓不到 | App 有代理检测，必须 SocksDroid 在 VPN 层转发，且先删系统代理 |
| Frida attach 不上 | 进程名是 `得物(毒)`；先做 27042/27043 端口转发 |
| Hook native 函数拿不到地址 | 用 `Module.findExportByName("libJNIEncrypt.so", "AES_128_ECB_PKCS5Padding_Encrypt")`，so 是动态注册但导出符号还在 |
| 换版本就失效 | key、字段、接口都可能变；这份记录只对应 4.74.5 |

## 十三、关键知识清单

- `newSign` = MD5( Base64( AES-128-ECB-PKCS5( 排序拼接串, key=d245a0ba8d678a61 ) ) )
- 排序是 key 的字典序，拼接是 `key + value` 直接相连，没有分隔符
- 参与签名的固定字段：`uuid / platform / v / loginToken / timestamp`
- `uuid` 可自造 16 位 hex，服务端不验真
- `X-Auth-Token` 是 JWT，游客 token 从 `getVisitorUserId` 响应头取，payload 里 `isGuest=true`
- JWT 第三段是 RSA 签名，不需要逆，拿到即可用
- 定位签名的通用套路：搜字段名 → 找拦截器 → Hook 生成函数 → 对抓包值 → 读 Java 逻辑 → native 看 so → Hook 导出函数确认
- native 层识别静态/动态注册：Exports 有没有 `Java_包名_类名_方法名`，没有就看 `JNI_OnLoad` 的 `RegisterNatives`
- 干扰项识别：固定返回值、传入却没被使用的参数，优先怀疑是障眼法

> 本笔记只记录课件机制与代码思路，没有重新跑 APK、没有复算密文；课件里给出的 Python 结果与 Hook 输出一致，属于课件记录。
