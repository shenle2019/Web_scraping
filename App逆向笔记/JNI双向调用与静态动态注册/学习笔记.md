## 一、这一课在知识线上的位置

day12 是 JNI 的第一次接触：建工程、跑通一个加法、把自己写的 so 反编译看一眼。day13 把这套动作系统化，补上四块：

- **类型与签名**：Java 类型、Native 类型、JNI 签名三者的对照表，以及方法签名的书写规则。
- **Java 调 C 的六种数据形态**：数字、字符串（指针法/数组法）、拼接、字符转 hex、字节数组转 hex。
- **C 调 Java**：反射式三步（找类→找方法→执行），静态方法与成员方法两条路径。
- **静态注册 vs 动态注册**：对应关系写在函数名里，还是写在 `JNI_OnLoad` 的注册表里——这直接决定逆向时怎么在 so 里定位加密函数。

day12 笔记已记过五步接入流程、`Java_包_类_方法` 命名规则、jadx + IDA 反编译链路，本篇只记增量，不重复。

## 二、为什么要 JNI：课件给的动机

这条逻辑在第 1 节被讲透，值得原样记住：

- 如果加密全用 Java 写，用 jadx 反编译 apk 就等于拿到源码，加密逻辑一眼看穿，直接破。
- 把真正的加密逻辑用 C 实现、Java 只负责调用，jadx 里只剩一行 `native` 声明，**方法体根本不在 dex 里**，破不了，必须下沉到 so 读汇编。

所以 JNI 在商业 App 里的第一职能不是性能，是**把代码挪出反编译工具的可视范围**。这一课之后的所有 so 案例，都是在这条线上加难度。

## 三、建工程与七步接入

课堂笔记给的是 7 步版，比 day12 的五步更贴工程实际：

| 步 | 动作 | 关键点 |
| --- | --- | --- |
| 1 | 在 `cpp` 目录建 `utils.c` | 后缀必须是 `.c`（不是 `.cpp`） |
| 2 | 新建 `Utils.java` | 包名决定 C 函数前缀 |
| 3 | `static { System.loadLibrary("utils"); }` | 名字映射到 `libutils.so` |
| 4 | `public static native int add(int a, int b);` | native 方法无方法体 |
| 5 | 改 `CMakeLists.txt` | `add_library(utils SHARED utils.c)` + `find_library(log-lib log)` + `target_link_libraries(utils ${log-lib})` |
| 6 | 在 `utils.c` 写 `Java_包_类_方法` | 包名里的 `.` 换成 `_` |
| 7 | `MainActivity` 里调用 `Utils.add(10, 20)` | 结果显示到 TextView |

**加载名与产物名的映射**（课堂笔记专门点了一句）：`System.loadLibrary("utils")` → `libutils.so`，`System.loadLibrary("dynamic")` → `libdynamic.so`。加载名不带 `lib` 前缀、不带 `.so` 后缀，CMake 的库名必须和它对上。

模板选择上，`Native C++` 会自带一个 C++ 示例（Java 调 C 返回固定字符串并显示到页面），好处是配置齐全，代价是多出一堆用不上的默认文件，课上建议先留着，等能自己配了再回来删。

## 四、类型与签名：本课最该背下来的一张表

课件用一张截图给了三列对照（Java 类型 / Native 类型 / JNI 签名）：

| Java 类型 | Native 类型 | JNI 签名 |
| --- | --- | --- |
| boolean | `jboolean` | `Z` |
| byte | `jbyte` | `B` |
| char | `jchar` | `C` |
| short | `jshort` | `S` |
| int | `jint` | `I` |
| long | `jlong` | `J` |
| float | `jfloat` | `F` |
| double | `jdouble` | `D` |
| byte[] | `jbyteArray` | `[B` |
| char[] | `jcharArray` | `[C` |
| short[] | `jshortArray` | `[S` |
| int[] | `jintArray` | `[I` |
| long[] | `jlongArray` | `[L` |
| float[] | `jfloatArray` | `[F` |
| double[] | `jdoubleArray` | `[D` |
| Java 类（如 String） | `jstring` / `jobject` | `L全类名;`（例 `Ljava/lang/String;`） |
| Java 方法（如 `start(String, long, long)`） | Native 方法 | `(参数签名...)返回值签名`（例 `(Ljava/lang/String;JJ)V`） |

三条必须记牢的规则：

1. **数组就是类型签名前加 `[`**，`int[]` 是 `[I`，`String[]` 会是 `[Ljava/lang/String;`。
2. **类签名两端有 `L` 和 `;`**，中间是全限定名，用 `/` 分隔而不是 `.`——`com/justin/s12day13/Foo` 这种写法在 `FindClass` 与签名里通用，`FindClass` 忘了把点换成斜杠是新手最常见的崩溃原因。
3. **方法签名 = `(形参)返回值`**，`V` 表示 void。重载方法只能靠签名区分，这是 `GetStaticMethodID` 必须传签名而不是只传方法名的原因。

另一张图是 `jstring` 与 C 字符串的双向转换示意：Java 侧的 `String` 进入 JNI 层还是 `jstring`，在 C 里必须经 `GetStringUTFChars` 才变成可直接读写的字符数组指针；处理完再用 `NewStringUTF` 转回 `jstring` 交还给 Java。这条"两个世界各有一套字符串表示，中间必须显式转换"是整节课反复出现的主线。

## 五、Java 调 C：六种数据形态

| 案例 | Java 声明 | C 侧做法 | 要点 |
| --- | --- | --- | --- |
| 数字 | `native int add(int, int)` | `jint` 直接参与运算 | `jint` 就是 int 的别名，无需转换 |
| 改字符串（指针法） | `native String v2(String)` | `GetStringUTFChars` 拿 `char *`，`info += n` 走位后 `*info = 'j'` 改字符，再 `info -= n` 回退，`NewStringUTF` 返回 | 演示"指针位移 + 解引用写值" |
| 改字符串（数组法） | `native String v3(String)` | `info[1] = 'j'; info[3] = 'j';` | 指针当数组用，等价且更直观 |
| 字符串拼接 | `native String v4(String, String)` | `malloc(strlen(a)+strlen(b)+1)` → `strcpy` → `strcat` | `+1` 给 `\0` 留位 |
| 字符转 hex | `native String v5(String)` | `strlen` 得 size → `char v34[size*2]` → 循环 `sprintf(v28, "%02x", ch)` 且 `v28 += 2` | 每字节输出 2 个 hex 字符，缓冲区要两倍 |
| 字节数组转 hex | `native String v6(byte[])` | `GetByteArrayElements` 拿指针 + `GetArrayLength` 拿长度 → 同上 | 字节数组走 `jbyteArray` 一族 API |

主文档还多给了一个 v7：用 `do { sprintf(...); v29++; } while (v29 != size)` 按长度循环，是比"靠 `\0` 判断结束"更稳的写法（见第九节第 7 条）。

`%02x` 的含义是"小写十六进制、不足两位补 0"。课件附了 sprintf 格式符表：`%% %c %d %f %o %s %x %X`。这套逐字节 `sprintf` 拼十六进制的写法，在 so 里是**识别"这是在做 hex 编码"的标准指纹**——看到循环里 `%02x` 加指针 `+= 2`，基本不用再猜。

## 六、C 调 Java：反射三件套

### 6.1 静态方法

四步：`FindClass` 找类 → `GetStaticMethodID(类, "方法名", "签名")` 找方法 ID → `CallStaticObjectMethod` / `CallStaticIntMethod` 执行 → 返回值按类型接。

课件用 `Foo` 类的四个同名重载 `getSign` 演示了签名区分：

| 方法 | 签名 |
| --- | --- |
| `static String getSign()` | `()Ljava/lang/String;` |
| `static String getSign(int, int)` | `(II)Ljava/lang/String;` |
| `static String getSign(String)` | `(Ljava/lang/String;)Ljava/lang/String;` |
| `static int getSign(String, int)` | `(Ljava/lang/String;I)I` |

同一句 `GetStaticMethodID(cls, "getSign", 签名)`，签名不同就命中不同重载。返回值类型决定用哪个 `Call` 函数：返回对象（含 String）用 `CallStaticObjectMethod`，返回 int 用 `CallStaticIntMethod`。传参时 C 字符串要先 `NewStringUTF` 成 `jstring`。

### 6.2 成员方法

多两步：先造对象，再用对象调方法。

1. `FindClass` 找类；
2. `GetMethodID(cls, "<init>", "(Ljava/lang/String;)V")` 找构造方法——**构造方法名固定是 `<init>`，返回类型固定是 `V`**；
3. `NewObject(env, cls, init, 参数...)` 实例化，拿到 `jobject`；
4. `GetMethodID(cls, "getName", "()Ljava/lang/String;")` 找目标方法；
5. `CallObjectMethod(env, 对象, 方法ID)` 执行。

静态方法传的是 `jclass`，成员方法传的是 `jobject`——这是 `Call*` 系列函数签名上唯一的实质差别。

### 6.3 逆向价值

so 里 `FindClass("com/justin/s12day13/Foo")` 的字符串常量会**明文躺在只读数据段里**，`GetStaticMethodID` 的签名串也是。所以读 so 时看到这一组，等于拿到了"这个 native 函数回调了哪个类、哪个方法、什么参数类型"的完整声明。加密算法把关键步骤放在 Java 层、C 层只做壳的 App，靠这条线索能直接把链路接回去。

## 七、静态注册与动态注册

| 维度 | 静态注册 | 动态注册 |
| --- | --- | --- |
| 对应关系写在哪 | C 函数名 `Java_包_类_方法` | `JNINativeMethod` 表（名、签名、函数指针三列） |
| 注册时机 | 类加载 `System.loadLibrary` 时由 JVM 按名字查找 | so 被加载时执行 `JNI_OnLoad` 主动注册 |
| C 函数命名 | 必须严格对应，不能随意 | 任意，如 `plus1` / `plus2` |
| 逆向难度 | 低：IDA 导出表里 `Java_` 开头的符号一目了然 | 高：导出表里找不到线索，得进 `JNI_OnLoad` 读表 |
| 课件例子 | 车智赢（IDA 里直接看到 `Java_` 符号） | `Dynamic.vv1/vv2` → `plus1/plus2` |

**动态注册的骨架**（`JNI_OnLoad` 前两段和后两段几乎固定，变化的只有中间的 `FindClass` + `RegisterNatives`）：

```c
static JNINativeMethod gMethods[] = {
    {"vv1", "(II)I",                                  (void *) plus1},
    {"vv2", "(Ljava/lang/String;)Ljava/lang/String;", (void *) plus2},
};

JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM *vm, void *reserved) {
    JNIEnv *env = NULL;
    if ((*vm)->GetEnv(vm, (void **) &env, JNI_VERSION_1_6) != JNI_OK) return JNI_ERR;
    jclass clazz = (*env)->FindClass(env, "com/justin/s12day13/Dynamic");
    int res = (*env)->RegisterNatives(env, clazz, gMethods, 2);   // 第三参数是表项个数
    if (res < 0) return JNI_ERR;
    return JNI_VERSION_1_6;
}
```

三条读法：

1. **表里每一行就是一条 Java↔C 的映射**：Java 方法名、方法签名、C 函数指针。签名又回到第四节那张表。
2. **`RegisterNatives` 的第三个参数是表项数量**，写少了就会出现"部分方法没注册、一调用就 `UnsatisfiedLinkError`"。
3. **`JNI_OnLoad` 是 so 的加载入口**，`dlopen` 时由系统调用。逆向动态注册的 so，第一步就是在这个函数上下断点或直接看它的伪 C。

## 八、反编译自己 App 的定位链路

课件第四节的四步，本质是一棵决策树：

1. **jadx 看 Java 层**：找到 `native` 声明和 `System.loadLibrary("utils")`。加载名直接告诉你 so 是 `libutils.so`，不用翻目录猜。
2. **解压 apk**：进 `lib/arm64-v8a/`（其他架构目录同理），取出对应的 `.so`。
3. **IDA 打开 so**：看 exports（导出符号表）。
   - 有 `Java_` 开头的符号 → **静态注册**，双击进去，`F5` 出伪 C，直接就是实现。
   - 没有 → **动态注册**，找 `JNI_OnLoad`，读 `gMethods` 表拿到函数指针，再双击进去 `F5`。
4. **回到 jadx 对照**：把 Java 侧的方法名、参数和 C 侧实现对齐，形成"Java 声明 → so 实现"的完整链。

这条链在 day12 已经用"自己写的加法"跑通过一遍；day13 的增量是：**遇到动态注册时出口不在导出表，而在 `JNI_OnLoad`**。加固过的 App 通常还会在 `JNI_OnLoad` 前后加反调试和字符串加密，但入口位置不变。

## 九、课件口径偏差与坑

1. **主文档 v2 的指针偏移写错**：`info += 1` 改下标 1，再 `info += 3` 落在下标 4，与注释"修改第三个位置"对不上；课堂笔记用的是 `info += 2`（落在下标 3）再 `info -= 3` 回退。以下标 1 和 3 为准（`justin` → `jjsjin`），主文档这一处属笔误。
2. **主文档动态注册少注册一个方法**：`gMethods` 有两项，`RegisterNatives` 却传 `1`，结果 `vv2` 不会注册。课堂笔记传 `2` 才是对的。
3. **主文档 C 调 Java 里 `char *result = malloc(50); strcat(result, p1);` 是错的**：`malloc` 不清零，`strcat` 会从随机位置开始找 `\0`。正确做法是先 `result[0] = '\0'` 或改用 `strcpy` 打头。课堂笔记把这段注释掉了，是对的。
4. **主文档 v5 的函数名前缀是从别的项目拷来的**：写成了 `Java_com_nb_s4luffy_EncryptUtils_v5`，与 `com.justin.s8day12.Utils` 对不上，属跨项目复制残留。函数名必须跟实际包名、类名严格一致，否则一定 `UnsatisfiedLinkError`。
5. **两套包名并存**：主文档沿用 `com.justin.s8day12`（day12 工程），课堂笔记用 `com.justin.s12day13`。对照代码时先看包名，别把两套函数名前缀混着抄。
6. **`char *v28 = &v34;`（v34 是数组）类型不严格**，应为 `v34` 或 `&v34[0]`。与 day12 的 `int *p = &a;` 是同一类教学简化。
7. **`char v34[size*2]` 只够放 hex，不够放结尾的 `\0`**：每次 `sprintf` 写"2 个 hex 字符 + 1 个 `\0`"，最后一次的 `\0` 会落在数组外一字节。逆向里遇到这种写法很常见，读的时候要知道它靠栈上运气收尾。
8. **用 `byteArray[i] != '\0'` 当字节数组的循环条件有隐患**：密文里出现 `0x00` 就会提前截断。主文档的 v7 用 `do-while` 配 `GetArrayLength` 才是正确口径。
9. **`%02x` 配 `char` 会打出 `ffffffff`**：`char` 在 x86/ARM 上默认有符号，值为负（≥0x80）时会被符号扩展成负数再按 `%x` 输出。规范的 hex 编码要先转 `unsigned char`。课件没处理这一点，而真实加密数据里高位字节几乎是必然出现的。
10. **`GetStringUTFChars` 拿的副本没有对应的 `ReleaseStringUTFChars`**：短命调用无所谓，循环里反复取就会累积。另外它给的是 JNI 的 **modified UTF-8**，与标准 UTF-8 在补充平面字符（emoji 等）上有差异，做字符串比对时要注意。

## 关键知识清单

- **JNI 的存在意义**：把加密逻辑挪出 dex，让 jadx 只能看到空 `native` 声明，逼分析者去读 so。
- **加载映射**：`System.loadLibrary("utils")` → `libutils.so`；CMake 里 `add_library(utils SHARED utils.c)` 的库名必须与加载名一致。
- **类型三列对照**：`int`→`jint`→`I`、`String`→`jstring`→`Ljava/lang/String;`、`byte[]`→`jbyteArray`→`[B`；数组加 `[`，类用 `L...;`，类名用 `/` 分隔。
- **方法签名**：`(形参)返回值`，`V` 为 void；重载只能靠签名区分，这是 `GetStaticMethodID` 必传签名的原因。
- **Java 调 C 的转换**：`jstring` ↔ `GetStringUTFChars` / `NewStringUTF`；`jbyteArray` ↔ `GetByteArrayElements` / `GetArrayLength`；hex 编码靠 `sprintf("%02x")` + 指针 `+=2`，缓冲区要两倍长。
- **C 调 Java**：`FindClass` → `GetStaticMethodID`/`GetMethodID` → `CallStatic*Method`/`CallObjectMethod`；构造方法名 `<init>`、返回 `V`；造对象用 `NewObject`；返回类型决定选哪个 `Call` 函数。
- **静态注册**：靠 `Java_包_类_方法` 命名约定，IDA 导出表直接命中，逆向最省事（车智赢案例）。
- **动态注册**：`JNI_OnLoad` + `RegisterNatives(gMethods, 个数)`，C 函数名随意（`plus1`/`plus2`），逆向必须进 `JNI_OnLoad` 读表。
- **定位决策树**：jadx 拿 `loadLibrary` 名 → 解压 apk 取 `lib/<abi>/*.so` → IDA exports 找 `Java_` 就是静态注册；没有就找 `JNI_OnLoad` → `F5` 出伪 C。
- **IDA 读 JNI so 的前提**：先导入 `jni.h` 等头文件，`JNIEnv`、`jstring` 才能具名显示。
- **几个必踩的坑**：`RegisterNatives` 个数要等于表长；`malloc` 不清零不能直接 `strcat`；`%02x` 喂有符号 `char` 会输出 `ffffffff`；hex 缓冲区忘了给 `\0` 留位；循环用 `!= '\0'` 判字节数组会截断。
