## 一、抓包与接口定位（day17）

### 1.1 确定哪个接口加播放量

抓包会同时看到 `heartbeat` 与 `click` 两类请求，逐个改包重发、观察播放量变化来确认。结论是 `https://api.bilibili.com/x/report/click/android2`（POST）。

风控现状（课件记录）：

- 早期同 IP 反复请求即可涨量，但增长有限；
- 现在同 IP 基本只涨一次，需要靠换 did / buvid / fp_local 构造新设备身份；
- 请求头里 `session_id` 可以删，`buvid`、`device-id`、`fp_local`、`fp_remote` 是必需身份。

### 1.2 抓包看到的请求体

请求体是二进制乱码，实际是 AES 密文的字节串。抓包工具里显示的十六进制与 hook 拿到的字节数组一一对应（注意 Java 的 byte 有符号、Python 无符号，负值需 `+256`，转 hex 时补零）。

### 1.3 反编译定位

- 搜地址 `click/android2`，命中 Retrofit 接口：
  `@POST("/x/report/click/android2")` + `@RequestInterceptor(com.bilibili.okretro.f.c.class)` + `reportClick(@Body c0 c0Var)`。
- 搜 `reportClick` 用例只有一处，关键代码是 `reportClick(c0.create(编码方式, d.this.H7(一堆参数)))`，请求体就是 `H7` 的返回值。
- 混淆说明：反编译出来全是 a / b / c 这种“魔鬼变量”。jadx 可以开反混淆让阅读顺一些，但 **hook 必须用混淆前的原始方法名/类名**，反混淆只用于读代码。

## 二、click 接口请求体：H7 的两层处理（day17）

### 2.1 H7 的整体流程

1. 十几个参数塞进 `TreeMap`（天然按 key 排序）：`aid`、`cid`、`part`、`mid`、`lv`、`ftime`、`stime`、`did`、`type`、`sub_type`、`sid`、`epid`、`auto_play`，登录态下还有 `access_key`，再加 `build`、`mobi_app`、`spmid`、`from_spmid`。
2. 遍历 TreeMap 拼成 `k1=v1&k2=v2&...&`，删掉末尾 `&`。
3. 对整串做签名：`sign = sha256(明文 + 盐)`，转小写十六进制。
4. 拼成 `明文&sign=xxx`。
5. 整串再做 AES 加密，返回 byte[]，作为请求体。

所以破解点是两个：**sign 怎么算** 和 **整体怎么 AES**。

### 2.2 sign：SHA256 + 固定盐

签名入口是 `t3.a.i.a.a.a.b.e.b(String)`：

- 明文 `getBytes(UTF-8)`；
- 取类内常量 `d` 当盐，也同样 `getBytes`；
- 调 `com.bilibili.commons.m.a.g(明文bytes, 盐bytes)`。

`g()` 内部就是 `MessageDigest.getInstance("SHA256")`，先 `update(明文)` 再 `update(盐)`，最后把 digest 逐字节 `& 255`、不足 16 补 `0` 转十六进制。也就是：**SHA256(明文 ‖ 盐)，不是 HMAC**。

盐值来源：hook `com.bilibili.commons.m.a.g` 打印 `bytes2` 得到 `9cafa6466a028bfb`，多次触发都是同一值。同源码里 `static{}` 块也写死了默认值（三个常量分别是 AES key、AES iv、SHA256 盐，都能被配置中心覆盖，取不到才用默认）。

### 2.3 请求体：AES/CBC/PKCS5Padding

`t3.a.i.a.a.a.b.e.a(String)` 里：

- `SecretKeySpec(key.getBytes(), "AES")`，key = `fd6b639dbcff0c2a1b03b389ec763c4b`（32 字符 → AES-256）；
- `IvParameterSpec(iv.getBytes())`，iv = `77b07a672d57d64c`（16 字节）；
- 交给 `com.bilibili.droid.g0.a.i()`，其内部是 `Cipher.getInstance("AES/CBC/PKCS5Padding")` 后 `doFinal`；
- 异常分支会退化成直接返回明文 bytes（排障时可用来判断是不是加密步骤失败）。

拿 key/iv 的通用手法：hook `javax.crypto.spec.SecretKeySpec` 的 `(byte[], String)` 构造和 `javax.crypto.spec.IvParameterSpec` 的 `(byte[])` 构造，再 hook `com.bilibili.droid.g0.a.i` 顺带打印 AES 前的明文，三者在一次请求里能对齐。

### 2.4 did：设备指纹的“异或链 + Base64”

`H7` 里 did 来自 `com.bilibili.lib.biliid.utils.f.a.c(context)`：

- 三级缓存：静态变量 → xml → 都没有才调用 `g(context)` 生成，并回写变量和 xml；
- `g()` 先用 `f(context)` 拼 `mac地址|蓝牙地址|设备总线|sn号`（各段都去掉非十六进制字符并转小写，取不到就留空）；
- 若拼出来长度 < 4，退化用 `android_id + "@" + MD5(Build.MODEL)`；
- 最后过 `b(str)`：首字节异或上 `长度 & 255`，之后每字节与前一个字节异或（形成链式累积），再 Base64 编码并去掉尾部 `=`、`==`。

课件现场 hook 时拿到的是 `|||`（模拟器读不到硬件信息），因此 Python 侧用随机 mac + 随机 sn 自行拼 `mac|||sn` 再走同一套异或 Base64 即可，不必复现真机取值。Python 的 `base64.encodebytes` 换行后需 `strip()`。

### 2.5 aid / cid

两者是视频 id 和分 P 的 cid，刷量场景里由客户给一个视频链接，直接请求 Web 页面正则 `var options = (.+);` 后 `json.loads` 取 `aid`、`cid`，与 App 端一致，没必要从 App 走一遍。day19 还给出纯接口路线：`x/player/pagelist?bvid=` 拿 cid，`x/web-interface/view?cid=&bvid=` 拿 aid、时长、播放量。

## 三、请求头四个指纹（day18）

### 3.1 头是在拦截器里塞的

`com.bilibili.okretro.f.c`（Retrofit 拦截器）里 `a(b0)` 取出 builder，调用 `e(builder)` 往 builder 上写头，再 `return builder.b()`。`e()` 里依次放 `Display-ID`、`Buvid`、`User-Agent`、`Device-ID`、`fp_local`、`fp_remote`、`session_id`，值都来自 `com.bilibili.api.*` 的静态 getter。

这类“静态 getter + 静态字段”的写法是通用信号：**真正的赋值点在别处，靠查找用例或打印调用栈回溯**。

### 3.2 buvid

链路：`com.bilibili.api.c.a()` 读静态字段 `a` → 赋值方法是 `b(String)` → 查找用例落到 `c2.f.b0.c.a.d.e()` → 再回到 `c2.f.b0.c.a.d.a()` → 私有字段 `this.a` 在 `d()` 里被赋值：

1. `MiscHelperKt.d(e.k().b())` —— 内存/xml 里已有的 buvid；
2. `MiscHelperKt.d(e.k().c())` —— 另一份缓存；
3. `c2.f.b0.c.b.a.c.a().toUpperCase()` —— 真正现场生成。

生成逻辑按优先级四选一，前缀区分来源：

| 前缀 | 依据 | 规则 |
| --- | --- | --- |
| `XZ` | 手机状态串 | `XZ` + md5 取第 2/12/22 位 + md5 全串 |
| `XY` | WiFi mac | 同上，换成 mac |
| `XX` | android_id | 同上 |
| `XW` | uuid | uuid 去掉 `-` 后取第 2/12/22 位 + 全串 |

即 `前缀 + md5str[2] + md5str[12] + md5str[22] + md5str`，最后统一 `.toUpperCase()`。`e()` 的取值下标固定是 2、12、22，越界时返回常量。

最省事的是 `XW` 的 uuid 方案，随机性强且不需要真机硬件信息（day17 抓到的 `XX...`、`XY...` 都是同族）。

### 3.3 session_id

链路：`com.bilibili.api.a.m()` → `b.getSessionId()`，而 `b` 是接口类型 `com.bilibili.api.a$b`，看不到实现。两条定位思路：

- 追 `a.o(b bVar)`（给静态字段 `b` 赋值的唯一入口），hook 后打印实参，得到 `$className: tv.danmaku.bili.utils.p$a`；
- 或全局搜 `getSessionId`，命中太多，不划算。

沿 `tv.danmaku.bili.utils.p$a` → `com.bilibili.lib.foundation.e.b().getSessionId()`，同样 hook 得到具体类是 `com.bilibili.lib.foundation.DefaultApps`，其 `getSessionId()` 从 xml 读 `foundation:session_id`，读不到返回静态常量 `l`。

`l` 在 `static{}` 里赋值：`new Random().nextBytes(byte[4])` 后 `ByteString.of(...).hex()`，即 **4 个随机字节转 8 位十六进制**。Python 侧 `random.randbytes(4)` 逐字节 `hex()`（注意 `hex()` 丢前导零的问题，严格对齐应格式化 `%02x`）后拼接。

### 3.4 fp_local（本课最硬的点）

链路：`com.bilibili.api.a.j()` → `b.F()`（同样先确认 `b` 的具体类型）→ `tv.danmaku.bili.utils.p$a.F()` → `c2.f.b0.c.a.c.a()` → `Fingerprint.h.c()`，那里只是把静态字段 `a` 读出来加读锁返回。

**卡点**：新版 jadx 对 `Fingerprint` 类里两个方法（`f()`、`e()`）反编译不全，看不到 `a = d2` 的赋值。课件换 **jadx 1.2.0**（老版内存默认给小，需把 `-Xmx` 调大）后编译成功；再往后 `MiscHelperKt.a()` 调用的 `f.Oe` 属于 Kotlin 集合库代码，jadx 反编译不出，改用 **GDA**（国产，免费版解压即用，`gda.wiki`）才能看到 `ArraysKt___ArraysKt.Oe / Fe / ne` 一层层到底。

定位到 `com.bilibili.lib.biliid.internal.fingerprint.a.a.a(str, aVar)`：

```
str2 = hex(md5(buvid + 手机型号model + 手机品牌band))
     + yyyyMMddHHmmss（14 位时间串）
     + hex(8 个随机字节)
fp_local = str2 + b(str2)
```

- `f()` → `e(str + a2.get("model") + a2.get("band"))`，`e()` 是 MD5（`MessageDigest("MD5")`）；品牌在模拟器上常是空串。
- `h()` → `SimpleDateFormat("yyyyMMddHHmmss").format(now)`。
- `g()` → `com.bilibili.commons.e.a(8)` → `new Random().nextBytes(byte[8])`。
- `MiscHelperKt.a()` 表面很绕（`f.Oe` → `ArraysKt___ArraysKt.Oe` → `Fe` → `ne` → 单例 `MiscHelperKt$asHex$1.INSTANCE.invoke`），本质就是 **joinToString + 每字节 `String.format("%02x")`**，即字节数组转十六进制串。
- 尾部 `b(str2)` 是关键：`q.S0(q.n1(0, min(len-1, 62)), 2)` 产生三元组，hook `kotlin.g0.q.S0` 拿到固定值 **g=0、h=60、step=2**；然后用 `str.substring(g, g+2)` 每隔 2 位取 2 字符、按 16 hex 解析后累加，最后 `% 256` 用 `%02x` 输出两位校验码拼在尾部。

`fp_remote` 用同一算法生成即可（形状相似，非完全相同；真实值由其他请求返回）。

### 3.5 device-id

复用第 2.4 节的 `g()`/`b()`：随机 mac + 随机 sn 拼 `mac|||sn`，异或链后 Base64 去等号。day19 的整合代码里 `create_device_id(mac)` 就是这条路径。

## 四、完播率接口 heartbeat/mobile（day19）

### 4.1 请求特征

- 地址 `https://api.bilibili.com/x/report/heartbeat/mobile`，POST；
- 请求体是明文 `application/x-www-form-urlencoded`（**不是** click 那种 AES 密文），字段多但结构稳定：`aid`、`cid`、`sid`、`epid`、`type=3`、`sub_type`、`quality`、`video_duration`、`played_time`、`paused_time`、`total_time`、`actual_played_time`、`last_play_progress_time`、`max_play_progress_time`、`start_ts`、`ts`、`statistics`、`session`、`sign` 等；
- 需要自己算的只有 `session` 和 `sign`；请求头沿用 day18 那四个指纹。

### 4.2 session = SHA1(buvid + 毫秒时间戳 + 随机数)

`HeartbeatParams` 构造里 `putParams("session", str)`，`str` 来自 `hVar.r1()` 读字段 `this.d`，赋值入口 `h.t2(String)`。hook `t2` 打印调用栈，看到 `h$a.b` → `d.L7` → `d.u7` → `PlayerCoreServiceV2$l.onPrepared`（播放器准备完成时生成），实参来自 `g.a.a()`：

```
Random random = new Random();
sb.append(E.t());                       // buvid，取不到就是 ""
sb.append(System.currentTimeMillis());  // 毫秒时间戳
sb.append(random.nextInt(1000000));     // 0 ~ 999999
return com.bilibili.commons.m.a.i(sb.toString());  // SHA1，无盐
```

`com.bilibili.commons.m.a.i` → `j` → `h(bytes, MessageDigest("SHA1"))`，逐字节高位/低位查表转十六进制再 `toLowerCase()`。hook `a.i` 打印入参可确认 `E.t()` 为空（此时等价于 `sha1(时间戳+随机数)`），这也是课件演示时的形态。

### 4.3 sign 不在 Java 层：先定位，再下 so

`HeartbeatParams` 里根本没有 sign 参数，所以先怀疑：要么拦截器补，要么 so 整体加密。

**路线 A：搜字符串 `"&sign="`**。搜到很多处，需要逐个排；真正命中的是 `com.bilibili.nativelibrary.SignedQuery.toString()`：

```
return this.a + "&sign=" + this.b;   // a=明文请求体，b=签名
```

hook 该 `toString` 打印调用栈：`SignedQuery.toString` ← `com.bilibili.okretro.f.a.c` ← `a.a` ← `d.a.execute`。`okretro.f.a.c()` 里 `c0.create(x-www-form-urlencoded, h(hashMap).toString())`，而 `h(map)` → `LibBili.g(map)` → `native s(SortedMap)`。`SignedQuery` 的构造找不到调用方，因为实例化发生在 so 里（`NewObject` 直接从 C 调 Java 构造）。

**路线 B：hook 底层 `NewStringUTF` 兜底**。so 里算完字符串要交回 Java，必然经过 `JNIEnv->NewStringUTF`。通用脚本三步：

1. `Module.enumerateSymbolsSync("libart.so")` 遍历符号，`name` 含 `NewStringUTF` 且不含 `CheckJNI`，取 `address`；
2. `Interceptor.attach(address, {onEnter: args => args[1].readCString()})`；
3. 用条件过滤噪声：返回串含特征词（如 `sign`），或长度固定（本例限 `length === 32`）。

命中后同时打印 `Thread.backtrace(...).map(DebugSymbol.fromAddress)` 看是哪个 so、以及 Java 调用栈。本例输出 32 位串 + 栈顶 `com.bilibili.nativelibrary.LibBili.s(Native Method)`，与路线 A 结论一致。`frida -UF -l script.js -o v1.txt` 可把日志落盘。

### 4.4 定位 so 内函数：静态注册 vs 动态注册

`libbili.so` 由 `com.getkeepsafe.relinker` 加载（`c.c("bili")`）。判断注册方式：

- 静态注册：导出表里找 `Java_包名_类名_方法名`；
- 动态注册：看 `JNI_OnLoad` 里的 `RegisterNatives` 表（IDA 里从 `&off_B004` 一类指针数组能看到 name/sig/fnPtr 三元组）。

课件给的是通用 Frida 脚本：hook `libart.so` 里含 `art`+`JNI`+`RegisterNatives` 的符号，`onEnter` 时：

- `args[1]` 是 jclass，用 `Java.vm.tryGetEnv().getClassName(java_class)` 得到类名，只放行 `com.bilibili.nativelibrary.LibBili`；
- `args[2]` 是 `JNINativeMethod[]`，`args[3]` 是数量；
- 每次 `i * pointerSize * 3` 读 name，`+pointerSize` 读签名，`+pointerSize*2` 读函数指针；
- `Process.findModuleByAddress(fnPtr)` 得到模块，`offset = fnPtr.sub(module.base)`。

得到映射（示例）：

```
name: s  sig: (Ljava/util/SortedMap;)Lcom/bilibili/nativelibrary/SignedQuery;  module: libbili.so  offset: 0x1c97
name: so sig: (Ljava/util/SortedMap;II)...   offset: 0x1c9d
name: a  sig: (Ljava/lang/String;)Ljava/lang/String;  offset: 0x1c7d
```

要点：**基地址和函数内存地址每次都变，偏移量固定**，偏移量才是能写进笔记复用的东西。IDA 用 `jump to address` 填 `0x1c97` 即到 `sub_1C96`（thumb 指令，符号偏移比函数起始多 1）。

### 4.5 so 内实现：MD5 + 四段盐

`sub_1C96` 只是转调 `sub_2F88`。`sub_2F88` 结构：

```
sub_227C(v36);                  // MD5 初始化：1732584193, -271733879, -1732584194, 271733878
sub_22B0(v36, v32, v27);        // update 明文
sprintf(v37, "%08x", v22);
sub_22B0(v36, v37, 8);          // update 盐
...
NewStringUTF(...)               // 结果转 Java 字符串
NewObject(..., v16, v17)        // 实例化 SignedQuery(明文, sign)
```

`sub_227C` 里的四个魔数正是 MD5 的初始向量 A/B/C/D，可以直接判定是 MD5。`sub_22B0` 是 update，因此 hook 它（`Module.findBaseAddress("libbili.so").add(0x22b0 + 1)`，**32 位 so 一律 +1**）打印 `args[1].readUtf8String()` 与 `args[2].toInt32()` 长度，就能拿到进 MD5 的每一段：

```
560c52cc  (长度 8)
d288fed0  (长度 8)
45859ed1  (长度 8)
8bffd973  (长度 8)
```

四段拼起来是 `560c52ccd288fed045859ed18bffd973`，正好 32 字符。签名为：

```
sign = md5(按 key 排序拼好的明文 + 四段盐).hexdigest()
体   = 明文 + "&sign=" + sign
```

和 click 接口的区别值得记：click 是“明文单独 SHA256 加盐 → 拼 sign → 整体 AES”，heartbeat 是“明文与盐一起 MD5 → 拼到 URL 编码体后面”，没有二次加密。

### 4.6 整合脚本的结构

`BiliBili` 类把三天的成果串起来，值得照搬的骨架：

1. `__init__`：生成 `wifi_mac` → `device_id`（异或 Base64）→ `buvid`（`XY` + md5 取位）→ `session_id`（4 字节 hex）→ `fp_local` / `fp_remote`（同一算法）→ `app_first_run_time`、`ts`；
2. `x_report_click_android2()`：拼 17 个字段 → sha256 加盐 → 拼 `&sign=` → AES-CBC → POST 二进制体，头里带四指纹；
3. `create_heart_beat_session_id()`：`sha1(ms时间戳 + 随机)`；
4. `heart_beat_start()`：`start_ts = now-10`、`played_time=0`、各计时字段为 0；
5. `heart_beat_end()`：`played_time=actual_played_time=duration`、`paused_time = now - start_ts - duration`、`total_time = now - start_ts`、`start_ts` 回填；
6. 签名统一走 `get_param_sign_s(dict)`：排序拼串 + 四盐 + MD5。

工程细节：

- `statistics` 字段必须先 `json.dumps(..., separators=(',',':'))` 再 `quote_plus`，否则拼串与签名对不上；
- `content-type` 分别是 `application/json; charset=utf-8`（click，实际是二进制体）与 `application/x-www-form-urlencoded; charset=utf-8`（heartbeat）；
- UA 用 `BiliDroid/6.24.0 ... model/Mate 10 Pro ...`，`build=6240300` 与 UA 的 `innerVer` 保持一致；
- `requests` 里 `verify=False` 需配 `urllib3.disable_warnings`；
- 刷量循环要有代理池或每次重建设备身份，否则同 IP/同设备只计一次。

## 五、这套流程里的可复用方法论

1. **先定接口再反编译**：改包重放看指标变化，比盲猜接口快。
2. **Retrofit 应用是入口**：搜 URL → 找 `@POST` 接口 → 搜方法名用例 → 顺着 `@Body` 参数进参数生成函数。请求头看 `@RequestInterceptor`。
3. **静态 getter 一定要回溯赋值点**：`return a` 这类代码没信息，靠“查找用例”或 hook setter 打调用栈（`Log.getStackTraceString(Throwable)`）回到生成现场。
4. **反编译不全就换工具**：jadx 版本问题（新版失败、1.2.0 成功）、内存不够（`-Xmx4g` → `-Xmx16g`）、Kotlin 集合库代码需 GDA。别在一个工具上死磕。
5. **Java 层找不到 sign，就往 so 走**：`native` 声明 → 判断静态/动态注册 → hook `RegisterNatives` 取 offset → IDA 按 offset 定位 → hook 内部函数拿真实入参（盐、明文字节）。
6. **NewStringUTF 是 so 返回字符串的万能锚点**：枚举 `libart.so` 符号 + 长度/关键字过滤 + backtrace。
7. **hook 时机**：`attach` 抓已运行进程，`spawn` + `resume` 抓启动期生成（如 did、buvid、fp_local 初始化）；改缓存类字段前先清 App 数据，否则拿到的是旧值。
8. **偏移量 +1**：32 位 so 在 Frida 里按函数地址 attach 需要 `offset + 1`（thumb 位）。

## 六、关键知识清单

- 接口：`x/report/click/android2`（播放量，AES 二进制体）、`x/report/heartbeat/mobile`（完播率，表单体）。
- click 签名：`sha256(排序明文 + "9cafa6466a028bfb")`，小写 hex。
- click 加密：AES-256-CBC/PKCS5，key `fd6b639dbcff0c2a1b03b389ec763c4b`，iv `77b07a672d57d64c`。
- did：`mac|蓝牙|设备总线|sn` → 异或链 → Base64 去 `=`；长度 <4 时退化 `android_id@MD5(model)`。
- buvid：`XZ/XY/XX/XW` + `md5[2]+md5[12]+md5[22]+md5`，整体大写；`XW` 用 uuid 最省事。
- session_id（头）：4 随机字节的 hex，8 位。
- fp_local：`hex(md5(buvid+model+band)) + yyyyMMddHHmmss + hex(8随机字节)`，再拼 `b(str2)` 校验码（g=0、h=60、step=2，累加 %256）。
- heartbeat session：`sha1(ms时间戳 + rand(0,1e6))`，无盐；buvid 取不到时为空串。
- heartbeat sign：`md5(排序明文 + 560c52cc + d288fed0 + 45859ed1 + 8bffd973)`。
- so 落点：`libbili.so` 动态注册，`s` 偏移 `0x1c97` → `sub_1C96` → `sub_2F88`；MD5 初始化 `sub_227C`，update `sub_22B0`（hook 偏移 `0x22b0+1`）。
- 字段一致性坑：`statistics` 需 URL 编码；`build` 与 UA `innerVer` 对齐；`paused_time`、`total_time` 由 `start_ts` 推算。
- 风控现状：同 IP 只涨一次，需重建设备身份或换代理。
