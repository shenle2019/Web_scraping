## 二、xml 持久化（SharedPreferences）

**要解决的问题**：登录成功后后端给一个 token，之后所有需要登录态的接口都要带上它。用户关掉 App、重启手机再打开，登录状态仍在——说明 token 被"持久化"到了磁盘，Android 上最常见的落点就是 xml。

**本质**：`/data/data/<包名>/shared_prefs/` 目录下的一个 xml 文件，键值对形式。API 入口是 `getSharedPreferences(文件名, MODE_PRIVATE)`，文件名不带 `.xml` 后缀，落盘时系统自动补。

**三个操作，对应三个 API 组合**：

| 操作 | 调用链 | 说明 |
| --- | --- | --- |
| 新增/改值 | `sp.edit().putString(k, v).commit()` | 编辑必须先拿 Editor |
| 取值 | `sp.getString(k, 默认值)` | 键不存在时返回默认值，不会抛异常 |
| 删除 | `editor.remove(k).commit()` | 只删这个键，不删文件 |

要点：课上统一用 `commit()`（同步写入、返回布尔），与 `apply()`（异步）是两套语义；`MODE_PRIVATE` 表示只有本应用可读。

**手机上怎么看到它**：`adb shell` → `su` → 进 `/data/data/<包名>/shared_prefs` → `cat` 那个 xml。前提是 App 确实执行过写操作，否则目录可能压根不存在——排查"文件找不到"时先确认代码路径真的跑到了。

**逆向意义（本课反复强调的一句）**：反编译代码里只要出现 `getSharedPreferences`，就等于告诉你"这个 App 在读写本地 xml"。更进一步：如果某个请求依赖 App 启动时生成并写进 xml 的值，完全不必啃加密逻辑，直接把设备上的 xml 抠出来，把值塞进自己构造的请求即可——这是绕过算法、复用凭证的一条捷径。

## 三、OkHttp 拦截器

**动机**：一批接口都要带同样的头（时间戳 `ctime`、签名 `sign`、客户端标识之类），逐个请求手写既啰嗦又容易漏一个。拦截器在请求真正发出前统一加工，业务代码只关心业务参数。

**机制**：实现 `Interceptor` 接口，在 `intercept(Chain chain)` 里做三步——`chain.request()` 拿原请求 → `newBuilder()` 派生新请求并 `addHeader()` 加头 → `chain.proceed(新请求)` 放行给下一环，把拿到的 `Response` 返回。拦截器是链式的，可以有多个，按添加顺序进出。

**两种写法**：

- **独立类** `implements Interceptor`，发请求时 `new OkHttpClient.Builder().addInterceptor(new XxxInterceptor()).build()`。反编译里最常见的形态。
- **匿名内部类**，在发请求处直接 `new Interceptor(){...}`。代码集中，但每个请求都要写一遍，实际项目很少这么用。

**安卓里的常见封装**：把拦截器实例做成 `public static final` 常量，全局共享同一个对象，各处 `addInterceptor(常量)`。反编译看到这种静态 final 拦截器，基本可以断定"全 App 所有请求都带同一套头"。

**后端侧怎么校验**：Flask 在 `@app.before_request` 里取 `request.headers.get(...)` 重新算一遍比对，不一致就返回错误码（课件示例是 `code=102` 加一句"IP 已被监控"的威慑文案）；Django 对应的是中间件。校验逻辑放在请求进入视图之前，是这类方案的共同点。

**逆向定位套路**：

1. 现象驱动：某个 App 所有请求都带固定的几个头，先怀疑拦截器统一注入，而不是每个接口各写一遍。
2. 静态：jadx 全局搜 `Interceptor`，逐个看 `intercept` 里加了什么头、签名怎么算、有没有读本地存储。
3. 动态：hook `OkHttpClient$Builder.addInterceptor`，把传入的拦截器实例打印出来，一眼看清挂了几个、分别是什么类、有没有匿名类。
4. 坑：课件附的 hook 脚本里写的是 `Java.user(...)`，Frida 里正确的 API 是 `Java.use(...)`，照抄会直接报错——这是课件笔误，不是新语法。

## 四、Retrofit

**定位**：对 OkHttp 的封装，底层仍然是 OkHttp。用"接口 + 注解"声明请求，不再手拼 `Request`。逆向时两种库都会遇到：老项目多用裸 OkHttp，新项目多是 Retrofit。

**四步用法**：`build.gradle` 引 `com.squareup.retrofit2:retrofit` → 写接口，方法上用注解描述请求 → `new Retrofit.Builder().baseUrl(...).build()` → `.create(XxxApi.class)` 拿到代理对象调方法。

**注解语义**：

| 注解 | 作用 |
| --- | --- |
| `@POST("login")` / `@GET("films")` | 请求方法与相对路径 |
| `@FormUrlEncoded` + `@Field("user")` | 参数做表单编码，进 body |
| `@Query("age")` | 参数拼到 URL 查询串 |
| `@Body` | 整个对象序列化后作为请求体（JSON 场景） |

**登录改造要点**：接口方法返回 `Call<ResponseBody>`，`execute()` 同步执行，`.body()` 取响应体字符串，再交给 Gson 反序列化；登录成功照样写 SharedPreferences 存 token，再 `startActivity` 跳列表页。列表页在 `onCreate` 起子线程请求 `/films`，解析完必须 `runOnUiThread` 回主线程再 `setAdapter`——子线程碰 UI 会崩。

**与拦截器的组合（最容易踩的坑）**：必须 `new Retrofit.Builder().baseUrl(...).client(okHttpClient).build()`。不显式 `.client()` 时 Retrofit 会自己 new 一个 `OkHttpClient`，之前配的拦截器全部不生效，表现就是"头没加上"。另外 `baseUrl` 必须以 `/` 结尾，接口注解里的路径别加前导 `/`，否则路径拼接会出意外。

**逆向特征**：搜 `retrofit2`、`@POST`、`@GET`、`create(`、`baseUrl` 就能定位接口层。接口注解里直接写着路径和参数名，比 OkHttp 手拼 URL 好读得多。课件拿"合伙人"App 举例，登录接口 `/v1/partnerLogin/login` 就是从 Retrofit 接口声明里直接读出来的。

## 五、逆向自己 App 的闭环

课件给的五步，也是后面所有第三方 App 案例的通用骨架：

1. 编译自己的 App（打包 APK）；
2. 装到真机；
3. 抓包看请求长什么样（Charles / Fiddler / mitmproxy）；
4. jadx 反编译，对照抓到的请求去找签名代码；
5. 用 Python requests 复刻签名直接调接口，验证脱离 App 也能拿到数据。

意义在于：第 5 步一旦跑通，就证明了"这套请求可以脱离客户端复现"。逆向第三方 App 只是在第 4 步上加大难度（混淆、加固、so），流程不变。

## 六、为什么要学 C：加密下沉到 so

**两类公司，两种难度**：

- 一般公司：加密写在 Java 层（比如合伙人 App 的密码就是 Java 侧 md5），jadx 反编译后基本等于看源码，好破。
- 硬核公司：Java 层只负责"调用"，真正的加密算法用 C 写进 `.so`（JNI）。jadx 里只能看到一个 `native` 方法声明，方法体是空的，必须改用 IDA 之类工具去分析 so 里的汇编和伪 C 代码——所以必须先能读懂 C。

**动态链接库**：C 代码写好编译出来的函数集合，运行时按需加载，不必全塞进主程序。Android / Linux 上是 `xxx.so`，Windows 上是 `xxx.dll`。类比 Java 的 jar、Python 的包。

**能反编译 so 的工具**：

| 工具 | 特点 |
| --- | --- |
| IDA Pro | 功能最强，反汇编/反编译/调试齐全，商业软件（课件提到"有大神给破"的版本流通） |
| Ghidra | NSA 开源，反汇编/反编译/脚本扩展，无授权成本 |
| Radare2 | 开源逆向框架，命令行风格，脚本化能力强 |
| Hopper Disassembler | 偏 macOS 生态，反汇编 + 图形界面 |

## 七、C 开发环境（Windows）

**C 是编译型语言**：源码必须先经编译器生成对应平台的可执行文件才能跑。常见编译器 GCC、MSVC、Clang。macOS / Linux 自带 gcc（mac 没有就装 Xcode），Windows 得自己装。

**MinGW**：全称 Minimalist GNU on Windows，把 GCC 移植到 Windows 并附带 Win32 API。区别要记住——**MinGW 只能产出 32 位程序，MinGW-w64 能产 64 位也能产 32 位**，现在装的都是后者。

**三种安装方式**（课件都给了）：

1. `mingw-w64-install.exe` 在线安装器，网络差容易失败；
2. **直接解压** `x86_64-8.1.0-release-win32-seh-rt_v6-rev0.7z`，把 `bin` 目录加进 PATH——最省事，课件里这个包已经解压好了；
3. `mingw-get-setup.exe`（老版 MinGW 安装器）作备选。

装完的验收标准只有一条：任意终端敲 `gcc -v` 有版本输出。

**第一个程序用记事本写**：`#include <stdio.h>` + `int main()` + `printf`，终端里 `gcc main.c` 默认产出 `a.exe`，直接运行。这一步的价值是让人看清"编译"这个动作，不被 IDE 遮住。

**IDE 用 CLion 2023.1.4**：JetBrains 家的，装完要在设置里**手动指定 MinGW 的工具链路径**（课件专门配了图 `配置clion的编译器.png`），否则新建工程直接报找不到编译器。激活沿用 IDEA 那套：先跑激活脚本，再填激活码。

**中文乱码两套解法**：`Ctrl+Shift+Alt+/` 打开 Registry 调编码项；或在设置里把文件编码 / 控制台编码统一改成 UTF-8。

## 八、C 基础语法（按课件 5.1–5.9 过一遍）

### 8.1 整型

| 类型 | 字节 | 范围要点 |
| --- | --- | --- |
| `char` / `signed char` | 1 | -128 ~ 127 |
| `unsigned char` | 1 | 0 ~ 255 |
| `short` | 2 | -32768 ~ 32767 |
| `unsigned short` | 2 | 0 ~ 65535 |
| `int` | 2 或 4 | 64 位机上固定 4 字节，约 ±21 亿 |
| `unsigned int` | 2 或 4 | 0 ~ 42 亿（4 字节时） |
| `long` | 4 | Windows 下与 int 同宽（Linux 64 位是 8 字节，跨平台要注意） |

关键认知：**存储大小由系统位数和编译器决定**，不是语言写死的；`sizeof` 是唯一可靠的判断手段。`char` 用 `%d` 打出来是 ASCII 码，用 `%c` 打出来是字符——同一个字节两种解读，这个"类型只是解读方式"的观念是后面看内存、看 so 的基础。

### 8.2 浮点

| 类型 | 字节 | 有效位 | 输出格式 |
| --- | --- | --- | --- |
| `float` | 4 | 6 位 | `%f` 普通计数、`%e` 指数计数 |
| `double` | 8 | 15 位 | `%f` / `%e` |
| `long double` | 16 | 19 位 | `%Lf` / `%Le` |

浮点字面量默认是 `double`，要 float 得加 `F` 后缀、要 long double 得加 `L`，否则精度和输出都可能不合预期。

### 8.3 常量

`const int MAX_VALUE = 99;` 声明后不可再赋值，再赋值编译不过。逆向时看到 const 常量表，往往就是硬编码的密钥、盐值、偏移量的藏身处。

### 8.4 运算符

- **算术**：`+ - * / %`，整数相除会截断（`B/A` 得 2 不是 2.5）；`++` / `--` 分前置后置——`a++` 先取值再加，`++a` 先加再取值，写在同一表达式里结果不同。
- **关系**：`== != > < >= <=`，C 里没有布尔类型，比较结果是 1 或 0。
- **逻辑**：`&& || !`，判真假以"非 0 即真"为准；想要 `bool` 得 `#include <stdbool.h>`。
- **赋值**：`= += -= *= /= %= <<= >>= &=`，复合赋值是"先算再写回"。
- **其它**：`sizeof`（求字节数）、`&`（取地址）、`*`（指针解引用）、`? :`（三元）。

`&` 和 `*` 这一对是 C 与 Java 最大的分水岭：Java 没有指针，C 里"地址"和"地址里存的值"是两回事。

### 8.5 条件判断

`if / else if / else`，条件里任何非 0 值都算真。输入用 `scanf("%d", &num)`——**传的是地址**，忘了 `&` 是新手最典型的崩溃原因。

### 8.6 循环

`while`（先判后做）、`do...while`（先做后判，至少执行一次）、`for`（三段式，最常用），以及 `for(;;)` 死循环。C 的 `for` 里变量可以就地声明，作用域仅在循环内。

### 8.7 函数

形态是"返回值类型 函数名(参数类型 形参) { 函数体 }"。C 没有类、没有方法重载，函数就是全局的；调用前必须先有定义或声明（头文件的作用就是这个）。看到 so 里的导出符号，基本就是这种裸函数名。

### 8.8 字符与字符串

**C 里没有字符串类型**。所谓字符串，就是字符数组，且必须以 `\0` 结尾——`"justin"` 实际占 7 个字节（6 字符 + 结束符），手写 `{'j','u','s','t','i','n'}` 少了 `\0` 就不是合法字符串，`%s` 打印会一直往后读直到撞见 0。

`%c` 打单字符，`%s` 打字符串（靠 `\0` 判断结束）。理解这一点，才能看懂 so 里的字符串比较、拼接、密钥表为什么都在按字节循环。

### 8.9 数组

同类型、定长、内存连续。`int a[] = {1,2,3}` 长度可省略，但定义完就固定；元素个数用 `sizeof(a) / sizeof(a[0])` 求（因为 `sizeof(a)` 得整个数组字节数）。

课件用打印地址的方式演示了最关键的一件事：**int 数组相邻元素地址相差 4 字节，char 数组相差 1 字节**。这就是"步长 = 元素大小"的直观证明，也是读汇编里 `[ebp-0x10]`、指针偏移时的直觉来源。

## 九、课件里的口径偏差与坑

1. **sign 口径前后端不一致**：课堂笔记里客户端算的是 `md5(用户名 + 密码)`，课件 md 的后端注释却是 `md5(t1 + 用户名)`。这是课件代码没对齐，不是"要背的正确口径"。真实逆向永远以客户端实际发出的参数为准，再反推服务端怎么校验。
2. **后端示例把密码写死成 md5(用户名)**：与课堂演示用的 `123456` 不是一回事，属演示占位。自己复刻时口径自己定，别去猜课件意图。
3. **hook 脚本 `Java.user` 是笔误**，Frida 正确 API 是 `Java.use`。
4. **Retrofit 不显式 `.client()` 拦截器不生效**——这是把 Retrofit 和拦截器串起来时最高频的坑。
5. **`baseUrl` 必须以 `/` 结尾**，接口注解路径不加前导 `/`。
6. **UI 更新必须回主线程**，子线程 `setAdapter` 直接崩。
7. **`*` 在运算符表里写成"指向一个变量"**：这是教学简化说法，实际 `*` 用在声明里表示"这是个指针"，用在表达式里表示"取地址里的值"（解引用），两者别混。
8. **软件包里的 MinGW 是解压版**：`x86_64-8.1.0-release-win32-seh-rt_v6-rev0` 目录已解压好，配 PATH 就能用，不必再跑在线安装器（那个经常卡在下载）。

## 关键知识清单

- **SharedPreferences**：`getSharedPreferences(文件名, MODE_PRIVATE)` + `edit().putString().commit()` / `getString()` / `remove().commit()`；落盘 `/data/data/包名/shared_prefs/*.xml`，root 机可直接 cat；反编译见 `getSharedPreferences` 即知在读写 xml，值可抠出来复用。
- **拦截器**：`implements Interceptor` → `chain.request()` → `newBuilder().addHeader()` → `chain.proceed()`；独立类 / 匿名类两种写法；静态 final 单例是常见封装；逆向搜 `Interceptor` 或 hook `addInterceptor`。
- **服务端校验**：Flask `before_request` 取头重算比对，Django 用中间件，都是"进视图前拦下"。
- **Retrofit**：接口 + `@POST/@GET/@FormUrlEncoded/@Field/@Query/@Body`；`Call<ResponseBody>` + `execute().body()` + Gson；必须 `.client(okHttpClient)` 才带拦截器；`baseUrl` 结尾带 `/`。
- **逆向闭环**：编译 → 装机 → 抓包 → jadx → Python 复刻，五步固定。
- **为什么学 C**：核心加密下沉到 so，jadx 只剩 `native` 声明；反编译工具 IDA / Ghidra / Radare2 / Hopper。
- **环境**：MinGW 是 GCC 的 Windows 移植，MinGW-w64 支持 64 位；解压版加 PATH 最快；`gcc -v` 验收；CLion 需手动指定工具链；中文乱码改 UTF-8 两套解法。
- **C 语法骨架**：类型宽度靠 `sizeof` 确认；`&` 取地址、`*` 解引用是 Java 没有的概念；`scanf` 要传地址；三种循环 + `for(;;)`；函数无重载、调用前需定义或声明；字符串 = 以 `\0` 结尾的 char 数组；数组内存连续、步长等于元素大小。
